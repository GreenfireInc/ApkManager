## Why Weston is needed

Lepton and Waydroid draw Android's screen as a **Wayland** client. They connect to a Wayland compositor's socket in `$XDG_RUNTIME_DIR` (here `/run/user/1000`) and never talk to X11.

This machine currently runs a **Cinnamon X11 session**:

| Variable | Value |
|----------|-------|
| `XDG_SESSION_TYPE` | `x11` |
| `DISPLAY` | `:0` |
| `WAYLAND_DISPLAY` | *(empty)* |
| Wayland sockets in `/run/user/1000` | none |

So there is no compositor for them to connect to. **Weston** is the reference Wayland compositor. Started inside an X11 session, it opens as an ordinary window on the Cinnamon desktop and acts as a Wayland compositor inside that window. Android apps then appear inside the Weston window, while everything else stays on X11.

## How Lepton chooses a display

From `liblepton.sh`:

```bash
# SteamOS runs apps under gamescope, whose socket is gamescope-0.  On a
# regular desktop session (KDE, GNOME, ...) there is no gamescope; fall back
# to the session's own compositor instead of failing to mount the socket.
local HOST_WAYLAND_DISPLAY="${WAYLAND_DISPLAY:-}"
export WAYLAND_DISPLAY="${GAMESCOPE_WAYLAND_DISPLAY:-gamescope-0}"
if [[ ! -e "${XDG_RUNTIME_DIR}/${WAYLAND_DISPLAY}" && -n "${HOST_WAYLAND_DISPLAY}" \
      && -e "${XDG_RUNTIME_DIR}/${HOST_WAYLAND_DISPLAY}" ]]; then
    export WAYLAND_DISPLAY="${HOST_WAYLAND_DISPLAY}"
fi
```

Lepton prefers `gamescope-0`. If that's absent, it uses **whatever `WAYLAND_DISPLAY` it inherited**, and `mounting.sh` bind-mounts that socket into the container as `/waydroid/xdg/wayland-0`.

Lepton is launched by **Steam**, so it inherits Steam's environment. Running Weston isn't enough on its own: **Steam must be started with `WAYLAND_DISPLAY` set to Weston's socket.** Starting Steam from the Cinnamon menu, without that variable, leaves Lepton with no display.

(gamescope, which Lepton prefers, isn't packaged for Ubuntu 24.04 / Mint 22 — `apt-cache policy gamescope` shows no candidate — so Weston is the practical choice here.)

## Option A: Weston nested in the X11 session (recommended)

This keeps the normal Cinnamon X11 desktop and only adds a Weston window for Android.

### 1. Install Weston

```bash
sudo apt install weston
```

The package is `weston` 13.0.0 from Ubuntu's `universe` archive (enabled on Mint). It includes `weston-terminal`, which is useful for testing.

### 2. Optional configuration

Create `~/.config/weston.ini` to stop Weston blanking or locking its window when idle:

```ini
[core]
idle-time=0

[shell]
locking=false
```

### 3. Start Weston with a fixed socket name

```bash
weston --backend=x11 --socket=wayland-lepton --width=1280 --height=800 &
```

| Option | Why |
|--------|-----|
| `--backend=x11` | Run as a window inside the X11 session. Weston picks this automatically when `DISPLAY` is set and `WAYLAND_DISPLAY` isn't, but stating it avoids surprises |
| `--socket=wayland-lepton` | A fixed, predictable socket at `/run/user/1000/wayland-lepton`, so Steam can be pointed at it. Without it Weston picks the first free `wayland-N` |
| `--width` / `--height` | Size of the Weston window. Lepton's `LEPTON_CROP_APP_WINDOWS=true` (the default in `lepton.conf`) sizes each app's window to the app, inside this area |

Weston uses its GL renderer (EGL on Mesa radeonsi for the RX 580), so Android's hardware rendering stays on the GPU.

### 4. Check it works

```bash
ls -l /run/user/1000/wayland-lepton                  # the socket exists
WAYLAND_DISPLAY=wayland-lepton weston-terminal       # a terminal opens inside the Weston window
```

### 5. Start Steam pointed at Weston

Steam must not already be running; if it is, the new command just hands off to the running instance and the variable is lost.

```bash
steam -shutdown; sleep 5
WAYLAND_DISPLAY=wayland-lepton steam &
```

Steam itself is an X11 program. It still uses `DISPLAY=:0` and opens on the normal desktop. Only the Android apps that Lepton launches go to Weston.

### 6. Convenience launcher (optional)

To do steps 3–5 in one go, save this as `~/.local/bin/steam-lepton` and make it executable (`chmod +x ~/.local/bin/steam-lepton`):

```bash
#!/bin/bash
# Start a nested Weston (if not already running) and Steam pointed at it, so
# Lepton's Android apps have a Wayland display inside an X11 session.
set -euo pipefail
SOCKET=wayland-lepton
RUNTIME="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"

if [[ ! -S "${RUNTIME}/${SOCKET}" ]]; then
    weston --backend=x11 --socket="${SOCKET}" --width=1280 --height=800 &
    for _ in $(seq 50); do
        [[ -S "${RUNTIME}/${SOCKET}" ]] && break
        sleep 0.1
    done
fi
[[ -S "${RUNTIME}/${SOCKET}" ]] || { echo "Weston did not start" >&2; exit 1; }

pgrep -x steam >/dev/null && { steam -shutdown; sleep 5; }
WAYLAND_DISPLAY="${SOCKET}" exec steam "$@"
```

Run `steam-lepton` instead of Steam whenever you want to play Android games.

**ApkManager now sets this up (November 21, 2026).** The Lepton install on the Debian and Ubuntu / Linux Mint rows of `runtime_install_dialog.vala` (`LEPTON_WESTON_STEPS`):

- adds `weston` to the package list;
- writes `~/.config/weston.ini` if it doesn't exist;
- installs this launcher as `~/.local/bin/steam-lepton`;
- adds a **Steam (Lepton)** menu entry (`~/.local/share/applications/steam-lepton.desktop`).

The installed launcher has one addition: if `WAYLAND_DISPLAY` is already set (a Wayland session, as in Option B), it starts Steam directly without Weston. Closing the Weston window ends the Wayland display; Android apps running in it close with it.

## Option B: Log in to "Cinnamon on Wayland (Experimental)"

Cinnamon 6.2 ships a Wayland session, and it's already installed here (`/usr/share/wayland-sessions/cinnamon-wayland.desktop`, which runs `cinnamon-session-cinnamon --wayland`).

1. Log out.
2. On the login screen, click the session icon next to your name and pick **Cinnamon on Wayland (Experimental)**.
3. Log in.

The whole desktop is now a Wayland compositor. `WAYLAND_DISPLAY` is set for everything, including Steam started from the menu, so Lepton finds the display with no extra steps. Android apps open as normal windows on the desktop.

The trade-off is that Cinnamon's Wayland session is marked experimental in Mint 22. Expect gaps, such as some applets, screen recording and screen sharing, and some X11-only tools. It's easy to switch back at the login screen.

## Comparison

| | Option A: nested Weston | Option B: Cinnamon on Wayland |
|---|---|---|
| Install | `sudo apt install weston` | Nothing |
| Desktop | Unchanged X11 Cinnamon | Experimental Wayland Cinnamon |
| Where Android apps appear | Inside the Weston window | As normal desktop windows |
| Steam | Must be started with `WAYLAND_DISPLAY=wayland-lepton` (or `steam-lepton`) | Start normally |
| Best for | Trying Lepton without changing the desktop | Regular use, if the Wayland session works well enough |

## Waydroid in the same setup

The ApkManager Waydroid guide (Ubuntu / Linux Mint row) already points X11 users at Weston. The same nested Weston works:

```bash
weston --backend=x11 --socket=wayland-lepton --width=1280 --height=800 &
WAYLAND_DISPLAY=wayland-lepton waydroid session start &
WAYLAND_DISPLAY=wayland-lepton waydroid show-full-ui
```

## Troubleshooting

| Symptom | Likely cause / fix |
|---------|-------------------|
| `weston: error while loading backend` | Use `--backend=x11` (Weston 13 accepts the short name); make sure `DISPLAY` is set, i.e. run it from the desktop, not a TTY |
| Weston window opens, Android apps open nowhere | Steam was started without `WAYLAND_DISPLAY=wayland-lepton`, or was already running. Fully quit Steam and start it with the variable |
| Socket name differs (`wayland-0`, `wayland-1`) | Weston was started without `--socket`; pass `--socket=wayland-lepton` or use the name it printed |
| Black or software-rendered Android screen | Check `glxinfo -B` shows radeonsi on the host; `LEPTON_FORCE_SOFTWARE=true` in `lepton.conf` is a fallback |
