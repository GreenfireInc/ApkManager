## 2. How it works

Valve built Lepton so Android VR games (Quest-class titles) can run unmodified on the **Steam Frame** headset. Its role is similar to Proton's, but instead of translating APIs, it runs a real, minimal Android system.

1. **Image.** An Android 11 root filesystem (`lineage_lepton_arm64_only`) built from **Waydroid's LineageOS 18.1 tree**, with Valve's forks of Waydroid's device and hardware repos. It also incorporates patches from Anbox, Halium, and Hybris. Services a game doesn't need are disabled.
2. **Container.** Steam starts the `lepton` launcher, about 3,500 lines of bash in `liblepton/`. Instead of Waydroid's LXC and Python, it creates a **rootless Podman** container. Every process runs as your normal user, with no root setup. Networking uses `pasta`.
3. **One app per container.** Lepton enforces no isolation between apps inside a container, so each Steam title gets its own.
4. **Host passthrough.** Host graphics drivers (**Mesa**, **Zink**), **Steam/Steamworks** libraries, and **Vulkan layers** (a foveated-rendering injector and a render-pass optimizer) are bind-mounted into the container. **SteamVR** becomes the container's OpenXR runtime, so VR games render through the host compositor.
5. **Fast start.** A pre-baked `/data` tree (`sysbake`) lets first boot skip Android's package scan and dexopt.
6. **Developer tools.** `strace`, `gdb`, `lldb`, `renderdoc`, and `perfetto` integration. The flat-screen window is hidden by default.

Valve's README says plainly: *"Lepton is not designed for general Android use … Most users should use Lepton provided by the Steam Client itself."*

### The community x86_64 port (`Lolig4/lepton-x86`)

- Adds a `lepton_x86_64_only` product: the Waydroid device tree without the Qualcomm parts, built with Mesa.
- Fixes the hwcomposer for desktop Wayland: one resizable, titled window per app.
- Runs ARM apps through `ndk_translation`.
- Installs as a Steam compatibility tool in `~/.local/share/Steam/compatibilitytools.d/lepton-x86_64`. You add an `.apk` as a non-Steam game and select that tool.
- **Current limits:** AMD GPUs only, no VR. Building the Android image needs tens of GB of source, hours of compiling, and more than 100 GB of disk.

## 3. Dependencies

### 3.1 Host requirements (all distros)

| Requirement | Why | Notes |
|-------------|-----|-------|
| **ARM64 CPU** (official Lepton) **or AMD GPU on x86_64** (community port) | The official build is aarch64-only. The port wires up only Mesa's `radeonsi` | `uname -m`; `lspci \| grep -i vga` |
| **Kernel with binder (`binderfs`)** | Android IPC inside the container | `grep binder /proc/filesystems`. The port ships a `lepton_binder` SELinux module for it |
| **Rootless Podman** with sub-UIDs/GIDs | Every app runs in a rootless container | `grep "^$USER:" /etc/subuid /etc/subgid` should print lines. Fedora and Ubuntu create them for new users; otherwise run `sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 $USER` |
| **Wayland compositor** | The hwcomposer draws Android windows as Wayland surfaces | Under X11, `weston` (the port installs it) |
| **Steam client** | Launches Lepton as a compatibility tool | Section 3.2 |
| **Disk** | Runtime: a few GB. **Building the port's Android image: more than 100 GB, and hours of compiling** | Build once, then copy the tarball to other machines |

### 3.2 Steam's dependencies

| Distro | Package | What it pulls in |
|--------|---------|------------------|
| Debian (`contrib`) | `steam-installer` | `steam-libs`, `steam-libs-i386` (needs **i386 multiarch**), `zenity`, `lsof`, `xdg-user-dirs`, a D-Bus session bus |
| Ubuntu (`multiverse`) | `steam-installer` | `steam-libs`, `steam-libs-i386` (needs i386 multiarch), `zenity` |
| Fedora (RPM Fusion nonfree) | `steam` | 32-bit Mesa, glibc, and audio libraries (`*.i686`) |
| Any (Flathub) | `com.valvesoftware.Steam` | Flatpak runtimes. Compatibility tools then live under `~/.var/app/com.valvesoftware.Steam/data/Steam/compatibilitytools.d/` |

### 3.3 Runtime packages for the container (the port's `setup-host.sh`)

| Debian / Ubuntu | Fedora | Role |
|-----------------|--------|------|
| `podman` | `podman` | Rootless container engine |
| `catatonit` | `catatonit` | Minimal init (PID 1) for the container |
| `inotify-tools` | `inotify-tools` | Watches the app's window and session state |
| `adb` | `android-tools` | Installing APKs into the container and debugging |
| `attr` | `attr` | Restores the `user.*` extended attributes on the baked `/data` |
| — | `policycoreutils` (`semodule`, `chcon`) | Loads the `lepton_binder` SELinux module and labels the tool directory |

### 3.4 Build packages for the port (`.x86_scripts/install-dependencies.sh`)

Everything in 3.3, plus:

| Debian / Ubuntu | Fedora | Role |
|-----------------|--------|------|
| `squashfs-tools-ng zstd rsync` | `squashfs-tools-ng zstd rsync` | Packing the root filesystem and the release tarball |
| `cargo rustc` | `cargo rust` | Builds `apk-info-extractor` |
| `git git-lfs python3` | `git git-lfs python3` | Sources and build scripts |
| `weston` | `weston` | Headless or nested Wayland for the first boot (`sysbake`) |
| — | `checkpolicy` | Compiles the SELinux module |

The AOSP compile runs inside a `lepton-builder` Podman container that brings its own toolchain, so no Android SDK or NDK is needed on the host.

## 4. Installation — Debian

**Step 1: install Steam and its dependencies** (`contrib`, with 32-bit multiarch):

```bash
sudo dpkg --add-architecture i386
sudo sed -i 's/^Components: main$/Components: main contrib/' /etc/apt/sources.list.d/debian.sources   # or add "contrib" by hand
sudo apt update
sudo apt install steam-installer          # pulls steam-libs, steam-libs-i386, zenity, …
steam                                     # first run downloads and updates the client; sign in
```

**Step 2: install the container runtime dependencies** (section 3.3):

```bash
sudo apt install podman catatonit inotify-tools adb attr
grep binder /proc/filesystems             # must print a binder line
```

**Step 3: get Lepton.**

- **ARM64 machine:** In Steam, go to **Library**, enable the **Tools** filter, and install **Lepton** (App ID 3029110). Steam then uses it automatically for titles marked `lepton-stable`.
- **x86_64 machine (AMD GPU):** the Steam build won't run, so use the community port. Build it on any machine with enough disk:

```bash
sudo apt install git git-lfs
git clone https://github.com/Lolig4/lepton-x86.git
cd lepton-x86
.x86_scripts/install-dependencies.sh        # section 3.4 packages (uses sudo)
.x86_scripts/build-all.sh                   # -> lepton-x86_64-<version>.tar.zst (hours; >100 GB disk)
```

**Step 4: install the tool** on the machine that will run it. The `--xattrs` flag is required:

```bash
mkdir -p ~/.local/share/Steam/compatibilitytools.d
tar --zstd --xattrs -xf lepton-x86_64-<version>.tar.zst -C ~/.local/share/Steam/compatibilitytools.d/
sudo ~/.local/share/Steam/compatibilitytools.d/lepton-x86_64/setup-host.sh   # installs 3.3 packages, labels
```

**Step 5: run an APK.** Restart Steam, then **Add a Game → Add a Non-Steam Game** and choose the `.apk`. In **Properties → Compatibility**, force **lepton-x86_64**.

## 5. Installation — Ubuntu (and Linux Mint)

**Step 1: install Steam and its dependencies** (`multiverse` on Ubuntu; Mint enables it by default):

```bash
sudo add-apt-repository multiverse        # Ubuntu only
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install steam-installer          # pulls steam-libs, steam-libs-i386, zenity
```

**Step 2: container runtime dependencies:**

```bash
sudo apt install podman catatonit inotify-tools adb attr
```

**Steps 3–5:** same as Debian. Mint's Cinnamon session is X11, so the port's `weston` dependency provides the Wayland surface Lepton needs.

## 6. Installation — Fedora

**Step 1: install Steam** from RPM Fusion nonfree, or from Flathub:

```bash
sudo dnf install https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm \
                 https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm
sudo dnf install steam                    # pulls the 32-bit (i686) libraries
# or: flatpak install flathub com.valvesoftware.Steam
```

**Step 2: container runtime dependencies:**

```bash
sudo dnf install podman catatonit inotify-tools android-tools attr policycoreutils
```

**Step 3:** same as Debian step 3. On Fedora, `install-dependencies.sh` also installs `checkpolicy` and `policycoreutils` to build the SELinux module.

**Step 4:** same as Debian step 4. `setup-host.sh` loads the **`lepton_binder` SELinux module** and labels the tool directory `container_file_t`; Fedora needs both because SELinux is enforcing. To undo, run `sudo …/setup-host.sh --remove`. **Flatpak Steam:** pass `STEAM_TOOL_DIR=~/.var/app/com.valvesoftware.Steam/data/Steam/compatibilitytools.d` to the installer.

**Step 5:** same as Debian.

## 7. Detecting an existing installation

Lepton is never a system package. The official build is a **Steam tool** (App ID 3029110), and the x86_64 port is a **Steam compatibility tool folder**. Detection therefore means finding Steam's data directory first, then looking inside it.

**Step 1: find Steam.**

| Steam install | Command | Data directory |
|---------------|---------|----------------|
| Native package (`steam`, `steam-installer`) | `command -v steam`, plus `dpkg -s steam-installer` (Debian/Ubuntu) or `rpm -q steam` (Fedora) | `~/.local/share/Steam` (`~/.steam/steam` is a symlink to it) |
| Flatpak | `flatpak info com.valvesoftware.Steam` | `~/.var/app/com.valvesoftware.Steam/data/Steam` |

**Step 2: look for Lepton in that directory** (`$STEAM` below):

| Check | Command | Installed when |
|-------|---------|----------------|
| Official Lepton (ARM64) | `ls "$STEAM"/steamapps/appmanifest_3029110.acf` | The manifest exists. Its `"installdir"` value names the folder under `steamapps/common/` |
| Official Lepton in another Steam library | `grep -o '"path"[^"]*"[^"]*"' "$STEAM"/steamapps/libraryfolders.vdf` | Repeat the manifest check in each listed `<path>/steamapps/` |
| x86_64 port | `test -f "$STEAM"/compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf` | The tool folder and its `compatibilitytool.vdf` exist. Steam lists the tool after a restart |
| Port host setup done | `command -v podman` and, on Fedora, `sudo semodule -l \| grep lepton_binder` | Podman is installed and the SELinux module is loaded (`setup-host.sh` does both) |
| Kernel support | `grep binder /proc/filesystems` | Prints a `binder` line. Required, but doesn't mean Lepton is installed |

```bash
# One-shot check (native and Flatpak Steam)
for STEAM in ~/.local/share/Steam ~/.var/app/com.valvesoftware.Steam/data/Steam; do
  [ -d "$STEAM" ] || continue
  [ -f "$STEAM/steamapps/appmanifest_3029110.acf" ] && echo "Lepton (Steam tool 3029110) in $STEAM"
  [ -f "$STEAM/compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf" ] && echo "lepton-x86_64 port in $STEAM"
done
```

If neither line prints, Lepton isn't installed. If no Steam directory exists, Steam itself isn't installed (section 3.2).

**From ApkManager (Vala):** build the two candidate data directories from `Environment.get_home_dir()` and test the two files with `FileUtils.test(..., FileTest.EXISTS)`. No Steam process needs to be running. On x86_64 hosts only the port matters, because the official tool won't run there even if its manifest exists.

## 8. Relevance to ApkManager

Lepton itself isn't useful to ApkManager on x86_64 desktops today. The x86_64 port shows a workable path: Steam launches an APK as a "non-Steam game" through a compatibility tool. That is heavy to set up, so for "run this APK" Waydroid or ATL is far simpler.

## 9. Corrections to the source notes

- The notes say Lepton runs on x86_64 "via the Steam Client compatibility tools". It doesn't. Steam offers the download on x86_64, but the binaries are ARM64-only ([#13634](https://github.com/ValveSoftware/steam-for-linux/issues/13634)).
- The notes give `./run-lepton --help` as the developer command. No such script exists. The launcher is `lepton` (under `compat_tool/` in the repo), and the repo is split into `image/` and `compat_tool/`.
- The notes' Steamworks link (`…/steamframe/adb_lepton`) could not be verified. The compatibility page linked above is the confirmed Valve documentation.
- The second "Lepton" section in the notes (snippet manager, AppImage or Snap) is a different project and isn't an Android runtime.
