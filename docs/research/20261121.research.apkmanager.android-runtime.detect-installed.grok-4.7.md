## 1. The short answer

A runtime counts as **installed** when its program is on the system. It counts as **ready** only after its data is in place. The package manager differs by distro. The files that prove installation do not.

| Runtime | Installed when | Ready when | Package on these nine distros |
|---------|----------------|------------|-------------------------------|
| **Waydroid** | `command -v waydroid` prints a path | `/var/lib/waydroid/waydroid.cfg` exists | Official or community package on all nine, under the name `waydroid`. Bazzite also ships `waydroid-nvidia` on NVIDIA images. SteamOS has no official package |
| **Android Translation Layer** | `command -v android-translation-layer` prints a path, or an AppImage is found under the home directory | The command above is enough for the AppImage. A source build also needs `dalvikvm` on `PATH` | None of the nine package it |
| **Lepton** | Steam's `appmanifest_3029110.acf` exists (official ARM64 tool), or `compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf` exists (x86_64 port) | The same files. The port also wants `podman` on `PATH` | Never a distro package. It lives inside a Steam install |

`command -v` and the file tests below work on every distro in the list. Section 3 adds the package-manager command for each distro, which confirms *how* Waydroid was installed. It is the wrong test on SteamOS after an OS update, and on Bazzite it reports the package that shipped in the image, not whether the user finished setup.

## 2. Naming the distro

Read `/etc/os-release`. Flatpak builds of ApkManager see the host copy at `/run/host/os-release`, and Snap builds see `/var/lib/snapd/hostfs/etc/os-release`. `HostDistro` already checks those paths.

| Distro | `ID` | `ID_LIKE` | Package manager |
|--------|------|-----------|-----------------|
| Debian | `debian` | (empty) | `apt` / `dpkg` |
| Ubuntu | `ubuntu` | `debian` | `apt` / `dpkg` |
| Linux Mint | `linuxmint` | `ubuntu debian` | `apt` / `dpkg` |
| Fedora | `fedora` | (empty) | `dnf` / `rpm` |
| openSUSE Tumbleweed | `opensuse-tumbleweed` | `opensuse suse` | `zypper` / `rpm` |
| openSUSE Leap | `opensuse-leap` | `opensuse suse` | `zypper` / `rpm` |
| Slackware | `slackware` | (empty) | `installpkg`. The installed-package list is `/var/log/packages` |
| SteamOS | `steamos` | `arch` | `pacman`, on a read-only root |
| Bazzite | `bazzite` | `fedora` | `rpm-ostree` / `rpm`. Current images use this `ID`. Images from around Fedora 40 still said `ID=fedora` and put "Bazzite" only in `PRETTY_NAME` |
| CachyOS | `cachyos` | `arch` when the branding hook has written it | `pacman` |

Bazzite's stable marker, on both the current and the older images, is the launcher the image ships:

```bash
test -x /usr/bin/waydroid-launcher && echo "Bazzite Waydroid launcher present"
```

`HostDistro` today maps any `ID_LIKE` containing `fedora` to the Fedora family. On a current Bazzite image that reports the family as Fedora. The Waydroid binary is still found by `command -v`, and `rpm -q` still answers, so that mapping does not hide the runtime.

## 3. Waydroid

### 3.1 Checks that are the same everywhere

These three questions are separate. A machine can have the program, have no Android image, and have the service stopped.

| Question | Command | Yes when |
|----------|---------|----------|
| Program installed | `command -v waydroid` | Prints a path, normally `/usr/bin/waydroid` |
| Version | `waydroid -V` | Prints a version such as `1.6.3`. `--version` is the same flag |
| Initialized | `test -f /var/lib/waydroid/waydroid.cfg` | `waydroid init` has written the config. Images then live under `/var/lib/waydroid/images/` |
| Container service | `systemctl is-active waydroid-container` | Prints `active` |
| Session | `waydroid status` | Prints `Session:` followed by `RUNNING`. `STOPPED` means the program is installed and the session is down |
| Kernel can run it | `grep binder /proc/filesystems` | Prints a `binder` line. This is a requirement, not an install |

```bash
if command -v waydroid >/dev/null; then
  echo "Waydroid installed at $(command -v waydroid) ($(waydroid -V 2>/dev/null))"
  if [ -f /var/lib/waydroid/waydroid.cfg ]; then
    echo "initialized"
  else
    echo "not initialized (sudo waydroid init has not been run)"
  fi
else
  echo "Waydroid not installed"
fi
```

### 3.2 Package-manager check per distro

Use this to confirm the package, after `command -v` has already answered. Each command exits 0 when the package is installed.

| Distro | Command | Notes |
|--------|---------|-------|
| Debian, Ubuntu, Linux Mint | `dpkg -s waydroid` | Status line `install ok installed`. Debian ships it in forky, sid, and trixie-backports. Ubuntu ships it in `universe` on the newest releases, and through `repo.waydro.id` on LTS. Mint follows its Ubuntu base, so the same `dpkg` test covers a Mint package and a package installed from Waydroid's apt repo |
| Fedora | `rpm -q waydroid` | In the official Fedora repos (1.6.3 on Fedora 44). Prints `package waydroid is not installed` and exits 1 otherwise |
| openSUSE | `rpm -q waydroid` | Not in the default OSS repo. The [Emulators:Waydroid](https://build.opensuse.org/project/show/Emulators:Waydroid) OBS project publishes a `waydroid` RPM for Tumbleweed, Slowroll, and Leap 16. Once that RPM is installed, `rpm -q` and `/usr/bin/waydroid` behave as on Fedora. `zypper se -i -x waydroid` is the readable form and is a poor yes/no test, because zypper still exits 0 when it finds nothing |
| Slackware | `ls /var/log/packages/waydroid-*` | Not in the official Slackware set. [SlackBuilds.org](https://slackbuilds.org/repository/15.0/system/waydroid/) has `waydroid` 1.5.4 for 15.0, and `installpkg` records it as `/var/log/packages/waydroid-<version>-<arch>-<build>_SBo`. The SlackBuild installs `/usr/bin/waydroid`. The stock Slackware kernel does not enable the binder options Waydroid wants, so a listed package can still fail the binder check in section 3.1 |
| CachyOS | `pacman -Q waydroid` | `waydroid` 1.6.3-1 is in Arch `extra`, which CachyOS mirrors. `pacman -Q cachyos/waydroid-image` is a separate, optional package of Android images. Missing it does not mean Waydroid is missing: `waydroid init` downloads the images itself |
| Bazzite | `rpm -q waydroid` and `rpm -q waydroid-nvidia` | Waydroid is **in the base image**, so the program is present before the user does anything. NVIDIA images ship `waydroid-nvidia` in its place. Setup is `ujust configure-waydroid` (also aliased as `ujust setup-waydroid`), which runs `waydroid init`. Until that finishes, `/usr/bin/waydroid` exists and `/var/lib/waydroid/waydroid.cfg` does not. Launch through `/usr/bin/waydroid-launcher` |
| SteamOS | `pacman -Q waydroid` | SteamOS does not ship Waydroid. Community installers unlock the root with `steamos-readonly disable` and install with `pacman`. A SteamOS update replaces the whole root filesystem, so `pacman -Q` and `/usr/bin/waydroid` can both come back empty while `/var/lib/waydroid/waydroid.cfg` and the images under the home directory are still there. Trust the binary for "installed" and the config file for "was set up". Report "data left behind, program missing" when the file exists and the binary does not |

Fedora Atomic (Silverblue, Kinoite) and Bazzite both answer `rpm -q` for packages baked into the image and for packages layered with `rpm-ostree`. `rpm-ostree status` shows layered packages only, so it misses Waydroid on Bazzite, where it is part of the image.

## 4. Android Translation Layer

No distro in this list packages `android-translation-layer`. Alpine and postmarketOS do. On Debian, Slackware, openSUSE, Fedora, Ubuntu, Linux Mint, SteamOS, Bazzite, and CachyOS the test is the same: look for the program, not for a package.

There are two install forms.

**A launcher on `PATH`.** This covers a source build (`sudo meson install`, default prefix `/usr/local`) and an AppImage that the user linked onto `PATH`.

```bash
command -v android-translation-layer
```

Resolve the symlink before deciding which form it is. An AppImage is an ELF file whose bytes 8–10 are `AI\x02` (the type-2 AppImage magic). A source build is a normal program and is accompanied by its framework:

| Extra file | Present for a source build |
|------------|----------------------------|
| `/usr/local/lib/java/dex/android_translation_layer/api-impl.jar`, or the same path under `lib64` on Fedora and openSUSE | ATL's Java framework. Without it the launcher starts and cannot load an app |
| `command -v dalvikvm` | `art_standalone`, which ATL needs |

**An AppImage sitting in the home directory.** Release names from pkgforge look like `Android_Translation_Layer-<hash>-anylinux-x86_64.AppImage`. A renamed copy does not match that glob. Search the usual download folders, and accept a file whose name contains `Android_Translation_Layer` or `Android Translation Layer`:

```bash
find "$HOME/Applications" "$HOME/.local/bin" "$HOME/Downloads" \
  -maxdepth 1 \( -iname '*Android_Translation_Layer*' -o -iname '*Android Translation Layer*' \) \
  -print 2>/dev/null
```

On this Fedora 44 machine, checked on 2026-11-21, that second form is exactly how ATL is installed:

- `command -v android-translation-layer` prints `/home/corey/.local/bin/android-translation-layer`.
- That path is a symlink, created the same day, to `/home/corey/Applications/Android Translation Layer`.
- The target is a 137 MB ELF file with the `AI\x02` magic, so it is an AppImage, and its name has no `.AppImage` suffix.
- `api-impl.jar` and `dalvikvm` are absent, which is what an AppImage looks like: those files are inside the image, not on the host.

A glob of `Android_Translation_Layer-*.AppImage` would have reported ATL missing on this machine.

## 5. Lepton

Lepton is a Steam tool, App ID **3029110**. The official build is ARM64. The community x86_64 port installs as a Steam compatibility tool named `lepton-x86_64`. Neither is a `dpkg`, `rpm`, `pacman`, or Slackware package, so the distro only changes where Steam keeps its files.

### 5.1 Find Steam's data directory

Check every directory that exists. A machine can have a native Steam and a Flatpak Steam at the same time.

| Steam install | Where it shows up | Data directory |
|---------------|-------------------|----------------|
| Native package, including Fedora, openSUSE, Slackware, CachyOS, and the Steam that SteamOS and Bazzite ship | `command -v steam` | `~/.local/share/Steam`. `~/.steam/steam` and `~/.steam/root` are symlinks to it. On SteamOS the home is usually `/home/deck` |
| Debian / Ubuntu package | `dpkg -s steam-installer` or `dpkg -s steam` | `~/.local/share/Steam` |
| Snap (Ubuntu and Linux Mint) | `snap list steam` | `~/snap/steam/common/.local/share/Steam`, or `~/.snap/data/steam/common/.local/share/Steam` when the hidden-snap-folder flag is on |
| Flatpak | `flatpak info com.valvesoftware.Steam` | `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`. Also check `~/.var/app/com.valvesoftware.Steam/data/Steam`, which is the path some install notes use for `STEAM_TOOL_DIR` |

Steam also reads compatibility tools from `/usr/share/steam/compatibilitytools.d` and `/usr/local/share/steam/compatibilitytools.d`.

### 5.2 Find Lepton inside that directory

| Check | File | Means |
|-------|------|-------|
| Official Lepton | `$STEAM/steamapps/appmanifest_3029110.acf` | Steam has downloaded tool 3029110. On x86_64 (Steam Deck SteamOS, Bazzite, CachyOS, Fedora, and the other distros here when they are not ARM64) the binaries are ARM64 and will not run. The manifest still means the tool is installed |
| Official Lepton in another library | `"path"` entries in `$STEAM/steamapps/libraryfolders.vdf` | Repeat the manifest test under each `<path>/steamapps/` |
| x86_64 port | `$STEAM/compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf` | The port is installed. Steam lists it after a restart |
| Port host setup | `command -v podman` | The port's `setup-host.sh` installs Podman. On Fedora and Bazzite it also loads an SELinux module, `lepton_binder`, visible with `sudo semodule -l` |

```bash
roots=(
  "$HOME/.local/share/Steam"
  "$HOME/.steam/steam"
  "$HOME/snap/steam/common/.local/share/Steam"
  "$HOME/.snap/data/steam/common/.local/share/Steam"
  "$HOME/.var/app/com.valvesoftware.Steam/.local/share/Steam"
  "$HOME/.var/app/com.valvesoftware.Steam/data/Steam"
)
for STEAM in "${roots[@]}"; do
  [ -d "$STEAM" ] || continue
  [ -f "$STEAM/steamapps/appmanifest_3029110.acf" ] && echo "Lepton 3029110 in $STEAM"
  [ -f "$STEAM/compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf" ] && echo "lepton-x86_64 in $STEAM"
done
for dir in /usr/share/steam/compatibilitytools.d /usr/local/share/steam/compatibilitytools.d; do
  [ -f "$dir/lepton-x86_64/compatibilitytool.vdf" ] && echo "lepton-x86_64 in $dir"
done
```

No line of output means Lepton is not installed. No existing directory in the list means Steam itself is not installed for this user.

## 6. One check for all three

This prints one line per runtime and exits 0 when at least one is installed. It uses the file and `PATH` tests, which cover all nine distros, and adds the package database only as a second Waydroid line.

```bash
#!/bin/bash
# detect-runtimes.sh — Waydroid, Android Translation Layer, Lepton.
found=0

if command -v waydroid >/dev/null; then
  found=1
  state="not initialized"
  [ -f /var/lib/waydroid/waydroid.cfg ] && state="initialized"
  echo "Waydroid: installed ($(waydroid -V 2>/dev/null)), $state"
else
  echo "Waydroid: not installed"
  [ -f /var/lib/waydroid/waydroid.cfg ] && echo "Waydroid: config left behind at /var/lib/waydroid/waydroid.cfg"
fi

id=$(. /etc/os-release && echo "$ID")
case "$id" in
  debian|ubuntu|linuxmint) dpkg -s waydroid >/dev/null 2>&1 && echo "Waydroid package: dpkg" ;;
  fedora|opensuse-tumbleweed|opensuse-leap|opensuse|bazzite)
    rpm -q waydroid >/dev/null 2>&1 && echo "Waydroid package: rpm waydroid"
    rpm -q waydroid-nvidia >/dev/null 2>&1 && echo "Waydroid package: rpm waydroid-nvidia" ;;
  slackware) ls /var/log/packages/waydroid-* >/dev/null 2>&1 && echo "Waydroid package: /var/log/packages" ;;
  steamos|cachyos|arch) pacman -Q waydroid >/dev/null 2>&1 && echo "Waydroid package: pacman" ;;
esac

if command -v android-translation-layer >/dev/null; then
  found=1
  target=$(readlink -f "$(command -v android-translation-layer)")
  if [ "$(od -An -t x1 -j 8 -N 3 "$target" | tr -d ' ')" = "414902" ]; then
    echo "Android Translation Layer: AppImage at $target"
  else
    echo "Android Translation Layer: $target"
  fi
else
  echo "Android Translation Layer: not on PATH"
fi

lepton=0
for STEAM in "$HOME/.local/share/Steam" "$HOME/.steam/steam" \
  "$HOME/snap/steam/common/.local/share/Steam" \
  "$HOME/.var/app/com.valvesoftware.Steam/.local/share/Steam" \
  "$HOME/.var/app/com.valvesoftware.Steam/data/Steam"; do
  [ -f "$STEAM/steamapps/appmanifest_3029110.acf" ] && lepton=1 && echo "Lepton: Steam tool 3029110 in $STEAM"
  [ -f "$STEAM/compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf" ] && lepton=1 && echo "Lepton: lepton-x86_64 in $STEAM"
done
[ "$lepton" = 0 ] && echo "Lepton: not installed"
found=$((found | lepton))
exit $((1 - found))
```

The AppImage byte check compares the three bytes at offset 8 with hex `41 49 02`, which is `AI\x02`.

Run on 2026-11-21, from `/etc/os-release` (`ID=fedora`):

| Check | Result |
|-------|--------|

## 8. What ApkManager should call

The yes/no answer does not need a distro branch.

| Runtime | Vala check |
|---------|------------|
| Waydroid installed | `GLib.Environment.find_program_in_path("waydroid") != null` |
| Waydroid initialized | `FileUtils.test("/var/lib/waydroid/waydroid.cfg", FileTest.EXISTS)` |
| ATL installed | `find_program_in_path("android-translation-layer") != null`. If that is null, scan `~/Applications`, `~/.local/bin`, and `~/Downloads` for the two name patterns in section 4 |
| Lepton installed | `FileUtils.test` on `appmanifest_3029110.acf` and on `compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf`, under each Steam root in section 5.1 built from `Environment.get_home_dir()` |

Read the distro only to explain the result. On Bazzite, a missing config file means "Waydroid came with the image and has not been initialized", and the setup hint is `ujust configure-waydroid`. On SteamOS, a config file with no binary means "a SteamOS update removed Waydroid and left its data". On the other seven, a missing binary means "not installed".

Avoid calling `waydroid status` on every window open. It talks to the container over D-Bus and is slow when the service is down. The config file answers "initialized" without starting anything.
