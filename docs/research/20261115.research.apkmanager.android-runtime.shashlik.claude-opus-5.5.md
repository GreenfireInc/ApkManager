## 2. How it works

Shashlik (2015, from developers in the KDE community) took a middle path between a full emulator and a container:

1. **Stripped Android.** A minimal Android build with no launcher, phone, or other system apps. The yui0 fork moved it to **Android 5.1.1 (x86)** with **F-Droid**, a small launcher, and Google Play Store and Services APKs preinstalled.
2. **Per-app emulator.** `shashlik-run <package> <title>` boots that minimal Android in a **QEMU-based Android emulator** (the SDK's "goldfish" virtual hardware). It uses **KVM** acceleration (`/dev/kvm`) and runs only that one app full-window, so each app looks like its own desktop window.
3. **Graphics.** OpenGL ES calls go through the emulator's GL pipe to the host's OpenGL.
4. **ARM apps.** The fork adds Intel's **Houdini** ARM-to-x86 binary translator for ARM-only native libraries.
5. **Install and data.** `shashlik-install app.apk` installs into a per-user data image under `~/.local/share/shashlik`.

Since it emulates a whole virtual machine, it's heavier than Waydroid or ATL. Android 5.1 is too old for most current apps, which often need Android 8 or later.

## 3. Dependencies

### 3.1 What the AppImage bundles

From the fork's `make_shashlik.sh` and `appimage/shashlik.yml`:

- The emulator binaries and the Android 5.1.1 `system.img` and `ramdisk.img`, taken from the original `shashlik_0.9.3.deb`.
- `adb`, `aapt`, and `mksdcard`.
- Houdini ARM translation (`ARM_Translation_Lollipop`).
- Preinstalled apps: F-Droid, a launcher, and Google Play Store and Play Services APKs.
- Ubuntu 22.10 (`kinetic`) userland libraries.

You don't need QEMU or the Android SDK on the host.

### 3.2 Host requirements

| Requirement | Why | Debian / Ubuntu | Fedora |
|-------------|-----|-----------------|--------|
| **x86_64 CPU with VT-x / AMD-V** | Hardware-accelerated emulation | Enable in BIOS; check `ls -l /dev/kvm` | same |
| **KVM access** | `/dev/kvm` must be writable by you | `sudo usermod -aG kvm $USER` | `sudo usermod -aG kvm $USER` (the `qemu-kvm` package also sets up the `kvm` group) |
| **Python 3** | `shashlik-run` and the install script are Python 3 scripts run with the host interpreter | `python3` (default) | `python3` (default) |
| **FUSE 2** | Mounting the AppImage | `libfuse2` (Debian ≤12, Ubuntu ≤23.10) or `libfuse2t64` (Debian 13+, Ubuntu 24.04+) | `fuse-libs` |
| **OpenGL** | The emulator's GL pipe renders with host GL | `libgl1 libegl1` (Mesa) | `mesa-libGL mesa-libEGL` |
| **X11 or XWayland** | The emulator window | default on all desktops | default |
| **~1 GB disk** | AppImage plus the per-user `sdcard.img` (500 MB) and data in `~/.local/share/shashlik` | — | — |

## 4. Installation — Debian

There's no package. Use the AppImage:

```bash
# 1. Dependencies (section 3.2)
sudo apt install python3 libfuse2 libgl1 libegl1 curl    # libfuse2t64 instead of libfuse2 on Debian 13+
sudo usermod -aG kvm "$USER"                             # then log out and back in
ls -l /dev/kvm                                           # should be group "kvm", mode crw-rw----

# 2. Shashlik
curl -LO https://github.com/yui0/shashlik/releases/download/2023-02-16/shashlik-0.9.3.glibc2.14-x86_64.AppImage
chmod +x shashlik-0.9.3.glibc2.14-x86_64.AppImage
./shashlik-0.9.3.glibc2.14-x86_64.AppImage               # boots the bundled launcher ("Desktop")
```

## 5. Installation — Ubuntu (and Linux Mint)

Same as Debian. On Ubuntu 24.04 and later, install `libfuse2t64` instead of `libfuse2`:

```bash
sudo apt install python3 libfuse2t64 libgl1 libegl1 curl    # libfuse2 on 22.04 / Mint 21
sudo usermod -aG kvm "$USER"                                # log out and back in
# then download and run the AppImage as in section 4, step 2
```

## 6. Installation — Fedora

Use the AppImage. The upstream README also describes an RPM installed to `/opt/shashlik`, from older releases. It was built against old Fedora releases and probably won't install cleanly on Fedora 44.

```bash
sudo dnf install python3 fuse-libs mesa-libGL mesa-libEGL curl
sudo usermod -aG kvm "$USER"            # log out and back in
# download and run the AppImage as in section 4, step 2

# Usage, per the upstream README (RPM layout):
/opt/shashlik/bin/shashlik-install com.example.app.apk
/opt/shashlik/bin/shashlik-run com.example.app "Example"
```

To uninstall: `sudo rpm -e shashlik` (RPM), then `rm -rf ~/.local/share/shashlik`.

## 7. Detecting an existing installation

Shashlik has no package on Debian, Ubuntu, or Fedora, so look for its two install forms directly.

| Check | Command | Installed / ready when |
|-------|---------|------------------------|
| AppImage | `ls ~/Applications/shashlik-*.AppImage ~/.local/bin/shashlik-*.AppImage ~/Downloads/shashlik-*.AppImage 2>/dev/null` | A file such as `shashlik-0.9.3.glibc2.14-x86_64.AppImage` is listed |
| Old RPM layout | `test -x /opt/shashlik/bin/shashlik-run` | The launcher exists (also `rpm -q shashlik` on Fedora) |
| Used before | `test -d ~/.local/share/shashlik` | The per-user data folder (including `sdcard.img`) exists. Shows Shashlik has run, not that it's still installed |
| KVM access | `test -w /dev/kvm` | You can write to `/dev/kvm`. Required to run, but doesn't mean Shashlik is installed |

```bash
# One-shot check
if [ -x /opt/shashlik/bin/shashlik-run ]; then
  echo "Shashlik (RPM layout) in /opt/shashlik"
elif ls ~/Applications/shashlik-*.AppImage >/dev/null 2>&1; then
  echo "Shashlik AppImage: $(ls ~/Applications/shashlik-*.AppImage | head -n1)"
else
  echo "Shashlik not installed"
fi
[ -w /dev/kvm ] || echo "note: /dev/kvm not writable (add yourself to the kvm group)"
```

**From ApkManager (Vala):** `FileUtils.test("/opt/shashlik/bin/shashlik-run", FileTest.IS_EXECUTABLE)`, plus a scan of `~/Applications` and `~/.local/bin` for `shashlik-*.AppImage`.

## 8. Relevance to ApkManager

Mostly historical. Its per-app window model is the user experience ApkManager would want. ATL delivers that today without a VM, and Waydroid's multi-window mode comes close.
