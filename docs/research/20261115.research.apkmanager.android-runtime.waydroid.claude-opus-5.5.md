## 2. How it works

Waydroid boots a real Android system (LineageOS 18.1 / Android 11 or LineageOS 20 / Android 13) inside a Linux container. It does not emulate a CPU, so Android runs at native speed on the host kernel.

1. **Container.** The host tool (Python) creates an **LXC** container. Android's `init` runs as PID 1 inside it, with its own mount, PID, and network namespaces.
2. **Shared kernel.** Android needs kernel features a normal Linux desktop doesn't use, mainly **binder** (Android's IPC). Waydroid uses `binderfs`, which current Fedora, Ubuntu, and Debian kernels provide. Check with `grep binder /proc/filesystems`.
3. **Images.** `waydroid init` downloads a `system.img` and `vendor.img` (vanilla, or `-s GAPPS` for Google Play Services) and mounts them as the container's root filesystem.
4. **Graphics.** Android draws with the host GPU through Mesa (`minigbm` gralloc plus a custom `hwcomposer`). Each Android window becomes a **Wayland surface** on the host. This is why Waydroid requires a Wayland compositor.
5. **Integration.** A session service bridges audio (PipeWire/PulseAudio), clipboard, notifications, and networking (an LXC bridge with NAT). Apps can appear as separate desktop windows ("multi-window") or inside one full Android UI.
6. **Apps.** `waydroid app install file.apk` installs into the container, and `waydroid app launch <package>` starts one. Images are x86_64. ARM-only apps need an ARM translator (libhoudini/libndk), which Waydroid doesn't ship. Community scripts such as `waydroid_script` add it.

**Wayland requirement:** under an X11 session (Linux Mint by default, and this Fedora machine's current `DISPLAY=:0` session), run a nested Wayland compositor such as `weston` or `cage` first, then start Waydroid inside it.

## 3. Dependencies

### 3.1 Host requirements (all distros)

| Requirement | Why | How to check / get it |
|-------------|-----|------------------------|
| **x86_64 or arm64 CPU** | Images exist for both | `uname -m` |
| **Kernel with binder (`binderfs`)** | Android IPC | `grep binder /proc/filesystems`. The stock Fedora, Ubuntu, and Debian kernels have it. Custom kernels need `CONFIG_ANDROID_BINDER_IPC=y` and `CONFIG_ANDROID_BINDERFS=y` |
| **Wayland compositor** | Waydroid draws Android windows as Wayland surfaces | `echo $XDG_SESSION_TYPE` should print `wayland`. Under X11, install `weston` or `cage` and run Waydroid inside it |
| **GPU with Mesa drivers** | Hardware rendering (Intel/AMD). NVIDIA proprietary needs software rendering | `glxinfo -B` (package `mesa-utils` / `glx-utils`) |
| **systemd** | Runs `waydroid-container.service` | Default on all three distros |
| **~4 GB free disk, ~2 GB RAM** | Android images plus user data under `/var/lib/waydroid` and `~/.local/share/waydroid` | `df -h /var` |
| **Internet on first run** | `waydroid init` downloads the system and vendor images | — |

### 3.2 Package dependencies (pulled in automatically)

| Debian / Ubuntu (`apt`) | Fedora (`dnf`) | Role |
|--------------------------|----------------|------|
| `lxc` | `lxc` | Container runtime |
| `python3`, `python3-gi`, `gir1.2-gtk-3.0` | `python3`, `python3-gobject`, `gtk3` | Host tool and GUI helpers |
| `python3-dbus`, `dbus` | `python3dist(dbus-python)` | Session ↔ container messaging |
| `python3-gbinder` | `python3dist(gbinder-python)` | Talks binder to Android services |
| `nftables` | `nftables`, `iproute`, `dnsmasq` | Container networking (NAT bridge, DHCP) |
| `pipewire-pulse` or `pulseaudio` | (uses the desktop's PipeWire) | Audio |
| `pkexec`, `polkitd` | — | Privileged actions from the GUI |
| — | `waydroid-selinux` (when SELinux is enabled) | SELinux policy for the container |

**Optional:** `adb` (`sudo apt install adb` / `sudo dnf install android-tools`) for `adb install`, logs, and debugging; `weston` for X11 sessions.

## 4. Installation — Debian

Waydroid is in Debian's official archive for **forky (testing)**, **sid**, and **trixie-backports** (Debian 13).

```bash
# 0. Check prerequisites (section 3.1)
grep binder /proc/filesystems          # must print a "binder" line
echo $XDG_SESSION_TYPE                 # "wayland"; if "x11", also: sudo apt install weston

# Debian 13 (trixie): enable backports once
echo "deb http://deb.debian.org/debian trixie-backports main" | sudo tee /etc/apt/sources.list.d/backports.list
sudo apt update
sudo apt install -t trixie-backports waydroid

# Debian forky / sid
sudo apt install waydroid
```

**Debian 12 (bookworm), or to track upstream directly:** use the upstream repo. The setup script detects the codename (supported: `bullseye`, `bookworm`, `trixie`, `sid`).

```bash
sudo apt install curl ca-certificates
curl -s https://repo.waydro.id | sudo bash
sudo apt install waydroid
```

Then initialize and start (all distros):

```bash
sudo waydroid init                 # or: sudo waydroid init -s GAPPS
sudo systemctl enable --now waydroid-container
waydroid session start             # as your normal user, inside a Wayland session
waydroid show-full-ui              # optional: full Android home screen
```

## 5. Installation — Ubuntu (and Linux Mint)

The newest Ubuntu releases ship Waydroid in **`universe`** (`sudo apt install waydroid`). **LTS releases** (22.04 `jammy`, 24.04 `noble`, 26.04 `resolute`) use the upstream repo:

```bash
grep binder /proc/filesystems                  # prerequisite check (section 3.1)
sudo apt install curl ca-certificates          # needed by the repo script
curl -s https://repo.waydro.id | sudo bash
sudo apt install waydroid                      # pulls lxc, python3-gbinder, nftables, … (section 3.2)
sudo apt install adb                           # optional
```

**Linux Mint:** the script reads `UBUNTU_CODENAME` from `/etc/os-release`, so it maps Mint to its Ubuntu base automatically. If detection fails, pass the codename, e.g. `curl -s https://repo.waydro.id | sudo bash -s noble` for Mint 22. Mint's Cinnamon session is X11, so also install a nested compositor:

```bash
sudo apt install weston
weston &                           # opens a Wayland window
# in a terminal inside Weston:
waydroid session start && waydroid show-full-ui
```

Then `waydroid init` and `systemctl enable --now waydroid-container` as in section 4.

## 6. Installation — Fedora

Waydroid is in Fedora's official repositories (1.6.3 in Fedora 44, and in Rawhide).

```bash
grep binder /proc/filesystems      # prerequisite check (section 3.1)
sudo dnf install waydroid          # pulls lxc, python3-gbinder, dnsmasq, nftables, waydroid-selinux, …
sudo dnf install android-tools     # optional: adb
sudo waydroid init                 # or: sudo waydroid init -s GAPPS
sudo systemctl enable --now waydroid-container
waydroid session start
```

Fedora Workstation defaults to a GNOME Wayland session, so nothing else is needed there. Under X11, run `weston` or `cage` first (`sudo dnf install weston`).

## 7. Limitations

- Needs **Wayland** (natively or nested).
- A full Android system uses about 1–2 GB of RAM and several GB of disk per installation.
- Images are x86_64. ARM-only apps (many games) need a third-party ARM translation add-on.
- No hardware video decode on some GPUs, and NVIDIA proprietary drivers are poorly supported. Use Mesa (AMD/Intel), or software rendering as a fallback.

## 8. Detecting an existing installation

Waydroid has three states worth telling apart: **installed** (the package is present), **initialized** (`waydroid init` has downloaded images), and **running** (the container service and a user session are up). Each check exits with status 0 when true.

| Check | Command | Installed / ready when |
|-------|---------|------------------------|
| Command on `PATH` | `command -v waydroid` | Prints `/usr/bin/waydroid` |
| Version | `waydroid -V` | Prints a version such as `1.6.3` |
| Package (Debian, Ubuntu, Mint) | `dpkg -s waydroid` | Exit 0, with `Status: install ok installed` |
| Package (Fedora) | `rpm -q waydroid` | Exit 0 (prints `package waydroid is not installed` and exits 1 otherwise) |
| Initialized | `test -f /var/lib/waydroid/waydroid.cfg` | The config exists. `waydroid init` writes it, and the images it points to live under `/var/lib/waydroid/images/` (or `/usr/share/waydroid-extra/images/` for preinstalled images) |
| Container service | `systemctl is-active waydroid-container` | Prints `active` |
| Session | `waydroid status` | First line reads `Session:` then `RUNNING` (otherwise `STOPPED`). Also prints the container state and vendor type |
| Kernel support | `grep binder /proc/filesystems` | Prints a `binder` line. This only says Waydroid *can* run, not that it's installed |

```bash
# One-shot check
if command -v waydroid >/dev/null; then
  echo "Waydroid $(waydroid -V) installed"
  [ -f /var/lib/waydroid/waydroid.cfg ] && echo "initialized" || echo "not initialized: run sudo waydroid init"
  systemctl is-active --quiet waydroid-container && echo "container service active"
else
  echo "Waydroid not installed"
fi
```

**From ApkManager (Vala):** `GLib.Environment.find_program_in_path("waydroid") != null` for installed, and `FileUtils.test("/var/lib/waydroid/waydroid.cfg", FileTest.EXISTS)` for initialized. Both work without root and without starting anything. Avoid calling `waydroid status` on every window open, because it talks to the container over D-Bus and is slow when the service is down.

## 9. Relevance to ApkManager

Waydroid is the most practical way for an ApkManager user to *run* an APK they've inspected. A future "Run in Waydroid" action could call `waydroid app install <apk>` followed by `waydroid app launch <package>`, using the package name ApkManager already reads from the manifest.

## 10. Corrections to the source notes

- The notes say Waydroid isn't in Debian or Ubuntu repos. It is in Debian forky, sid, and trixie-backports, and in Ubuntu `universe` for the newest releases.
- The notes' Mint snippet sets `export DISTRO=…` before the repo script. The script ignores that variable and reads `/etc/os-release` or its first argument instead.
