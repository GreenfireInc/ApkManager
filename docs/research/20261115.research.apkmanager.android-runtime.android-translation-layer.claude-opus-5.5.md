## 2. How it works

ATL is to Android what Wine is to Windows. It doesn't boot Android. It loads an app's code into a normal Linux process and supplies its own implementations of the Android APIs that code calls.

| Piece | What it replaces |
|-------|------------------|
| **`art_standalone`** | Android's ART runtime, built for desktop glibc Linux. It runs the app's `classes.dex` bytecode |
| **`bionic_translation`** | Lets the app's native `.so` libraries, compiled against Android's **bionic** libc, run on the host's **glibc** by mapping symbols and behavior |
| **`libandroidfw`** | Android's resource and asset loader (`resources.arsc`, `res/`, `assets/`) |
| **ATL itself (`api-impl`)** | A reimplementation of `android.*` framework classes in Java and C. `View`s become **GTK 4** widgets, OpenGL ES goes through host **EGL**, and audio, input, and OpenXR (VR) map to host libraries. Missing classes and methods are stubbed on demand |
| **`libOpenSLES` (optional)** | Android's native audio API, which some games need |

The app's private data lives in `~/.local/share/android_translation_layer/<apk-name>_/`. ATL passes that directory to the app where Android would pass `/data/data/<app-id>` and `/storage/emulated/0`.

**Trade-offs:** ATL is fast and light, with no VM or full Android boot, and each app is a normal desktop window. But it is **experimental**: an app works only if every API it touches has been implemented. Many apps crash on a missing class until someone writes a stub. Google Play Services are not available.

**Usage:**

```bash
android-translation-layer /path/to/app.apk -l com/example/MainActivity   # run (activity optional)
android-translation-layer --install /path/to/app.apk                     # copy into ATL's data dir and add a .desktop launcher
GDK_DEBUG=gl-egl android-translation-layer app.apk                        # on X11, force EGL (GTK may choose GLX)
```

## 3. Dependencies

### 3.1 Host requirements (all distros)

| Requirement | Why | Notes |
|-------------|-----|-------|
| **x86_64 or aarch64** | ART and bionic_translation are built per architecture | ARM-only native libraries won't load on x86_64 (no ARM translator) |
| **GTK 4 desktop session** (Wayland preferred) | Android views are GTK 4 widgets | On X11, set `GDK_DEBUG=gl-egl` so GTK uses EGL instead of GLX |
| **GPU with EGL / OpenGL ES** (Mesa) | Apps' GL rendering | Software rendering works but is slow |
| **xdg-desktop-portal** | `--install` creates `.desktop` launchers through the portal | Present on GNOME, KDE, and Cinnamon desktops |
| **FUSE 2** (AppImage only) | Mounting the AppImage | Debian/Ubuntu: `libfuse2` (`libfuse2t64` on Debian 13 / Ubuntu 24.04+). Fedora: `fuse-libs` |

### 3.2 Components ATL is made of

A source build compiles all of these. The AppImage bundles them.

| Component | Source | Packaged by Debian / Ubuntu / Fedora? |
|-----------|--------|----------------------------------------|
| `android_translation_layer` | [GitLab](https://gitlab.com/android_translation_layer/android_translation_layer) | No |
| `art_standalone` (ART runtime) | [GitLab](https://gitlab.com/android_translation_layer/art_standalone) | No |
| `bionic_translation` | [GitLab](https://gitlab.com/android_translation_layer/bionic_translation) | No |
| `libopensles-standalone` (optional) | [GitLab](https://gitlab.com/android_translation_layer/libopensles-standalone) | No |
| wolfSSL **with JNI** | [GitHub](https://github.com/wolfSSL/wolfssl) | Distro wolfSSL is built without JNI, so build it yourself |

### 3.3 Build dependencies

| Purpose | Debian / Ubuntu | Fedora |
|---------|-----------------|--------|
| Toolchain | `git meson ninja-build build-essential autoconf automake libtool` | `git meson ninja-build gcc gcc-c++ make autoconf automake libtool` |
| Java (framework and tools) | `default-jdk libasm-java libgetopt-java` | `java-25-openjdk-devel objectweb-asm maven` (getopt is downloaded by Meson) |
| GTK / UI | `libgtk-4-dev libglib2.0-dev libportal-dev libwebkitgtk-6.0-dev` | `pkgconfig(gtk4) pkgconfig(libportal) pkgconfig(webkitgtk-6.0)` |
| Audio / video | `libasound2-dev libavcodec-dev` | (ALSA and FFmpeg are pulled in through the `pkgconfig()` deps) |
| Hardware / system | `libdrm-dev libgudev-1.0-dev libcap-dev` | `pkgconfig(libbsd)` |
| Storage / compression / images | `libsqlite3-dev` | `pkgconfig(sqlite3) pkgconfig(liblz4) pkgconfig(libwebp)` |
| VR / secrets | `libopenxr-dev libsecret-1-dev` | `pkgconfig(openxr) pkgconfig(libsecret-1)` |

**Runtime libraries:** a source build needs the non-`-dev` versions of the same libraries at runtime (GTK 4, WebKitGTK 6, libportal, ALSA, FFmpeg, OpenXR loader, libsecret, SQLite), plus the four companion libraries installed under `/usr/local`. If `/usr/local/lib` (or `lib64`) isn't on the loader path, run `sudo ldconfig` after installing.

## 4. Installation — Debian

There is no Debian package. Use either the AppImage or a source build.

**Option A: AppImage (unofficial, simplest).** Release file names include a commit hash, so download the current `…-anylinux-x86_64.AppImage` from the [releases page](https://github.com/pkgforge-dev/android_translation_layer-AppImage/releases). The build current at the time of writing:

```bash
sudo apt install curl libfuse2                 # libfuse2t64 on Debian 13+; only if the AppImage fails to mount
curl -LO "https://github.com/pkgforge-dev/android_translation_layer-AppImage/releases/download/3e686d14%402026-09-22_1790090775/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
chmod +x Android_Translation_Layer-*-x86_64.AppImage
./Android_Translation_Layer-*-x86_64.AppImage /path/to/app.apk
```

**Option B: build from source.** Step 1 installs the build dependencies (section 3.3, from upstream `doc/Build.md`):

```bash
sudo apt install git meson ninja-build build-essential autoconf automake libtool \
  libasound2-dev libavcodec-dev libcap-dev libdrm-dev libglib2.0-dev libgtk-4-dev \
  libgudev-1.0-dev libopenxr-dev libportal-dev libsqlite3-dev libwebkitgtk-6.0-dev \
  libsecret-1-dev libasm-java libgetopt-java default-jdk
```

ATL also needs four companion libraries that Debian doesn't package: **wolfSSL** (with JNI), **bionic_translation**, **art_standalone**, and optionally **libopensles-standalone**. Step 2 builds each one from source as described in section 7. Step 3 builds ATL. On Debian, point Meson at the distro Java jars:

```bash
git clone https://gitlab.com/android_translation_layer/android_translation_layer.git
cd android_translation_layer
meson setup builddir \
  -Dasm_jar_path=/usr/share/java/asm.jar \
  -Dasm_tree_jar_path=/usr/share/java/asm-tree.jar \
  -Dgetopt_jar_path=/usr/share/java/gnu-getopt.jar
meson compile -C builddir
sudo meson install -C builddir
```

## 5. Installation — Ubuntu (and Linux Mint)

Same as Debian: use the AppImage (Option A) or a source build (Option B). The same `apt install` line works, because Ubuntu uses the same package names. On Ubuntu 24.04 and later, AppImages that need FUSE 2 also need `sudo apt install libfuse2t64`.

## 6. Installation — Fedora

There is no Fedora package. The AppImage (section 4, Option A) works the same way. If it fails to mount, install FUSE 2 with `sudo dnf install fuse-libs`.

**Source build dependencies.** Upstream lists `java-17-openjdk-devel`, but **Fedora 44 no longer ships JDK 17**, so use `java-25-openjdk-devel` (not yet tested with ATL):

```bash
sudo dnf install git meson ninja-build gcc gcc-c++ make autoconf automake libtool maven \
  java-25-openjdk-devel objectweb-asm \
  'pkgconfig(gtk4)' 'pkgconfig(libbsd)' 'pkgconfig(libportal)' 'pkgconfig(sqlite3)' \
  'pkgconfig(libwebp)' 'pkgconfig(liblz4)' 'pkgconfig(openxr)' 'pkgconfig(webkitgtk-6.0)' \
  'pkgconfig(libsecret-1)'
```

Build the companion libraries (section 7), then build ATL. **Fedora requires `-Ddownload_tool_deps=true`**, because `java-getopt` is no longer packaged and Meson downloads it from Maven Central with `mvn`:

```bash
git clone https://gitlab.com/android_translation_layer/android_translation_layer.git
cd android_translation_layer
meson setup builddir -Ddownload_tool_deps=true
meson compile -C builddir
sudo meson install -C builddir
```

## 7. Companion libraries (all three distros)

These steps come from upstream `doc/Build.md`. They need the toolchain from section 3.3. Build them in this order, then run `sudo ldconfig`:

```bash
# wolfSSL with JNI
git clone https://github.com/wolfSSL/wolfssl.git && cd wolfssl
git checkout v5.8.2-stable
autoreconf -i
./configure --enable-shared --disable-opensslall --disable-opensslextra --enable-aescbc-length-checks \
  --enable-curve25519 --enable-ed25519 --enable-ed25519-stream --enable-oldtls --enable-base64encode \
  --enable-tlsx --enable-scrypt --disable-examples --enable-crl --enable-jni --enable-sessioncerts
make && sudo make install && cd ..

# bionic_translation
git clone https://gitlab.com/android_translation_layer/bionic_translation.git && cd bionic_translation
meson setup builddir && meson compile -C builddir && sudo meson install -C builddir && cd ..

# art_standalone (Fedora uses lib64: ____LIBDIR=lib64)
git clone https://gitlab.com/android_translation_layer/art_standalone.git && cd art_standalone
make ____LIBDIR=lib && sudo make ____LIBDIR=lib install && cd ..

# optional: libOpenSLES
git clone https://gitlab.com/android_translation_layer/libopensles-standalone.git && cd libopensles-standalone
meson setup builddir && meson compile -C builddir && sudo meson install -C builddir && cd ..
```

## 8. Detecting an existing installation

No distro package manager knows about ATL on Debian, Ubuntu, or Fedora, so `dpkg -s` and `rpm -q` can't detect it. Check for the two install forms directly.

**Source build** (`sudo meson install` defaults to the `/usr/local` prefix; `libdir` is `lib` on Debian/Ubuntu and `lib64` on Fedora):

| Check | Command | Installed when |
|-------|---------|----------------|
| ATL launcher | `command -v android-translation-layer` | Prints `/usr/local/bin/android-translation-layer` |
| ATL Java framework | `ls /usr/local/lib*/java/dex/android_translation_layer/api-impl.jar` | The file exists. Without it the launcher starts but can't load any app |
| ATL data | `test -d /usr/local/share/atl` | The directory exists |
| art_standalone | `command -v dalvikvm` and `ls /usr/local/lib*/art/` | Both exist. ATL can't start without ART |
| Shared library | `ldconfig -p \| grep libtranslation_layer_main` | The library is listed. If it exists on disk but isn't listed, run `sudo ldconfig` |

**AppImage:** an AppImage isn't registered anywhere, so the only way to find it is to look where users keep them. Release file names start with `Android_Translation_Layer-`:

```bash
ls ~/Applications/Android_Translation_Layer-*.AppImage \
   ~/.local/bin/Android_Translation_Layer-*.AppImage \
   ~/Downloads/Android_Translation_Layer-*.AppImage 2>/dev/null
```

AppImage launchers such as Gear Lever or AppImageLauncher also add a `.desktop` file, so `grep -l Android_Translation_Layer ~/.local/share/applications/*.desktop` finds integrated copies.

```bash
# One-shot check
if command -v android-translation-layer >/dev/null; then
  echo "ATL (source build) at $(command -v android-translation-layer)"
  command -v dalvikvm >/dev/null || echo "warning: art_standalone (dalvikvm) missing"
elif ls ~/Applications/Android_Translation_Layer-*.AppImage >/dev/null 2>&1; then
  echo "ATL AppImage: $(ls ~/Applications/Android_Translation_Layer-*.AppImage | head -n1)"
else
  echo "ATL not installed"
fi
```

**From ApkManager (Vala):** `GLib.Environment.find_program_in_path("android-translation-layer")` covers the source build. For the AppImage, list `~/Applications` and `~/.local/bin` for names starting with `Android_Translation_Layer-` and ending in `.AppImage`, and remember the path the user picks, because there's no fixed location.

## 9. Relevance to ApkManager

ATL is the closest match to how ApkManager already treats an APK: as a file, not as something installed into a virtual phone. A future "Try with ATL" action could run `android-translation-layer <apk> -l <launcher activity>`, using the launcher activity ApkManager reads from the decoded manifest. Expect many apps to fail, and show ATL's stderr to the user.

## 10. Corrections to the source notes

- The notes' AppImage URL (`releases/latest/download/android-translation-layer-x86_64.AppImage`) doesn't exist. Real asset names look like `Android_Translation_Layer-<hash>-anylinux-x86_64.AppImage`.
- The notes' short dependency lists (`gtk4-devel libglvnd-devel wayland-devel`) are incomplete. ATL also needs the companion libraries plus WebKitGTK 6, OpenXR, libportal, Java, and others.
- The notes mention a "Flatpak BaseApp". No generic ATL app exists on Flathub; the only ATL-based Flathub app found is NewPipe (unofficial port).
- The notes link a "Nura Wiki" page as the ATL website. It could not be verified, so it is not listed here.
