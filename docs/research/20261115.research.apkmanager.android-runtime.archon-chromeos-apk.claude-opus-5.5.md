## 2. How it works

1. **ARC.** In 2014 Google released *App Runtime for Chrome* (ARC) to run selected Android apps on Chromebooks. It's an Android 4.4 runtime (Dalvik plus framework) compiled for **Native Client**, Chrome's sandbox for native code, and shipped as a Chrome App.
2. **ARChon.** Developer Vlad Filippov repackaged ARC as **ARChon**, an unpacked Chrome extension. It removes ARC's whitelist and lets it load in desktop Chrome on Windows, macOS, and Linux, not only Chrome OS.
3. **chromeos-apk.** A Node.js command-line tool that wraps an APK in a Chrome App directory (`manifest.json` plus the APK and metadata) that ARChon knows how to launch.
4. **Running.** You load ARChon and each converted app as *unpacked extensions* at `chrome://extensions`, then launch the app from `chrome://apps`. The app runs inside the browser's NaCl sandbox, drawing through Pepper (PPAPI) graphics.

**Why it no longer works:** Google ended Chrome Apps on desktop platforms and removed NaCl from Chrome, so ARChon has nothing to run on. Android 4.4 is also far too old for current apps. On Chromebooks, ARC was replaced by ARC++ (a container) and later ARCVM (a VM), neither of which is available on desktop Linux.

## 3. Dependencies

### 3.1 Converter (`chromeos-apk` 4.0.2 on npm)

| Dependency | Debian / Ubuntu | Fedora | Notes |
|------------|-----------------|--------|-------|
| **Node.js + npm** | `nodejs npm` | `nodejs npm` | Any current Node runs it; the code is plain 2014-era JavaScript |
| npm modules (installed automatically by `npm install -g`) | `adbkit-apkreader ^1.0.0` (reads the APK manifest), `commander ^2.3.0` (CLI), `chalk ^0.5.1` (colors), `ncp ^0.6.0` (copies files) | same | Pulled from the npm registry |
| **32-bit C++ runtime** (sometimes) | `lib32stdc++6` | `libstdc++.i686` | The upstream README says Ubuntu "might need" it. Install only if the converter fails |

### 3.2 Runtime (ARChon 1.2)

| Dependency | Notes |
|------------|-------|
| **Google Chrome or Chromium 37+ that still supports Chrome Apps and Native Client (NaCl)** | The hard blocker. Current Chrome and Chromium removed both on Linux, so you'd need an archived build from that era, run offline and unpatched, which is a security risk |
| **The ARChon ZIP that matches the browser's bitness** | `v1.2-x86_64` for 64-bit Chrome, `v1.2-x86_32` for 32-bit, `v1.2-ARM` for ARM Chromebooks |
| `unzip` | To extract the runtime: `sudo apt install unzip` / `sudo dnf install unzip` |

## 4. Installation — Debian

These steps are historical and need a very old Chrome build that still loads Chrome Apps and NaCl (section 3.2):

```bash
sudo apt install nodejs npm unzip curl          # section 3.1 / 3.2 dependencies
sudo npm install -g chromeos-apk                # pulls adbkit-apkreader, commander, chalk, ncp
chromeos-apk com.example.app.apk          # creates com.example.app.android/ (add --tablet for tablet layout)

# ARChon runtime (64-bit):
curl -LO https://bitbucket.org/vladikoff/archon/get/v1.2-x86_64.zip
unzip v1.2-x86_64.zip
# Chrome → chrome://extensions → Developer mode → "Load unpacked" → the ARChon folder, then the app folder
```

If the converter fails on a missing 32-bit C++ library, enable i386 multiarch and install `lib32stdc++6`:

```bash
sudo dpkg --add-architecture i386 && sudo apt update && sudo apt install lib32stdc++6
```

## 5. Installation — Ubuntu (and Linux Mint)

Same as Debian (section 4), including `lib32stdc++6` if the converter complains:

```bash
sudo apt install nodejs npm unzip curl
sudo npm install -g chromeos-apk
# optional: sudo apt install lib32stdc++6
```

## 6. Installation — Fedora

```bash
sudo dnf install nodejs npm unzip curl      # section 3 dependencies
sudo npm install -g chromeos-apk            # pulls adbkit-apkreader, commander, chalk, ncp
# optional, only if the converter needs it: sudo dnf install libstdc++.i686
# download and load the ARChon ZIP as in section 4
```

The same limitation applies: no current Chrome or Chromium build on Fedora can load it.

## 7. Detecting an existing installation

ARChon has two parts to detect: the `chromeos-apk` converter (an npm package) and the ARChon runtime (an unpacked Chrome extension).

| Check | Command | Installed when |
|-------|---------|----------------|
| Converter on `PATH` | `command -v chromeos-apk` | Prints a path such as `/usr/local/bin/chromeos-apk` or `/usr/bin/chromeos-apk` |
| Converter package | `npm ls -g chromeos-apk` | Lists `chromeos-apk@4.0.2` (prints `(empty)` otherwise) |
| ARChon loaded in Chrome | `grep -il archon ~/.config/google-chrome/*/Preferences ~/.config/chromium/*/Preferences 2>/dev/null` | A profile's `Preferences` file mentions ARChon. Unpacked extensions are recorded there by folder path, so this works when the ARChon folder name still contains "archon" |
| Chrome present | `command -v google-chrome google-chrome-stable chromium chromium-browser` | One prints a path |

```bash
# One-shot check
command -v chromeos-apk >/dev/null && echo "chromeos-apk converter installed" || echo "chromeos-apk not installed"
grep -qil archon ~/.config/google-chrome/*/Preferences ~/.config/chromium/*/Preferences 2>/dev/null \
  && echo "ARChon extension registered in a Chrome/Chromium profile" \
  || echo "ARChon extension not found"
```

A positive result doesn't mean it works: current Chrome and Chromium releases no longer run Native Client, so ARChon can't start even when it's registered.

**From ApkManager (Vala):** not worth detecting beyond `GLib.Environment.find_program_in_path("chromeos-apk")`. If it's found, treat ARChon as unsupported.

## 8. Relevance to ApkManager

None for running apps. It's interesting only as history: it showed that an APK can be repackaged into a different host format with a manifest that maps Android metadata to the host's. ApkManager already reads that same metadata (label, icon, package, launcher activity).
