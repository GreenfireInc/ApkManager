## 2. How it works

Anbox was the first widely used project to run Android in a container rather than an emulator. Waydroid grew out of it.

1. **Container.** Anbox's container manager (`anbox container-manager`, run by systemd) starts an **LXC** container that boots an Android 7.1 (Nougat) `android.img` (a squashfs root filesystem).
2. **Kernel modules.** Android's `ashmem` (shared memory) and `binder` (IPC) aren't in normal desktop kernels, so Anbox needed the out-of-tree **`anbox-modules`** (`ashmem_linux`, `binder_linux`), usually built with DKMS.
3. **Session manager.** A per-user `anbox session-manager` handles the host side. It connects to Android over sockets and pipes.
4. **Graphics.** Android's OpenGL ES calls are serialized through the Android Emulator's GL pipe ("goldfish" OpenGL translator) and drawn by the host's OpenGL. Each Android activity becomes an ordinary X11 or Wayland window through SDL.
5. **Apps.** APKs are installed with `adb install app.apk`, since the container exposes adb, and launched from desktop entries or `anbox launch --package=<pkg>`.

**Why it was replaced:** the out-of-tree kernel modules broke with new kernels. The GL pipe was slow and incomplete, and Android 7 aged out of app support. Waydroid replaced all three: mainline `binderfs`, native Mesa graphics, and Android 11/13 images.

## 3. Dependencies

### 3.1 Host requirements

| Requirement | Why | Notes |
|-------------|-----|-------|
| **`ashmem_linux` and `binder_linux` kernel modules** | Android shared memory and IPC | From the out-of-tree [anbox-modules](https://github.com/anbox/anbox-modules) (also archived), built with DKMS. **ashmem was removed from mainline Linux in 5.18**, and the modules don't build on current kernels, which is the main reason Anbox is unusable today |
| **Kernel headers + DKMS** | Building those modules | `linux-headers-$(uname -r)`, `dkms` |
| **`android.img`** | The Android 7.1 root filesystem | Not included in the package. Expected at `/var/lib/anbox/android.img`. The old downloads at `build.anbox.io` may be gone, so you may have to build it from Anbox's AOSP tree |
| **OpenGL ES / EGL on the host** | Rendering through the GL pipe | Mesa (`libegl1`, `libgles2`) |
| **systemd + D-Bus user session** | `anbox-container-manager.service` and the per-user session manager | `dbus-user-session` (recommended by the package) |

### 3.2 Package dependencies (pulled in by `apt install anbox`)

These are identical on Debian 11 and Ubuntu 22.04, apart from version numbers:

| Group | Packages |
|-------|----------|
| Containers / networking | `lxc`, `liblxc1`, `iptables` |
| Graphics / windows | `libegl1`, `libgles2`, `libsdl2-2.0-0`, `libsdl2-image-2.0-0` |
| Boost (C++) | `libboost-filesystem1.74.0`, `libboost-iostreams1.74.0`, `libboost-log1.74.0`, `libboost-program-options1.74.0`, `libboost-thread1.74.0` |
| IPC / system | `libprotobuf-lite23`, `libsdbus-c++0` (Debian) / `libsdbus-c++1` (Ubuntu), `libsystemd0`, `init-system-helpers` |
| C/C++ runtime | `libc6`, `libstdc++6`, `libgcc-s1` |
| Recommended | `dbus-user-session` |

**Also needed for actual use:** `adb` (to install APKs) and `dkms` plus `linux-headers-$(uname -r)` (for the modules).

## 4. Installation — Debian

Only **Debian 11 (bullseye)** carries the package, in `contrib`. Enable `contrib` first, then:

```bash
# 1. Dependencies for the kernel modules and APK installs
sudo apt install dkms linux-headers-$(uname -r) git adb

# 2. Kernel modules (anbox-modules README steps)
git clone https://github.com/anbox/anbox-modules.git && cd anbox-modules
sudo cp anbox.conf /etc/modules-load.d/
sudo cp 99-anbox.rules /lib/udev/rules.d/
sudo cp -rT ashmem /usr/src/anbox-ashmem-1
sudo cp -rT binder /usr/src/anbox-binder-1
sudo dkms install anbox-ashmem/1
sudo dkms install anbox-binder/1
sudo modprobe ashmem_linux && sudo modprobe binder_linux

# 3. Anbox itself (pulls the section 3.2 libraries)
sudo apt install anbox

# 4. Put an android.img at /var/lib/anbox/android.img, then:
sudo systemctl enable --now anbox-container-manager
adb install app.apk
```

On Debian 12 and later, there's no package, and the modules don't build on those kernels. Use [Waydroid](20261115.research.apkmanager.android-runtime.waydroid.claude-opus-5.5.md).

## 5. Installation — Ubuntu (and Linux Mint)

Available in **`universe`** on Ubuntu **22.04 (jammy)** and **20.04 (focal)**, and on Mint 20.x and 21.x through those bases:

```bash
sudo apt install dkms linux-headers-$(uname -r) git adb    # module build + APK install deps
sudo apt install anbox                                     # pulls the section 3.2 libraries
```

Then build the kernel modules exactly as in Debian step 2. Ubuntu's generic kernels ship `binder_linux` in `linux-modules-extra-$(uname -r)`; `ashmem` is not available in newer kernels. You also need an Android image (`android.img`). Anbox's image downloads were hosted at `build.anbox.io` and may no longer be available. Building one from AOSP source is the only reliable route.

The old `sudo snap install --devmode --beta anbox` no longer works, because the snap was removed.

## 6. Installation — Fedora

**Not available**, so there are no dependencies to list. Fedora never packaged Anbox, and the old community COPR repos are long dead. Use [Waydroid](20261115.research.apkmanager.android-runtime.waydroid.claude-opus-5.5.md) (`sudo dnf install waydroid`).

## 7. Detecting an existing installation

Anbox can be left over from an older install even though it's no longer packaged, so detection is mostly about finding stale copies.

| Check | Command | Installed / ready when |
|-------|---------|------------------------|
| Command on `PATH` | `command -v anbox` | Prints `/usr/bin/anbox` (apt) or `/snap/bin/anbox` (old snap) |
| Version | `anbox version` | Prints the Anbox version |
| Package (Debian 11, Ubuntu 20.04/22.04) | `dpkg -s anbox` | Exit 0, with `Status: install ok installed` |
| Snap (legacy) | `snap list anbox` | Lists `anbox`. The snap can't be reinstalled, but existing installs remain |
| Kernel modules | `lsmod \| grep -E 'ashmem_linux\|binder_linux'`, or `ls /dev/ashmem /dev/binder` | Both modules are loaded and both device nodes exist |
| Container manager | `systemctl is-active anbox-container-manager` | Prints `active` |
| Android image | `test -f /var/lib/anbox/android.img` | The image exists. Without it Anbox starts but has nothing to boot |
| Feature check | `anbox check-features` | Reports that the CPU supports the features the image needs |

```bash
# One-shot check
if command -v anbox >/dev/null; then
  echo "Anbox installed at $(command -v anbox)"
  [ -f /var/lib/anbox/android.img ] || echo "warning: no /var/lib/anbox/android.img"
  [ -e /dev/binder ] && [ -e /dev/ashmem ] || echo "warning: ashmem_linux / binder_linux modules not loaded"
else
  echo "Anbox not installed"
fi
```

Fedora never packaged Anbox, so on Fedora only a manual source build (`/usr/local/bin/anbox`) can show up. Current kernels (5.18 and later) removed ashmem, so a detected Anbox install will usually fail the kernel module check.

**From ApkManager (Vala):** `GLib.Environment.find_program_in_path("anbox")`. If found, treat it as unsupported and suggest Waydroid, its maintained successor.
