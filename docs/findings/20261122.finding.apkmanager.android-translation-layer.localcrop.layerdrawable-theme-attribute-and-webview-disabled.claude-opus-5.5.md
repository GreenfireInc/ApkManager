## Short answer

This run didn't crash: ATL exited with status 0 after about 48 seconds, when the window was closed. Two things kept LocalCrop from working:

1. **The splash background failed to inflate.** AndroidX's splash-screen theme sets `android:windowBackground` to a layer list whose icon item is `android:drawable="?windowSplashScreenAnimatedIcon"`, a **theme attribute**, not a direct `@drawable/…` reference. ATL's `LayerDrawable` only understands direct references, so the item looks empty. AppCompat catches the resulting `XmlPullParserException`, and the activity carries on without a window background.
2. **The app's whole user interface is a WebView, and ATL's WebView is off by default.** LocalCrop is a Capacitor app: `BridgeActivity` hosts a WebView that loads the bundled web app from `assets/public`. Unless `ATL_UGLY_ENABLE_WEBVIEW` is set, ATL's `WebView` is an empty view. Even with it set, Capacitor serves its pages through `WebViewClient.shouldInterceptRequest`, which ATL never calls. Either way the window stays empty.

## Why it happens

### Theme attributes in layer lists

ATL's `LayerDrawable.inflate()` comes from an older Android release:

```java
int drawableRes = a.getResourceId(
    com.android.internal.R.styleable.LayerDrawableItem_drawable, 0);
...
if (drawableRes != 0) {
	dr = r.getDrawable(drawableRes, theme);
} else {
	// expects a child element such as <shape> or <bitmap>
	...
	throw new XmlPullParserException(parser.getPositionDescription() + ": <item> tag requires a 'drawable' attribute or "
```

For `?windowSplashScreenAnimatedIcon` the attribute's raw value has type `TYPE_ATTRIBUTE`. `getResourceId` returns 0 unless the `TypedArray` was obtained against a theme that resolves the reference. `Resources.loadDrawable` → `Drawable.createFromXml(r, parser)` is called *without* a theme in this stack, so the reference stays unresolved and the item counts as having no drawable. Android 5.0 and later handle this with `TypedArray.extractThemeAttrs()` and `applyTheme()`.

### WebView

```c
// ATL src/api-impl-jni/widgets/android_webkit_WebView.c
if (!getenv("ATL_UGLY_ENABLE_WEBVIEW"))
	return Java_android_view_View_native_1constructor(env, this, context, attrs);
```

ATL deliberately skips WebKitGTK unless asked, because most apps only use WebView for ads and fingerprinting. Capacitor and Cordova apps are the exception: the WebView *is* the app.

I reran with `ATL_UGLY_ENABLE_WEBVIEW=1`. There was no crash, but no web content either, because Capacitor's `WebViewLocalServer` serves `https://localhost/…` from `assets/public` through `WebViewClient.shouldInterceptRequest`. ATL's `WebViewClient` doesn't have that method, and ATL's WebKitGTK glue never asks the app for intercepted responses.

## Suggested fixes in the runtime (ATL)

### 1. Resolve theme attributes in `LayerDrawable` (and pass the theme down)

`src/api-impl/android/graphics/drawable/LayerDrawable.java`, in `inflate(...)`:

```java
	TypedValue value = new TypedValue();
	Drawable dr = null;
	if (a.getValue(com.android.internal.R.styleable.LayerDrawableItem_drawable, value)) {
		if (value.type == TypedValue.TYPE_ATTRIBUTE && theme != null) {
			// "?attr/..." -> resolve through the theme first
			if (theme.resolveAttribute(value.data, value, true) && value.resourceId != 0) {
				dr = r.getDrawable(value.resourceId, theme);
			}
		} else if (value.resourceId != 0) {
			dr = r.getDrawable(value.resourceId, theme);
		}
	}
	a.recycle();

	if (dr == null) {
		while ((type = parser.next()) == XmlPullParser.TEXT) {
		}
		if (type != XmlPullParser.START_TAG) {
			// Android skips an unresolvable theme attribute instead of failing the whole drawable
			if (value.type == TypedValue.TYPE_ATTRIBUTE) {
				continue;
			}
			throw new XmlPullParserException(...);
		}
		dr = Drawable.createFromXmlInner(r, parser, attrs, theme);
	}
```

`src/api-impl/android/content/res/Resources.java`, in `loadDrawable(...)`: pass the theme to `Drawable.createFromXml(this, parser, theme)` so XML drawables inflated for a themed context can resolve `?attr` references. The same applies to `<color android:color="?windowSplashScreenBackground">` in the first item.

### 2. Make Capacitor and Cordova apps usable

a) **ApkManager side, no ATL change:** set `ATL_UGLY_ENABLE_WEBVIEW=1` when the APK is a web-wrapper app. Detection is cheap from the APK file list: `assets/public/` with `com/getcapacitor/` classes (Capacitor), or `assets/www/` with `org/apache/cordova/` (Cordova). This would go in `RuntimeRunner.start_atl_debug` and the normal ATL launch.

b) **ATL side:** support `shouldInterceptRequest` by registering a WebKitGTK URI scheme handler for `https://localhost` traffic. In practice, add `webkit_web_context_register_uri_scheme` for a private scheme and rewrite `https://localhost/` to it, as ATL already does for `file:///android_asset/` → `android-asset:///assets/`. The handler would call into Java:

```java
// src/api-impl/android/webkit/WebViewClient.java
public WebResourceResponse shouldInterceptRequest(WebView view, WebResourceRequest request) {
	return null;
}
public WebResourceResponse shouldInterceptRequest(WebView view, String url) {
	return null;
}
```

```java
// src/api-impl/android/webkit/WebView.java
@Export
WebResourceResponse internalShouldInterceptRequest(String url) {
	if (webViewClient == null)
		return null;
	return webViewClient.shouldInterceptRequest(this, new WebResourceRequestImpl(url));
}
```

Then in C, finish the `WebKitURISchemeRequest` with the response's `getData()` stream, `getMimeType()` and status, or fall back to loading the original URL when the result is `null`.
