## Short answer

Flutter's engine calls `dlopen("libandroid.so")` while starting up and treats a failure as fatal (`FML_CHECK`). ATL installs its NDK library as `libandroid.so.0`. bionic_translation, ATL's Android-to-glibc linker, finds the real file through a small mapping file, `share/bionic_translation/cfg.d/bionic_translation.cfg`. **The AppImage doesn't include that mapping file**, so the lookup falls through to glibc, which looks for a literal `libandroid.so`, finds nothing, and Flutter aborts.

Confirmed by experiment: running the same AppImage with the mapping file supplied through `XDG_DATA_DIRS` gets the app past this check.

## What the error is

Debug capture (lines 33–35):

```text
bundle.getBoolean(io.flutter.embedding.android.EnableSkParagraph, true) called
bundle.getBoolean(io.flutter.embedding.android.LeakVM, true) called

```

The capture doesn't show the line explaining the abort, probably because ATL's output was still buffered when it died (see "Capture caveat" below). Running the AppImage directly shows it:

```text
A/flutter (399379): [FATAL:flutter/shell/platform/android/flutter_main.cc(48)] Check failed: libandroid.
Fatal signal 6 (SIGABRT), code -6 (SI_TKILL)
```

The Flutter source at that line (engine 3.10):

```cpp
bool IsATraceEnabled() {
  auto libandroid = fml::NativeLibrary::Create("libandroid.so");
  FML_CHECK(libandroid);
  auto atrace_fn =
      libandroid->ResolveFunction<bool (*)(void)>("ATrace_isEnabled");
  ...
```

`fml::NativeLibrary::Create` is a plain `dlopen("libandroid.so", RTLD_NOW)`.

## Why it happens

1. ATL builds its NDK `libandroid` with `soversion: 0` (ATL `meson.build`, line 111 onward). The installed files are `libandroid.so.0`, plus a `libandroid.so` development symlink in a normal install.
2. `quick-sharun` copies runtime libraries into the AppImage by soname and drops development symlinks. The AppImage's `lib/` contains `libandroid.so.0` but no `libandroid.so`, which I checked by mounting the AppImage.
3. bionic_translation handles exactly this case with a mapping file:

   ```text
   # bionic_translation cfg.d/bionic_translation.cfg
   libandroid.so       libandroid.so.0
   libEGL.so           libEGL.so.1
   libGLESv2.so        libGLESv2.so.2
   libvulkan.so        libvulkan.so.1
   ...
   ```

   It's installed to `/usr/share/bionic_translation/cfg.d/` and read from `$XDG_DATA_DIRS`. The recipe's `quick-sharun` list (`/usr/bin/android-translation-layer`, `/usr/lib/art`, `/usr/lib/java`, `/usr/share/atl`, …) doesn't include `/usr/share/bionic_translation`, so the mapping is missing at runtime.
4. Normal library loading still mostly works, because `libandroid.so.0` is already loaded globally by ATL's own `libtranslation_layer_main.so`, so symbols in `libflutter.so`'s `DT_NEEDED: libandroid.so` resolve anyway. Only Flutter's explicit `dlopen("libandroid.so")` returns `NULL`.
5. Newer Flutter engines (such as RustDesk's) don't have this `IsATraceEnabled` check, which is why they get further. See the RustDesk finding.

### Experiment

```bash
mkdir -p /tmp/btcfg/bionic_translation/cfg.d
cp bionic_translation/cfg.d/bionic_translation.cfg /tmp/btcfg/bionic_translation/cfg.d/
XDG_DATA_DIRS="/tmp/btcfg:$XDG_DATA_DIRS" "~/Applications/Android Translation Layer" \
    ~/Applications/android/io.dahliaos.calculator.from.F-Droid.universal.apk
```

Result: `Check failed: libandroid` is gone. Flutter starts its engine threads (`Failed to set UI task runner priority` / `raster task runner priority`, which are harmless) and then stops at the next blocker, described below.

## Suggested fix in the runtime

### 1. Packaging (ATL.edge recipe, and upstream pkgforge-dev)

`packaging/atl-edge/make-appimage.sh`: bundle the mapping directory.

```sh
quick-sharun \
	/usr/bin/android-translation-layer \
	/usr/bin/addr2line                 \
	/usr/bin/dex2oat                   \
	/usr/bin/dalvikvm                  \
	/usr/bin/dx                        \
	/usr/lib/libOpenSLES.so*           \
	/usr/lib/java                      \
	/usr/lib/art                       \
	/usr/share/atl                     \
	/usr/share/bionic_translation
```

sharun adds the AppDir's `share/` to `XDG_DATA_DIRS`, so bionic_translation should then find `cfg.d` without further changes. Check that after rebuilding: `--appimage-mount` and look for `share/bionic_translation/cfg.d/bionic_translation.cfg`.

As a fallback that doesn't rely on `XDG_DATA_DIRS`, also add the unversioned symlinks bionic_translation would otherwise map:

```sh
ln -sf libandroid.so.0 ./AppDir/lib/libandroid.so
ln -sf libOpenSLES.so.1 ./AppDir/lib/libOpenSLES.so
ln -sf libvulkan.so.1  ./AppDir/lib/libvulkan.so
```

(`libEGL.so` already exists unversioned in the AppImage.)

### 2. Robustness in bionic_translation

When an app `dlopen`s a bare `libX.so` with no mapping, try `libX.so.0`, `.1` and `.2` in turn before giving up. A small change in `apkenv_find_library` (`linker/linker.c`) would stop packaging slips like this from breaking apps.

### 3. Second blocker: `android.view.accessibility.AccessibilityRecord`

With the mapping in place, this Flutter version aborts next with:

```text
JNI DETECTED ERROR IN APPLICATION: JNI GetMethodID called with pending exception
  java.lang.NoClassDefFoundError: Failed resolution of: Landroid/view/accessibility/AccessibilityRecord;
```

ATL's `src/api-impl/android/view/accessibility/` has `AccessibilityManager`, `AccessibilityNodeInfo`, `AccessibilityNodeProvider` and `CaptioningManager`, but no `AccessibilityRecord` or `AccessibilityEvent`. Flutter's `AccessibilityBridge` refers to both. Minimal stubs:

With `AccessibilityManager.isEnabled()` returning `false`, which ATL already does, Flutter never sends these events. It only needs the classes to resolve. After that, expect the same `android.media.Image` blocker as RustDesk (see that finding), because both use the same engine registration code.

## Capture caveat

ApkManager's debug capture missed the `A/flutter … Check failed` line, which is visible when running ATL in a terminal. ATL's stdout is block-buffered when it writes to a pipe, so output that's still buffered when the process aborts is lost. ApkManager could give the child a pseudo-terminal, or set `stdbuf -oL`, to keep those lines.

## Noise in this log (not the cause)

- `Unrecognized value "gl-egl"`: from ApkManager's `GDK_DEBUG=gl-egl`. Harmless.
- `apply_path_overrides: !!! app trying to access >/system/fonts/…<`: Flutter probes Android's system fonts, and ATL redirects it to fontconfig. Harmless.
