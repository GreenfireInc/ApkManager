## Short answer

Fing's splash screen reads an XML resource (`res/xml/…`) with `XmlResourceParser` and asks for the text between tags (`getText()`). ATL's `XmlBlock.Parser.getText()` calls the native method `nativeGetText`, which ATL declares in Java but **never implements in C**. ART throws `UnsatisfiedLinkError`, and the process aborts.

---

## What the error is

```text
at android.content.res.XmlBlock.nativeGetText(Native Method)
at android.content.res.XmlBlock.access$100(Unknown Source:0)
at android.content.res.XmlBlock$Parser.getText(Unknown Source:2)
at bn.b.<clinit>(Unknown Source:162)
at com.overlook.android.fing.ui.main.SplashActivity.onCreate(Unknown Source:123)
JNI DETECTED ERROR IN APPLICATION: JNI GetMethodID called with pending exception
  java.lang.UnsatisfiedLinkError: No implementation found for int android.content.res.XmlBlock.nativeGetText(long)
  (tried Java_android_content_res_XmlBlock_nativeGetText and Java_android_content_res_XmlBlock_nativeGetText__J)
```

`UnsatisfiedLinkError: No implementation found` means ART searched the loaded native libraries for `Java_android_content_res_XmlBlock_nativeGetText` and found nothing. The failure is in a static initializer (`bn.b.<clinit>`), which makes it fatal for that class.

## Why it happens

Comparing the natives `XmlBlock.java` declares with what `android_content_res_XmlBlock.c` defines shows five missing:

| Declared in `XmlBlock.java` | Implemented in C |
|------|------|
| `nativeGetText` | **missing**, used by `Parser.getText()` (this crash) |
| `nativeGetNamespace` | **missing**, used by `Parser.getNamespace()` |
| `nativeGetAttributeNamespace` | **missing**, used by `Parser.getAttributeNamespace()` |
| `nativeGetIdAttribute` | **missing**, used by `Parser.getIdAttribute()` |
| `nativeGetStringBlock` | **missing**, used when `XmlBlock` builds its string pool |

Most layouts and drawables never ask for element text, so this rarely comes up. Apps that keep data in `res/xml` (configuration lists, vendor tables and so on), as Fing does, hit it right away.

The androidfw C API that ATL's JNI code uses (`ResXMLParser_*`) also has no text accessor. Its wrappers cover element names, attributes, line numbers, `indexOfID/Class/Style` and so on, but not `ResXMLParser::getTextID()` or `getElementNamespaceID()`. So the fix needs two small changes in two repositories.

---

## Suggested fix in the runtime

### 1. art_standalone: expose the missing `ResXMLParser` getters

`libandroidfw/include/androidfw/androidfw_c_api.h`:

```c
int32_t ResXMLParser_getTextID(const struct ResXMLParser *parser);
int32_t ResXMLParser_getElementNamespaceID(const struct ResXMLParser *parser);
int32_t ResXMLParser_getAttributeNamespaceID(const struct ResXMLParser *parser, size_t idx);
```

`libandroidfw/androidfw_c_api.cpp`, in the style of the existing wrappers:

```cpp
extern "C" int32_t ResXMLParser_getTextID(const struct ResXMLParser *parser)
{
  const android::ResXMLParser *parserPtr = reinterpret_cast<const android::ResXMLParser *>(parser);
  return parserPtr->getTextID();
}

extern "C" int32_t ResXMLParser_getElementNamespaceID(const struct ResXMLParser *parser)
{
  const android::ResXMLParser *parserPtr = reinterpret_cast<const android::ResXMLParser *>(parser);
  return parserPtr->getElementNamespaceID();
}

extern "C" int32_t ResXMLParser_getAttributeNamespaceID(const struct ResXMLParser *parser, size_t idx)
{
  const android::ResXMLParser *parserPtr = reinterpret_cast<const android::ResXMLParser *>(parser);
  return parserPtr->getAttributeNamespaceID(idx);
}
```

### 2. ATL: implement the natives

`src/api-impl-jni/content/android_content_res_XmlBlock.c`:

```c
JNIEXPORT jint JNICALL Java_android_content_res_XmlBlock_nativeGetText(JNIEnv *env, jclass this, jlong parser_ptr)
{
	struct ResXMLParser *parser = (struct ResXMLParser *)_PTR(parser_ptr);
	return ResXMLParser_getTextID(parser);
}

JNIEXPORT jint JNICALL Java_android_content_res_XmlBlock_nativeGetNamespace(JNIEnv *env, jclass this, jlong parser_ptr)
{
	struct ResXMLParser *parser = (struct ResXMLParser *)_PTR(parser_ptr);
	return ResXMLParser_getElementNamespaceID(parser);
}

JNIEXPORT jint JNICALL Java_android_content_res_XmlBlock_nativeGetAttributeNamespace(JNIEnv *env, jclass this, jlong parser_ptr, jint index)
{
	struct ResXMLParser *parser = (struct ResXMLParser *)_PTR(parser_ptr);
	return ResXMLParser_getAttributeNamespaceID(parser, index);
}

JNIEXPORT jint JNICALL Java_android_content_res_XmlBlock_nativeGetIdAttribute(JNIEnv *env, jclass this, jlong parser_ptr)
{
	struct ResXMLParser *parser = (struct ResXMLParser *)_PTR(parser_ptr);
	ssize_t idx = ResXMLParser_indexOfID(parser);
	if (idx < 0)
		return -1;
	return ResXMLParser_getAttributeValueStringID(parser, idx);
}
```

`XmlBlock.Parser.getText()` already maps a negative ID to `null` and otherwise looks the ID up in the string pool (`id >= 0 ? getPooledString(id) : null`), so returning the `ResXMLParser` text ID is all that's needed. The generated header (`generated_headers/android_content_res_XmlBlock.h`) already declares these functions.

### 3. Optional: catch this class of bug at build time

A build step could compare each `native` declaration in `api-impl` against the symbols exported by `libtranslation_layer_main.so` and print the unimplemented ones. That would have flagged all five methods above.

## What to expect after the fix

Fing should get past the splash screen. It's a network scanner: it needs raw sockets, ARP and Wi-Fi APIs (`WifiManager`, `ConnectivityManager` details) that ATL stubs, so scans will probably find nothing even once the user interface works.
