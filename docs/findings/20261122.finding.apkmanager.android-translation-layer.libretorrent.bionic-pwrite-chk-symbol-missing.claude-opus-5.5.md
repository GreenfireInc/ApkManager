## Short answer

LibreTorrent's torrent engine, `libtorrent4j.so` (libtorrent built with the Android NDK), was compiled with `_FORTIFY_SOURCE`. Its `pwrite()` calls became calls to bionic's checked `__pwrite_chk()`. bionic_translation provides checked variants for `read`, `write`, `memcpy`, `strcpy` and so on, but **not for `pwrite`**. glibc has no `__pwrite_chk` either, only `__pread_chk`. The library fails to load, LibreTorrent's `TorrentEngine` can't be created, and the process aborts.

- `apkenv_reloc_library … cannot locate symbol` comes from bionic_translation's linker (descended from apkenv) while it relocates `libtorrent4j.so`. Every undefined symbol must resolve to a `bionic_`-prefixed replacement or to a host (glibc) symbol.
- libtorrent4j catches the `UnsatisfiedLinkError` and rethrows it as `LinkageError` with a hint about CPU architecture. That hint is misleading: this is the correct x86_64 binary, and only one libc symbol is missing.
- The failure ends up in `HomeViewModel` creation, which kills `MainActivity.onCreate`.

## Why it happens

With `_FORTIFY_SOURCE=2`, the NDK's bionic headers redirect `pwrite(fd, buf, n, off)` to `__pwrite_chk(fd, buf, n, off, __builtin_object_size(buf))` (and the 64-bit offset form to `__pwrite64_chk`). bionic_translation resolves symbols like this:

1. Look for `bionic___pwrite_chk` in the translation layer.
2. Otherwise look for `__pwrite_chk` in the host process (glibc).

Neither exists. bionic_translation's `libc-chk.c` already has the pattern for the read/write pair:

```c
ssize_t bionic___read_chk(int fd, void *buf, size_t count, size_t buf_size)
{
	return read(fd, buf, count);
}
...
ssize_t bionic___write_chk(int fd, const void* buf, size_t count, size_t buf_size) {
	if (__builtin_expect(count > buf_size, 0)) {
		fprintf(stderr, "write: prevented read past end of buffer");
		abort();
	}
	...
	return write(fd, buf, count);
}
```

The positional versions were never added.

## Suggested fix in the runtime (bionic_translation)

`libc/libc-chk.c`, next to `bionic___write_chk`:

```c
ssize_t bionic___pwrite_chk(int fd, const void *buf, size_t count, off_t offset, size_t buf_size)
{
	if (__builtin_expect(count > buf_size, 0)) {
		fprintf(stderr, "pwrite: prevented read past end of buffer");
		abort();
	}
	if (__builtin_expect(count > SSIZE_MAX, 0)) {
		fprintf(stderr, "pwrite: count > SSIZE_MAX");
		abort();
	}
	return pwrite(fd, buf, count, offset);
}

ssize_t bionic___pwrite64_chk(int fd, const void *buf, size_t count, off64_t offset, size_t buf_size)
{
	if (__builtin_expect(count > buf_size, 0)) {
		fprintf(stderr, "pwrite64: prevented read past end of buffer");
		abort();
	}
	if (__builtin_expect(count > SSIZE_MAX, 0)) {
		fprintf(stderr, "pwrite64: count > SSIZE_MAX");
		abort();
	}
	return pwrite64(fd, buf, count, offset);
}

ssize_t bionic___pread_chk(int fd, void *buf, size_t count, off_t offset, size_t buf_size)
{
	if (__builtin_expect(count > buf_size, 0)) {
		fprintf(stderr, "pread: prevented write past end of buffer");
		abort();
	}
	return pread(fd, buf, count, offset);
}

ssize_t bionic___pread64_chk(int fd, void *buf, size_t count, off64_t offset, size_t buf_size)
{
	if (__builtin_expect(count > buf_size, 0)) {
		fprintf(stderr, "pread64: prevented write past end of buffer");
		abort();
	}
	return pread64(fd, buf, count, offset);
}
```

The `pread` pair isn't strictly required: glibc exports `__pread_chk` and `__pread64_chk` with compatible arguments on 64-bit. Defining them in bionic_translation keeps the behaviour consistent, and on 32-bit targets bionic's `off_t` is 32 bits while glibc's isn't.

Add `#define _LARGEFILE64_SOURCE` (or check that the file already gets it from the build) so `off64_t`, `pread64` and `pwrite64` are declared.

### Find the rest at once

bionic has more `_chk` entry points than bionic_translation implements, including `__sendto_chk`, `__recvfrom_chk`, `__readlink_chk`, `__getcwd_chk`, `__poll_chk`, `__ppoll_chk`, `__FD_SET_chk`, `__FD_ISSET_chk`, `__FD_CLR_chk`, `__strlcpy_chk` and `__strlcat_chk`. Before rebuilding, list what a given app needs:

```bash
unzip -q -o app.apk 'lib/x86_64/*' -d /tmp/apklibs
for so in /tmp/apklibs/lib/x86_64/*.so; do
  readelf --dyn-syms -W "$so" | awk '$7=="UND"{print $8}' | grep '_chk$'
done | sort -u
```

Any name in that list without a `bionic_` version in `libc-chk.c` and without a glibc export will fail the same way.

## What to expect after the fix

`libtorrent4j.so` should load and LibreTorrent's main screen should appear. Downloads need ordinary sockets and file I/O, which ATL passes to the host, so basic torrenting has a realistic chance of working. The Android foreground service and notifications are likely to be partial.
