## Short answer

These two exports don't describe a runtime failure. Both have the same sequence (the real ATL failures are the separate LibreTorrent and PUBG MOBILE `debug` exports):

1. The app failed in ATL, and the user clicked **Save debug JSON**.
2. The user **cancelled** the file chooser.
3. GTK 4's `Gtk.FileDialog` reports a cancel as **`Gtk.DialogError.DISMISSED`** ("Dismissed by user"), not `IOError.CANCELLED`. ApkManager only ignores `IOError.CANCELLED`, so it treated the cancel as an error and called `show_run_error()`.
4. That opened a **"Could not run with Android Translation Layer"** dialog with the message "Dismissed by user". Its **Export** button saved it as an `error` JSON.

---

## What the error is

```json
"error": {
  "title": "Could not run with Android Translation Layer",
  "message": "Dismissed by user"
}
```

"Dismissed by user" is GTK's message for `GTK_DIALOG_ERROR_DISMISSED`, which `gtk_file_dialog_save_finish()` returns when the chooser is closed without picking a file.

## Why it happens

```vala
// src/windows/main_window.vala — save_debug_json()
} catch (Error e) {
    if (!closed && !(e is IOError.CANCELLED)) {
        show_run_error(engine, debug_apk_path, e.message);   // runs for DISMISSED
    }
}
```

The GTK 4 VAPI has a separate error domain for dialogs:

```vala
// gtk4.vapi
[CCode (cheader_filename = "gtk/gtk.h", cprefix = "GTK_DIALOG_ERROR_")]
public errordomain DialogError {
    FAILED,
    CANCELLED,   // the app cancelled the dialog through its GCancellable
    DISMISSED;   // the user closed it
}
```

`IOError.CANCELLED` is GIO's error for a cancelled `GCancellable`. `Gtk.FileDialog` uses `DialogError` instead, so neither of ApkManager's checks ever matches a user cancel. The comment on `ErrorExport.save()` records the wrong assumption.

The same mistake affects all three places that call `ErrorExport.save()`:

| Where | What the user sees after cancelling |
|------|------|
| `main_window.vala` `save_debug_json()` | A "Could not run with …" dialog (the case in these exports) |
| `main_window.vala` `export_run_error()` | Status bar: "Could not export the error: Dismissed by user" |
| `open_window.vala` `export_run_error()` | Toast: "Could not export the error: Dismissed by user" |

---

## Suggested fix (ApkManager)

The runtime wasn't involved, so the fix goes in ApkManager. Add one helper to `ErrorExport` and use it at all three call sites.

`src/utils/error_export.vala`:

```vala
        // Gtk.FileDialog reports a user cancel as DialogError.DISMISSED.
        public static bool is_cancel(Error e) {
            return e is Gtk.DialogError.DISMISSED
                || e is Gtk.DialogError.CANCELLED
                || e is IOError.CANCELLED;
        }

        // Throws Gtk.DialogError.DISMISSED when the user closes the file chooser.
        public static async void save(Gtk.Window parent, string title, string filename, string json) throws Error {
```

`src/windows/main_window.vala`, in `save_debug_json()`:

```vala
            } catch (Error e) {
                if (!closed && !ErrorExport.is_cancel(e)) {
                    show_run_error(engine, debug_apk_path, e.message);
                }
            }
```

`src/windows/main_window.vala`, in `export_run_error()`:

```vala
            } catch (Error e) {
                if (!closed && !ErrorExport.is_cancel(e)) {
                    status_label.set_text("Could not export the error: %s".printf(e.message));
                }
            }
```

`src/windows/open_window.vala`, in `export_run_error()`:

```vala
            } catch (Error e) {
                if (!closed && !ErrorExport.is_cancel(e)) {
                    toast_overlay.add_toast(new Adw.Toast("Could not export the error: %s".printf(e.message)));
                }
            }
```

Leave `runtime_runner.vala` line 288 alone: it checks a `GCancellable` from ApkManager's own process handling, where `IOError.CANCELLED` is correct.

### A related improvement

`save_debug_json()` reports a *save* failure (disk full, no permission) through `show_run_error()`, titled "Could not run with …". Even after the fix above, a real save failure would be labelled as a runtime failure. Using the status label, as `export_run_error()` does, keeps runtime errors and ApkManager's own errors separate:

```vala
                if (!closed && !ErrorExport.is_cancel(e)) {
                    status_label.set_text("Could not save the debug JSON: %s".printf(e.message));
                }
```

## What to expect after the fix

Cancelling **Save debug JSON** or **Export error** does nothing, which matches GNOME convention for a cancelled save. "Dismissed by user" exports stop appearing in `00.references/errors`.
