## Short answer

This isn't a network problem. The message is **Cordova's own load timeout** (error code −6), shown when the start page doesn't finish loading within 20 seconds. That happens for two reasons:

1. **The WebView is off.** ATL builds a real WebKitGTK view only when `ATL_UGLY_ENABLE_WEBVIEW` is set. Without it, `loadUrl()` does nothing, so no page ever loads.
2. **With the WebView on, Cordova blocks its own start page.** ATL rewrites `file:///android_asset/www/index.html` to `android-asset:///assets/www/index.html` for WebKitGTK, but then asks the app whether to allow navigation to the *rewritten* URL. Cordova only allows `file://` URLs (plus its allow-list), so it refuses the navigation and the timeout fires anyway.

Both were confirmed by rerunning the APK with timestamps (below).

## Why it happens

```c
// ATL android_webkit_WebView.c
JNIEXPORT void JNICALL Java_android_webkit_WebView_native_1loadUrl(...)
{
	if (!getenv("ATL_UGLY_ENABLE_WEBVIEW"))
		return;                       /* (1) nothing loads by default */
	webkit_web_view_load_uri(webview, _CSTRING(url));
}

static gboolean decide_policy(WebKitWebView *web_view, WebKitPolicyDecision *decision, ...)
{
	...
	const gchar *uri = webkit_uri_request_get_uri(request);   /* "android-asset:///assets/www/index.html" */
	jboolean result = J__WebView__internalShouldOverrideUrlLoading(env, wrapper->jobj, _JSTRING(uri));
	if (result)
		webkit_policy_decision_ignore(decision);           /* (2) Cordova says "block" */
	...
}
```

```java
// ATL WebView.java
public void loadUrl(String url) {
	...
	// webkit doesn't allow overwriting the file:// uri scheme. So we replace it with the android-asset:// scheme
	url = url.replace("file:///android_asset/", "android-asset:///assets/");
	native_loadUrl(widget, url);
}
```

The rewrite is needed, because WebKitGTK won't let ATL take over `file://`. But the app should never see the rewritten URL. On Android, `shouldOverrideUrlLoading`, `onPageStarted` and `onPageFinished` all receive `file:///android_asset/...`. Cordova's `SystemWebViewClient.shouldOverrideUrlLoading` → `CordovaWebViewImpl` → `PluginManager.shouldAllowNavigation()` allows `file://` by default and rejects the unknown `android-asset:` scheme.

## Suggested fixes in the runtime (ATL)

### 1. Translate URLs back before calling the app

`src/api-impl/android/webkit/WebView.java`:

```java
	private static final String ATL_ASSET_PREFIX = "android-asset:///assets/";
	private static final String ANDROID_ASSET_PREFIX = "file:///android_asset/";

	private static String toAppUrl(String url) {
		if (url != null && url.startsWith(ATL_ASSET_PREFIX))
			return ANDROID_ASSET_PREFIX + url.substring(ATL_ASSET_PREFIX.length());
		return url;
	}

	@Export
	void internalLoadChanged(int loadState, String url) {
		url = toAppUrl(url);
		if (loadState == /*WEBKIT_LOAD_STARTED*/ 0 && webViewClient != null) {
			webViewClient.onPageStarted(this, url);
		} else if (loadState == /*WEBKIT_LOAD_FINISHED*/ 3 && webViewClient != null) {
			webViewClient.onPageFinished(this, url);
		}
	}

	@Export
	boolean internalShouldOverrideUrlLoading(String url) {
		url = toAppUrl(url);
		// Android doesn't consult the client for loads the app itself started with loadUrl()
		if (url.equals(pendingLoadUrl)) {
			pendingLoadUrl = null;
			return false;
		}
		if (webViewClient != null)
			return webViewClient.shouldOverrideUrlLoading(this, url);
		return false;
	}

	private String pendingLoadUrl;

	public void loadUrl(String url) {
		if (url.startsWith("javascript:")) {
			System.out.println("loadUrl: " + url + " - not implemented yet");
			return;
		}
		pendingLoadUrl = url;
		url = url.replace(ANDROID_ASSET_PREFIX, ATL_ASSET_PREFIX);
		native_loadUrl(widget, url);
	}
```

ATL's `WebView` has no `getUrl()` yet. When one is added, it should go through `toAppUrl()` as well.

The `pendingLoadUrl` check matches Android: `shouldOverrideUrlLoading` is only called for navigations the *page* starts (link clicks, redirects), not for the app's own `loadUrl()`. Cordova depends on that.

### 2. Let ApkManager turn the WebView on for web-wrapper apps

The WebView is off by default for a good reason (performance, ad and fingerprinting junk), so ApkManager could enable it only where the WebView is the app. `assets/www/` with `org/apache/cordova/` classes means Cordova; `assets/public/` with `com/getcapacitor/` means Capacitor. When either is found, add `ATL_UGLY_ENABLE_WEBVIEW=1` to the environment in `RuntimeRunner` (normal run and debug).

### 3. Two smaller gaps Cordova will hit next

- **`loadUrl("javascript:…")`** is "not implemented yet" in ATL. Cordova's bridge uses it to send results from Java to JavaScript. Implement it with `webkit_web_view_evaluate_javascript()`.
- **`addJavascriptInterface()`** is a stub except for one OctoDroid hack. Cordova's `exec()` bridge calls Java through `_cordovaNative`. WebKitGTK has no direct equivalent; the usual approach is a `WebKitUserContentManager` script message handler plus a small injected script that defines `window._cordovaNative.exec(...)` and posts to it.

Without those two, the page would display but Cordova plugins (and so most of SureSupply's features) wouldn't respond.
