## Short answer

1. **VLC thinks this PC is a TV.** At start-up it asks `hasSystemFeature("android.hardware.touchscreen")`. ATL doesn't recognize that feature and answers `false`, so VLC concludes "no touchscreen, not a Chromebook, therefore a TV" and starts `MainTvActivity`, its Android TV (Leanback) interface, instead of the phone and tablet interface.
2. **The TV interface crashes while inflating.** Leanback's `SearchOrbView` constructor calls `setSoundEffectsEnabled(false)`, a basic `View` method since API 1 that ATL doesn't have. The layout fails to inflate and `MainTvActivity.onCreate` dies.

This run didn't abort through CheckJNI: the activity failed and ATL exited with status 0.

## Suggested fixes in the runtime (ATL)

### 1. Report touch input

ATL turns mouse input into touch events (and passes real touchscreens through), so it should advertise touch. `src/api-impl/android/content/pm/PackageManager.java`:

```java
	public boolean hasSystemFeature(String name) {
		switch (name) {
			case FEATURE_TOUCHSCREEN:                       // "android.hardware.touchscreen"
			case FEATURE_FAKETOUCH:                         // "android.hardware.faketouch"
			case "android.hardware.touchscreen.multitouch":
			case "android.hardware.touchscreen.multitouch.distinct":
				return System.getenv("ATL_IS_TELEVISION") == null;
			case FEATURE_PICTURE_IN_PICTURE:               // "android.software.picture_in_picture"
				return false;
			case FEATURE_AUTOMOTIVE:
				return System.getenv("ATL_IS_AUTOMOTIVE") != null;
			case FEATURE_LEANBACK:
			case FEATURE_TELEVISION:
				return System.getenv("ATL_IS_TELEVISION") != null;
			case FEATURE_WATCH:
				return System.getenv("ATL_IS_WATCH") != null;
			default:
				Slog.e(TAG, "!!!!!!! hasSystemFeature: case >" + name + "< is not implemented yet");
				return false;
		}
	}
```

Tying touch to "not a TV" keeps `ATL_IS_TELEVISION=1` meaningful for anyone who wants the TV interface. Many other apps (games, media players) use the same touchscreen check, so this fix helps beyond VLC.

### 2. Add `setSoundEffectsEnabled` (and its getter)

`src/api-impl/android/view/View.java`, next to `setHapticFeedbackEnabled`:

```java
	private boolean soundEffectsEnabled = true;

	public void setSoundEffectsEnabled(boolean soundEffectsEnabled) {
		this.soundEffectsEnabled = soundEffectsEnabled;
	}

	public boolean isSoundEffectsEnabled() {
		return soundEffectsEnabled;
	}

	public boolean playSoundEffect(int soundConstant) {
		return false;    // ATL plays no UI click sounds
	}
```

Fix 1 alone should send VLC to its normal interface. Fix 2 matters for any Leanback (TV-style) app and for apps that turn off click sounds on custom views.
