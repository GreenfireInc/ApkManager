## Short answer

The install itself **succeeded**. "Done." and the zero exit status mean every step worked, and Lepton is installed in `~/.local/share/Steam/compatibilitytools.d/lepton-x86_64/`.

The message is a warning from the last step. **Lepton won't be able to start Android until binderfs is available.** The kernel already supports it; it is built as a **module that isn't loaded**. The message's suggestion that the kernel needs rebuilding with `CONFIG_ANDROID_BINDERFS` doesn't apply here.

---

## What binder and binderfs are

- **Binder** is Android's core inter-process communication system. Almost everything in Android talks through it: apps to system services, SurfaceFlinger (the display server), the package manager and so on. Without binder, Android doesn't get past early boot.
- Binder is provided by the **Linux kernel**, not by Android's userspace. A container like Lepton (or Waydroid) shares the host's kernel, so the host has to provide it.
- **binderfs** is a small filesystem (type `binder`) that hands out binder device nodes on demand. Lepton's Android mounts its own binderfs inside its Podman container:

  ```text
  # Android mounts its own binderfs inside the container and the device nodes
  # it creates there are not in podman's device list.
  ```

  (from `liblepton/mounting.sh`)

  That mount only works if the host kernel has the `binder` filesystem type registered.

---

## How `setup-host.sh` checks

```bash
grep -qw binder /proc/filesystems && echo "  binderfs: ok" \
    || echo "  binderfs MISSING -- the kernel needs CONFIG_ANDROID_BINDERFS" >&2
```

`/proc/filesystems` lists only filesystem types the running kernel has **right now**: built-in ones, plus modules that are currently loaded. A filesystem that exists as an unloaded module isn't listed. The script can't tell "not supported" apart from "not loaded", and the message assumes the former. It is only a warning; the script still ends with "Done".

## What this machine actually has

| Check | Result | Meaning |
|-------|--------|---------|
| `grep BINDER /boot/config-6.8.0-48-generic` | `CONFIG_ANDROID_BINDER_IPC=m`, `CONFIG_ANDROID_BINDERFS=m` | Binder and binderfs are both enabled, as a **module** (`m`), not built in (`y`) |
| `modinfo binder_linux` | `/lib/modules/6.8.0-48-generic/kernel/drivers/android/binder_linux.ko.zst` | The module is installed (from `linux-modules-extra-6.8.0-48-generic`, which is installed) |
| `lsmod \| grep binder` | nothing | **The module isn't loaded** |
| `grep binder /proc/filesystems` | nothing | So the `binder` filesystem type isn't registered, and the check fails |
| `ls /dev/binder*` | none | No binder devices either |

Ubuntu, and Linux Mint on top of it, ship binder as `binder_linux` and don't load it at boot. Fedora and Arch build binderfs into the kernel (`=y`), which is why the lepton-x86 README calls it "standard on Fedora and Arch". The message is written with those distributions in mind.

Rootless Podman, which Lepton uses, cannot load kernel modules itself, so nothing will load `binder_linux` automatically when Lepton starts.

## What to do

Load the module now, and have it load at every boot (both need your password):

```bash
sudo modprobe binder_linux
echo binder_linux | sudo tee /etc/modules-load.d/binder.conf
```

Then confirm:

```bash
grep -w binder /proc/filesystems      # expect: nodev	binder
~/.local/share/Steam/compatibilitytools.d/lepton-x86_64/setup-host.sh   # expect: binderfs: ok
```

Re-running `setup-host.sh` is optional. Lepton only needs the module loaded, but the re-run gives you the "ok" confirmation.

### Notes

- **Don't pass `devices=` to the module.** Older Anbox and Waydroid guides used `modprobe binder_linux devices="binder,hwbinder,vndbinder"` to create fixed `/dev/binder*` nodes. Lepton mounts binderfs and creates its own devices, so plain `modprobe binder_linux` is what it expects. Waydroid on this kernel also works with binderfs.
- **Kernel updates:** the module comes from `linux-modules-extra-<version>`, which Ubuntu/Mint installs alongside each `generic` kernel. If `modprobe` ever says "Module binder_linux not found" after a kernel update, install `linux-modules-extra-$(uname -r)`.
- **Secure Boot:** `binder_linux` is signed by Canonical like the rest of the kernel's modules, so it loads with Secure Boot on.

## Remaining requirements after binderfs

Loading the module clears this warning. Lepton on x86_64 still needs:

| Requirement | State on this machine |
|-------------|----------------------|
| Steam installed and run once | `~/.local/share/Steam` didn't exist before the install; start Steam, then **restart** it so it picks up "Lepton (x86_64)" |
| AMD GPU | Met: AMD Radeon RX 580 (Polaris 20), which uses radeonsi. The x86_64 port currently renders on AMD only |
| Wayland session | **Not met right now:** the current session is X11 (Cinnamon). Lepton's 2D window needs Wayland: log in to Cinnamon's Wayland session, or run a nested compositor such as Weston (`sudo apt install weston`) |

Then add the `.apk` in Steam with *Games → Add a Non-Steam Game* (set the file filter to "All Files"), and under *Properties → Compatibility* choose **Lepton (x86_64)**.

## ApkManager follow-up (done, November 21, 2026)

The Lepton guide in `runtime_install_dialog.vala` now loads the module itself on Debian and Ubuntu / Linux Mint (`LEPTON_BINDER_STEPS`), before `setup-host.sh` runs its kernel check:

```bash
grep -qw binder /proc/filesystems || sudo modprobe binder_linux
echo binder_linux | sudo tee /etc/modules-load.d/binder.conf
```

The Fedora row is unchanged, since Fedora builds binderfs into the kernel. The Waydroid guide doesn't include this step.
