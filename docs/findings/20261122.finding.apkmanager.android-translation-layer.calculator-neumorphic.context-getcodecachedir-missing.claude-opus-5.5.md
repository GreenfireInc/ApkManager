## Short answer

Flutter's loader (`FlutterLoader`, shown obfuscated as `p.d`) asks for the app's code-cache directory on a background thread while starting the engine. Android has had `Context.getCodeCacheDir()` since API 21. ATL's `Context` doesn't have it, so the background task fails with `NoSuchMethodError`. Flutter then rethrows the failure on the main thread inside `FlutterActivity.onCreate`, and the CheckJNI abort follows.

## Why it happens

`FlutterLoader.startInitialization` runs an initialization `Callable` on an executor. It calls `PathUtils.getCacheDirectory(context)` and similar helpers, which use `context.getCodeCacheDir()` on API 21+. `FlutterLoader.ensureInitializationComplete` later calls `future.get()` on the UI thread, which wraps the background `NoSuchMethodError` in `ExecutionException` and then `RuntimeException`.

ATL's `Context` already creates `files`, `cache` and `no_backup` directories under the app's data folder. `code_cache` is the only one missing.

## Suggested fix in the runtime (ATL)

`src/api-impl/android/content/Context.java`, next to `getNoBackupFilesDir()`. It follows the same pattern and adds a field like `nobackup_dir`:

```java
	private File code_cache_dir;

	public File getCodeCacheDir() {
		if (code_cache_dir == null) {
			code_cache_dir = new File(getDataDirFile(), "code_cache/" + getPackageName());
		}
		if (!code_cache_dir.exists()) {
			if (!code_cache_dir.mkdirs()) {
				if (code_cache_dir.exists()) {
					// spurious failure; probably racing with another process for this app
					return code_cache_dir;
				}
				Slog.w(TAG, "Unable to create code_cache directory >" + code_cache_dir.getPath() + "<");
				return null;
			}
		}
		return code_cache_dir;
	}
```

If ATL's `ContextWrapper` overrides directory getters individually, add the matching delegation there too:

```java
	@Override
	public File getCodeCacheDir() {
		return mBase.getCodeCacheDir();
	}
```

Other API 21+ `Context` directory getters that Flutter and AndroidX use, worth checking while you're there: `getDataDir()` (API 24), `getExternalFilesDirs(String)`, `getExternalMediaDirs()` and `getObbDir()`.
