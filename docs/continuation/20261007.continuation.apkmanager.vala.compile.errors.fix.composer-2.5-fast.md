## 1. Summary

The initial **Pass 1** Vala sources mixed **invalid syntax** (methods written like properties, C#-style `while` loops) with **APIs that do not match** Vala 0.56 + current GTK 4 / GIO / libarchive VAPIs on Fedora 40+. Meson and dependencies were fine; **`valac` failed** during the first compile.

Those issues are **fixed in the repository**. After pulling or syncing these changes, rebuild with:

```bash
cd /home/corey/Workspace/Applications/ApkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Compile may emit **deprecation warnings** for `Gtk.TreeView` / `Gtk.ListStore` (deprecated GTK 4.10+); they do not block the build.

## 2. Errors reported first (root cause)

### 2.1 `app_paths.vala` — property syntax on methods

**Symptom:**

```text
../src/core/app_paths.vala:64: error: syntax error, expected identifier
            owned get {
```

**Cause:** `decoded_dir_for_key()` and `partial_decode_dir()` were written with **`owned get { ... }` blocks**, which is **property** syntax in Vala, not a method body. Only the static properties above them correctly use `owned get`.

**Fix:** Use normal method bodies:

```vala
public static string decoded_dir_for_key(string cache_key) {
    return Path.build_filename(decoded_root, cache_key);
}

public static string partial_decode_dir(string cache_key) {
    return "%s.partial-%d".printf(decoded_dir_for_key(cache_key), Posix.getpid());
}
```

**File:** `src/core/app_paths.vala`

---

### 2.2 `main_window.vala` — invalid `while (var …)` loop

**Symptom:**

```text
../src/windows/main_window.vala:205: error: syntax error … `while (var child = …)`
```

**Cause:** Vala does **not** support C#-style assignment inside `while (...)`. The compiler stops parsing and reports cascading syntax errors.

**Fix:** Explicit nullable widget and re-fetch first child after each remove:

```vala
Gtk.Widget? child = session_list.get_first_child();
while (child != null) {
    session_list.remove(child);
    child = session_list.get_first_child();
}
```

**File:** `src/windows/main_window.vala` (`refresh_sessions`)

## 3. Additional errors uncovered after syntax fix

Once the first errors were fixed, `valac` continued and reported **API mismatches** typical of scaffold code written against older docs or other languages. All were corrected so the project links on Fedora.

| Area | Problem | Fix |
|------|---------|-----|
| `decode_session_registry.vala` | `Object` ambiguous with `using Json` | Base class `GLib.Object`; `GLib.Path.get_basename` |
| `main_window.vala` | `Adw.ProgressBar` does not exist | `Gtk.ProgressBar` |
| `main_window.vala` | `NavigationSplitView.sidebar` / `.content` need `Adw.NavigationPage` | Wrap widgets: `new Adw.NavigationPage(sidebar_box, "Sessions")` |
| `main_window.vala` | `Gtk.ListStore(typeof(...), …)` | `new Gtk.ListStore.newv({ typeof(string), … })` |
| `main_window.vala` | `FileFilter.set_name` | `set_filter_name` (GTK 4 rename) |
| `application.vala` | `command_line(string[])` override | `command_line(ApplicationCommandLine)` + CLI APK handling |
| `apk_archive.vala` | Wrong libarchive API (`Read.new`, fields vs methods) | `new Archive.Read()`, `pathname()`, `size()`, `FileType.IFDIR`, `unowned Entry`, `close()` |
| `apk_archive.vala` | `Checksum.update` slice | `checksum.update(buffer, bytes_read)` |
| `apktool_runner.vala` | Removed GIO APIs (`set_line_funcs`, `wait_async(…, out status)`, `check_exit_status`) | Async `read_line_utf8_async` loop + `wait_check_async` |
| `file_utils.vala` | `%d` with `int64` | `%lld` for byte counts |
