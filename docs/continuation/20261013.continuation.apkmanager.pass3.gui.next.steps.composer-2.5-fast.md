## 1. Executive summary

**You can run the GUI today.** On the developer host (October 13, 2026): Vala 0.56.16, OpenJDK 21, Meson/Ninja, GTK 4 + Libadwaita are present; `meson compile -C build` succeeds; `~/.local/bin/apk-manager` launches.

Since the October 7 continuation, **Pass 3** added substantial UX: **Get APKs** (multi-store search/download), **Preferences**, **Open APK** install flow (drag-drop, confirmation, verify SHA256), **grid/list session views**, **Files / Properties tabs**, decode controls on Properties, sidebar search, install-folder scanning, and many bug fixes documented under `docs/errorsSolutions/` (Oct 8–11).

**What still does not match the unified methodology vision:** after **Full Decode**, the **Files** tab still lists **raw ZIP entries** from the APK — not the decoded folder under `~/.cache/apk-manager/decoded/`. There is no **GtkSourceView** window for manifest/smali/XML, no hex/image viewers for decoded assets, and no **framework install** UI (`apktool if` / `lf` / `cf`). Several preference keys exist in GSettings but are not fully wired (file-manager icons, runtime engine, update checks).

**Immediate next step for users:** rebuild/install and smoke-test (§4). **Next engineering milestone:** show the **decoded tree** after Full Decode and open selected files in read-only viewers (Phases 3–4 closure).

If `valac` or dev libraries are missing on a **new** machine, use the package lists in [requirements §3](../requirements/20261007.requirements.apkmanager.build.environment.debian.fedora.composer-2.5-fast.md).

### 4.2 Build, install, run

```bash
cd ~/Workspace/Applications/apkManager
chmod +x scripts/fetch-apktool.sh
meson setup build --prefix="$HOME/.local"    # once
meson compile -C build
meson install -C build
update-desktop-database ~/.local/share/applications
glib-compile-schemas ~/.local/share/glib-2.0/schemas
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

**Important:** Quit any running `apk-manager` before reinstalling, or rely on `Application.retire_stale_instance()` so the new binary is picked up.

### 4.3 Smoke test (current behavior)

1. **Open APK** — pick or drop an `.apk`; raw entries appear under **Files**.
2. **Quick Manifest** (Properties tab) — fills **Properties** with package, SDK, permissions; switches to that tab.
3. **Full Decode** — progress in footer; cache under `~/.cache/apk-manager/decoded/<key>/`; **Files tab still shows raw ZIP** (known gap).
4. **Get APKs** — search, confirm download, install to `~/Applications/android` (or Preferences path).
5. **Properties → File** — file manager opens with APK selected (Nemo/Nautilus via D-Bus).

## 5. Recommended next steps (engineering priority)

### 5.1 Critical — decoded browsing (Phases 3–4 core)

This is the largest gap versus the unified methodology and the Oct 7 continuation promise (“see decoded tree after Full Decode”).

| Task | Rationale |
|------|-----------|
| After `DecodeState.DECODED`, populate **Files** (or a third tab) from `session.cache_dir` | Users cannot inspect smali, `res/`, or decoded manifest in-app today |
| Tree selection → read-only **GtkSourceView** for `.xml`, `.yml`, `.smali` | Phase 4 exit criterion |
| **Gtk.Picture** (or existing icon loader) for drawables under `res/` | Phase 4 |
| Toggle or auto-switch: raw ZIP vs decoded tree when cache valid | Clear UX when both views exist |

Suggested approach: filesystem walk of `cache_dir` into a `Gtk.TreeView` or `Gtk.ColumnView` model; reuse `ApkArchive` path safety rules for traversal.

### 5.2 High — framework and decode errors (Phase 3)

| Task | Notes |
|------|-------|
| Preferences page: **Install framework…** (`apktool if`), list, clear | Paths exist in `AppPaths.frameworks_dir`; runner already passes `-p` |
| Banner when decode fails with framework-not-found | Map Apktool stderr to actionable UI (methodology §5 / consolidated quick reference) |
| Parse `java -version` and require ≥ 17 | Phase 2 exit criterion still open |

### 5.3 Medium — preferences wiring
