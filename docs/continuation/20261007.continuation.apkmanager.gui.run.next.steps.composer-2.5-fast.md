## 1. Executive summary

ApkManager **Pass 1** delivered a Meson/Vala GTK 4 + Libadwaita skeleton: open/drop flow, raw APK listing via libarchive, Apktool subprocess integration with progress phases and cancel, session JSON registry, and desktop/AppStream/GSettings metadata. That matches **much of Phase 1** and **part of Phase 2** in the unified methodology.

**What you cannot do yet without a successful build:** launch `apk-manager` on this machine. **What the GUI will not do yet even after a successful build:** browse decoded output in the tree (the main pane still lists **raw ZIP entries only** after decode), show an info/metadata window, or open manifest/smali in GtkSourceView.

The **immediate next step** is environmental: install the Vala compiler and GTK/dev libraries, then compile and install. The **next engineering step** after the GUI runs is to finish Phase 2 hardening, then Phase 3 (metadata + decoded cache UX) so decode results are visible and reusable.

## 4. Step-by-step: first successful GUI run

Run from the project root:

```bash
cd /home/corey/Workspace/Applications/ApkManager
chmod +x scripts/fetch-apktool.sh
rm -rf build   # only if a prior failed setup left a broken build dir
meson setup build --prefix=$HOME/.local
meson compile -C build
meson install -C build
```

Post-install (required for MIME/desktop integration):

```bash
update-desktop-database ~/.local/share/applications
glib-compile-schemas ~/.local/share/glib-2.0/schemas
gtk-update-icon-cache ~/.local/share/icons/hicolor
export PATH="$HOME/.local/bin:$PATH"
```

**Smoke test:**

```bash
apk-manager --version
apk-manager
apk-manager /path/to/sample.apk
```

**Expected behavior today (Pass 1):**

1. App window opens with session sidebar and raw archive table for the selected APK.
2. **Quick Manifest** / **Full Decode** invoke Apktool when Java and the installed `apktool.jar` are available; status line and progress pulse update from runner telemetry.
3. After a successful decode, cache lands under `~/.cache/apk-manager/decoded/<cache-key>/` (after rename from `.partial-<pid>`), but the **main tree still shows raw ZIP entries** — not the decoded folder. That is the first functional gap to close after “it runs.”

Full checklist: [requirements §5](../requirements/20261007.requirements.apkmanager.build.environment.debian.fedora.composer-2.5-fast.md).

## 5. Recommended order of work after the GUI launches

### 5.1 Close Phase 2 (Apktool integration)

| Task | Priority | Rationale |
|------|----------|-----------|
| Parse `java -version` and reject JRE &lt; 17 | High | Methodology exit criterion; today only `java` on PATH is checked |
| On cancel/failure, ensure partial dir removal and UI state reset | Medium | Partial cleanup exists on failure path; audit cancel + `on_decode_finished` for race with rename |
| Surface decoded output in UI | **Critical** | Without this, decode success is invisible except status text and disk cache |
| Optional: reload tree from `session.cache_dir` after decode | **Critical** | Second half of “decode & browse” promise |

Suggested implementation sketch (align with AppManager main window patterns):

- After `DecodeState.DECODED`, populate a second model or replace `archive_store` with a filesystem tree walk of `session.cache_dir`.
- Wire session selection to prefer decoded tree when `cache_dir` exists and is valid for current `cache_key`.

### 5.2 Phase 3 (metadata and sessions)

| Task | Notes |
|------|-------|
| `ApkInfoWindow` with `Adw.PreferencesGroup` | Parse `AndroidManifest.xml` / `apktool.yml` from cache |
| Cache invalidation | Hash + Apktool version + decode mode (see unified §5.3) |
| Framework dir UI | `apktool if` / list / clear — paths already in `AppPaths` |

### 5.3 Phase 4 (viewers)

| Task | Notes |
|------|-------|
| GtkSourceView window | Read-only XML/YAML/smali from decoded tree selection |
| `Gtk.Picture` for drawables | PNG/JPEG/WebP under `res/` |
| Search/filter on decoded tree | Quality-of-life after tree exists |

### 5.4 Phase 5 (packaging)

Ship `.deb`, `.rpm`, and Flatpak per unified plan; AppStream legal bundle already started in `data/com.github.ApkManager.metainfo.xml`.

### 5.5 Quality

- Meson compile on CI or documented matrix (Debian 13 + Fedora 40+).
- Integration test: subprocess decode of a tiny fixture APK (optional but valuable).
