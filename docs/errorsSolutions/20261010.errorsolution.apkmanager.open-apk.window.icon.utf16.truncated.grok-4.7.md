## 1. What you see

Opening an APK (file manager or `apk-manager /path/to/app.apk`) shows the Install APK window: filename, archive summary, file size, and **Inspect APK**. The space at the top stays the generic Android package symbol. The app’s own logo is not drawn.

There is no error dialog. **Verify** and **Inspect APK** still work.

---

## 2. What that means

The window asks `UiUtils.load_session_apk_icon()` for the logo. That helper needs the `android:icon` resource id from `AndroidManifest.xml`, then the matching image inside the APK.

`AndroidManifest.xml` inside an APK is Android binary XML. Its string pool is usually UTF-16. Each character is a 16-bit unit whose high byte is `0x00` for normal ASCII (`'a'` is the bytes `61 00`).

The readers in `apk_display_name.vala` and `apk_icon.vala` built that text with a Vala cast:

```vala
return ((string) chars).dup();
```

That cast treats the array as a C string and stops at the first `0x00` byte. A checked sample:

```text
uint16[] { 'm','a','n','i','f','e','s','t' }
casted len=1 value=[m]
```

So the element name `application` became `a`, and the attribute name `icon` became `i`. The comparison `pool[name_index] == "application"` never succeeded, `application_icon_ref()` returned null, and the window kept the generic symbol.

A decoded manifest cache could still supply the icon id after **Quick Manifest**, which is why some already-inspected APKs looked fine in the session list while a freshly opened APK did not.

After the string fix, the same files resolve and load:

```text
apk icon ref=@2131492864 bytes=3922 file=bitchat.apk
apk icon ref=@2131492864 bytes=7231 file=orion-store-1-5-0.apk
```

The Orion window then shows the app logo above the filename.

---

## 3. Fix applied

Both UTF-16 pool readers now append every code unit with `StringBuilder.append_unichar()`, including a surrogate pair when one is present. They no longer cast `uint16[]` to `string`.

`src/windows/open_window.vala` already displays that result through `UiUtils.load_session_apk_icon()` at 96px. With a real icon id, that image is the APK logo. The generic package symbol remains only when the APK has no readable icon.

---

## 4. What you should run

Quit ApkManager, then rebuild and start it again:

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager /path/to/app.apk
```

The Install APK window should show that app’s icon above the filename.
