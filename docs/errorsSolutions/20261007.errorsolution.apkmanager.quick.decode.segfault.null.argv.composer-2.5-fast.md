## 1. What the message means

`Segmentation fault (core dumped) apk-manager` means the **ApkManager process itself died**. The kernel sent signal 11 (`SIGSEGV`) because the program read or wrote memory it does not own. The shell then notes that systemd saved a core dump.

This is not an Apktool error and not a bad APK. Java never started. The crash is inside ApkManager, on the click that begins a decode.

| Piece | Meaning |
|-------|---------|
| Segmentation fault | Invalid memory access in `apk-manager` |
| core dumped | A snapshot was written under `/var/lib/systemd/coredump/` for debugging |
| When | Immediately on **Quick Manifest** (and the same bug on **Full Decode**), after the APK is already open |

Opening the file only lists ZIP entries. The crash is the next step, when `ApktoolRunner` tries to spawn `java`.

## 2. Where it crashed

`coredumpctl` backtrace for PID 135217, main thread:

```text
#0  __strlen_avx2
#1  g_strdup
#2  g_strdupv
#3  g_subprocess_set_property
#4  g_object_new_internal
#9  g_subprocess_newv
#10 apk_manager_core_apktool_runner_decode_async_co
        at src/core/apktool_runner.vala  (Subprocess.newv)
#14 apk_manager_windows_main_window_start_decode
        mode = MANIFEST_ONLY
```

`g_subprocess_newv()` copies its `argv` with `g_strdupv()`, which walks pointers until it finds a `NULL`. The pointer it was given did not end with `NULL`, so `strlen` ran off the end of the array and faulted.

The arguments at the crash were a real APK and a real output directory:

```text
apk_path   /home/corey/Downloads/F-Droid.apk
output_dir ~/.cache/apk-manager/decoded/<sha256>-manifest.partial-135217
mode       MANIFEST_ONLY
```

---

## 3. Why the argv was not terminated

`g_subprocess_newv()` is bound in Vala as a **NULL-terminated** `string[]` (`array_null_terminated = true`, `array_length = false`). The runner built that list with Gee and then converted it:

```vala
var args = new Gee.ArrayList<string>();
args.add("java");
// ...
var argv = args.to_array();
current_proc = new Subprocess.newv(argv, ...);
```

`Gee.Collection.to_array()` (`gee_collection_to_array`) allocates exactly `size` pointers and returns the length separately. It does **not** write a trailing `NULL`. Valac passed that pointer straight through:

```c
argv = gee_collection_to_array(args, &argv_length1);
g_subprocess_newv(argv, G_SUBPROCESS_FLAGS_STDOUT_PIPE | G_SUBPROCESS_FLAGS_STDERR_MERGE, &error);
```

A Vala `string[]` written in the language (`new string[] { ... }` and `+=`) is different: valac allocates `n + 1` slots with `g_new0` and each `+=` sets `array[length] = NULL`. That is what `g_strdupv` requires.

## 4. Fix applied

### 4.1 NULL-terminated argv (`src/core/apktool_runner.vala`)

The Gee list is gone. The command is a Vala `string[]`:

```vala
var argv = new string[] {
    "java",
    "-Xmx%dM".printf(DEFAULT_JAVA_HEAP_MB),
    "-Dfile.encoding=utf-8",
    "-Djdk.util.zip.disableZip64ExtraFieldValidation=true",
    "-Djdk.nio.zipfs.allowDotZipEntry=true",
    "-jar",
    AppPaths.apktool_jar_path,
    "d", "-f", "-p",
    AppPaths.frameworks_dir
};
if (mode == DecodeMode.MANIFEST_ONLY) {
    argv += "-s";
    argv += "-r";
    argv += "--force-manifest";
}
argv += "-o";
argv += output_dir;
argv += apk_path;
```

Generated C for the initial array is `g_new0(gchar*, 11 + 1)`, and each `_vala_array_add` ends with `(*array)[*length] = NULL`.

### 4.2 Do not close Apktool’s stdout pipe

`get_stdout_pipe()` is unowned; the `Subprocess` owns that fd. `DataInputStream` defaults to closing its base stream on dispose, which would close the same fd again when the process object is freed. The wrapper now sets `stdout.close_base_stream = false`.

## 5. What you should run

The rebuilt binary is already installed. Quit any running ApkManager (a crashed one is already gone) and start it again:

```bash
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open the APK, then **Quick Manifest**. The process should stay up and Apktool should run. A successful quick pass writes under `~/.cache/apk-manager/decoded/<sha256>-manifest/`.

If you build yourself:

```bash
cd /home/corey/Workspace/Applications/ApkManager
meson compile -C build
meson install -C build
```
