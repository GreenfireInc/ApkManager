## 1. Summary

Compile succeeded, but **`meson install` crashed** while copying the bundled `apktool.jar`. The failure is **not** in ApkManager's code; it is Meson's installer post-processing every installed build-target output. Any such output whose name ends in **`.jar`** is assumed to be a Java target that Meson built, and Meson shells out to the JDK **`jar`** tool to rewrite its manifest. The host has only **headless JREs** (no JDK), so `jar` does not exist and the whole install aborts before `apk-manager` is copied to `~/.local/bin` — hence `apk-manager: command not found`.

**Fix (applied):** stop installing the JAR as a build-target output and copy it verbatim via a Meson **install script**, which bypasses the `.jar` post-processing entirely. A second latent bug surfaced during verification and was also fixed: the app searched for the JAR under `<prefix>/lib/apk-manager` with a hardcoded `/usr/local` prefix, but Fedora installs to **`lib64`** and the prefix is `~/.local`, so decode would have failed with “Apktool JAR not found.”

## 2. Root cause (detailed)

### 2.1 Meson's `fix_jar` post-install step

In `meson.build`, the JAR was produced by a `custom_target` with `install: true`:

```meson
apktool_jar = custom_target('apktool-jar',
  output: 'apktool.jar',
  command: ['sh', fetch_apktool_script, meson.current_build_dir()],
  install: true,
  install_dir: apktool_libdir
)
```

During `meson install`, `minstall.py::install_targets` calls `fix_rpath()` on **every** installed target output. In `depfixer.py`:

```python
def fix_rpath(fname, ...):
    ...
    if fname.endswith('.jar'):
        fix_jar(fname)
        return
    fix_elf(...)

def fix_jar(fname):
    subprocess.check_call(['jar', 'xf', fname, 'META-INF/MANIFEST.MF'])
    # strip "Class-Path:" lines, then:
    subprocess.check_call(['jar', 'ufM', fname, 'META-INF/MANIFEST.MF'])
```

This logic exists for JARs Meson compiled itself (`jar()` targets), to remove build-tree `Class-Path` entries. It cannot distinguish those from a **downloaded third-party JAR** that merely shares the extension.

Two problems follow:

| Problem | Effect |
|---------|--------|
| `jar` binary is part of the **JDK**, not the JRE | `java-25-openjdk-headless` / `java-latest-openjdk-headless` provide `java` but **not** `jar` → `FileNotFoundError` |
| `fix_jar` rewrites the manifest | Even with a JDK, Meson would **modify Apktool's pinned release artifact**, which we want to ship byte-for-byte |

### 2.2 Why `apk-manager: command not found`

The installer processes targets in order. It crashed on `apktool.jar` **before** reaching `src/apk-manager`, so nothing was copied to `~/.local/bin`. The `export PATH` line was correct; the binary simply was not there yet.

### 2.3 Latent follow-on bug: JAR lookup path

Meson's `libdir` is **`lib64`** on Fedora x86_64 (and `lib/<triplet>` on Debian multiarch), so the JAR lands at:

```text
~/.local/lib64/apk-manager/apktool.jar
```

`src/core/app_paths.vala` only probed `<prefix>/lib/apk-manager/`, and `get_install_prefix()` defaulted to `/usr/local` unless `APK_MANAGER_PREFIX` was exported. Result: the GUI would launch, but **Quick Manifest / Full Decode** would report `Apktool JAR not found at /usr/local/lib/apk-manager/apktool.jar`.

## 3. Fix applied

### 3.1 `meson.build` — install the JAR with a script, not as a target

```meson
apktool_jar = custom_target('apktool-jar',
  output: 'apktool.jar',
  build_by_default: true,
  command: ['sh', fetch_apktool_script, meson.current_build_dir()],
  install: false            # was: true
)

meson.add_install_script('scripts/install-apktool.sh',
  meson.current_build_dir() / 'apktool.jar',
  get_option('libdir') / 'apk-manager'
)
```

Install scripts run **after** target installation and are **not** passed through `fix_rpath`, so no `jar` tool is needed and the manifest is untouched. The custom target still downloads the JAR at **build** time as before.

### 3.2 New `scripts/install-apktool.sh`

Plain copy honoring `DESTDIR` via Meson's `MESON_INSTALL_DESTDIR_PREFIX`:

```bash
PREFIX="${MESON_INSTALL_DESTDIR_PREFIX:?...}"
DEST_DIR="${PREFIX}/${REL_DIR}"
mkdir -p "${DEST_DIR}"
install -m 0644 "${SRC}" "${DEST_DIR}/apktool.jar"
```

### 3.3 Bake the real JAR directory into the binary

`src/core/build_info.vala.in` now receives the configured install dir from Meson:

```vala
public const string APKTOOL_INSTALL_DIR = "@APKTOOL_LIBDIR@";
```

```meson
build_info_conf.set('APKTOOL_LIBDIR', apktool_libdir)   # <prefix>/<libdir>/apk-manager
```

### 3.4 Robust lookup in `src/core/app_paths.vala`

`apktool_jar_path` resolution order:

1. `APK_MANAGER_APKTOOL_JAR` env override (unchanged)
2. **`APKTOOL_INSTALL_DIR/apktool.jar`** — exact Meson-configured path
3. Relocated install: prefix derived from **`/proc/self/exe`** (`<prefix>/bin/apk-manager` → `<prefix>`), probing `lib64`, `lib`, `lib/x86_64-linux-gnu`, `lib/aarch64-linux-gnu`
4. Development fallback: `./build/apktool.jar`

`get_install_prefix()` no longer blindly returns `/usr/local`; it honors `APK_MANAGER_PREFIX`, then the running binary's location, then falls back.

## 5. What you should run now

```bash
cd /home/corey/Workspace/Applications/ApkManager
meson setup build --prefix=$HOME/.local --reconfigure
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager --version
apk-manager
```

`--reconfigure` is required once because `meson.build` changed (new install script, new `build_info` substitution). Add the `export PATH` line to `~/.bashrc` if `~/.local/bin` is not already on your `PATH`.

## 6. Alternatives considered

| Option | Verdict | Reason |
|--------|---------|--------|
| Install a JDK (`java-latest-openjdk-devel`) so `jar` exists | Rejected | Works around the symptom; Meson would still rewrite the pinned Apktool manifest; adds a heavy build dependency for a copy operation |
| Rename output to `apktool.jar.bin` and rename on install | Rejected | Obscure; `install_data(rename:)` cannot take a `custom_target` output |
| Download at configure time (`run_command`) + `install_data` | Rejected | Re-downloads on every reconfigure; network at configure instead of build |
| **`meson.add_install_script()` plain copy** | **Chosen** | Zero new deps, artifact copied verbatim, honors `DESTDIR` for `.deb`/`.rpm` packaging |
