## 1. What you see

The rebuild command from the README stops before anything compiles:

```text
$ meson compile -C build/meson && meson install -C build/meson

ERROR: Current directory is not a meson build directory: `/home/corey/Workspace/Applications/ApkManager/build/meson`.
Please specify a valid build dir or change the working directory to it.
It is also possible that the build directory was generated with an old
meson version. Please regenerate it in this case.
```

Because of `&&`, `meson install` never runs either.

---

## 2. What that means

`meson compile -C <dir>` and `meson install -C <dir>` do not create anything. They run inside a build directory that **`meson setup <dir>`** already created. Meson recognizes that directory by the files `setup` writes there, mainly `build.ninja` and `meson-private/`.

On this machine, **`build/meson` did not exist at all.** So Meson had no build directory to work in, and it printed this error. The line about “an old meson version” is a general hint Meson includes in the same message. It was not the cause here.

### Why the folder was missing

Since October 24 (see the related errorsSolutions doc), this project builds in **`build/meson`** for local development. That keeps `build/` free for packaging files (`build/debian/`, `build/snap/`, `build/meson-debian/`, `build/meson-appimage/`). The README and the requirements doc were updated to the new path.

Only the **“Rebuild and run”** line works on an existing tree. The README’s **“First-time setup”** block is what creates the tree (`meson setup build/meson --prefix=$HOME/.local`), and that step had not been run for `build/meson` here. Meanwhile, the **older top-level `build/` Meson tree** from October 7 was still configured, and builds kept going there. Earlier instructions in this chat (`meson compile -C build`) used that old tree. That is why everything appeared to work until you followed the README exactly.

Quick check:

| Path | Before the fix |
|------|----------------|
| `build/meson/` | Missing, which caused the error |
| `build/build.ninja`, `build/meson-private/` | Present (the old top-level tree, prefix `~/.local`) |
| `build/debian/`, `build/snap/` | Present (packaging metadata tracked in git) |

---

## 3. Fix applied

The README’s one-time setup step was run once:

```bash
cd ~/Workspace/Applications/ApkManager
meson setup build/meson --prefix="$HOME/.local"
```

Then the exact failing command was run again:

```bash
meson compile -C build/meson && meson install -C build/meson
```

Result:

```text
Compilation succeeded - 38 warning(s)
Installing apktool.jar to /home/corey/.local/lib64/apk-manager
Installing src/apk-manager to /home/corey/.local/bin
```

The 38 warnings are existing GTK deprecation notices (`Gtk.TreeView`, `Gtk.ListStore`, `Gtk.StyleContext`, and similar). They do not stop the build.

## 4. What you should run from now on

Every rebuild after this uses the README commands:

```bash
cd ~/Workspace/Applications/ApkManager
meson compile -C build/meson && meson install -C build/meson
apk-manager
```

Quit any running ApkManager window first. If an instance is already open, starting it again only brings that old window forward.

**Use only `build/meson`.** `meson compile -C build` still works, because the old top-level tree is still there. However, it installs from a different tree, so the two can get out of step.

### Optional: remove the old top-level Meson tree

This is not required. If you want only one dev tree, delete just the Meson files in `build/` and keep the packaging folders:

```bash
cd ~/Workspace/Applications/ApkManager
rm -rf build/build.ninja build/compile_commands.json build/meson-private build/meson-info \
       build/meson-logs build/src build/data build/.ninja_deps build/.ninja_log \
       build/build_info.vala build/apk-manager-resources.c build/apk-manager-resources.h \
       build/apktool.jar
```

**Do not** run `rm -rf build`. That would also delete `build/debian/` and `build/snap/`, which the deb and Snap package builds need.

### If `build/meson` is ever deleted

Run the setup step once more, then compile and install:

```bash
meson setup build/meson --prefix="$HOME/.local"
meson compile -C build/meson && meson install -C build/meson
```
