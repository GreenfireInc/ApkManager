## 1. What you see

There is no error dialog and no status-line failure. **Quick Manifest** still opens the metadata popup (package, version, SDK, permissions), but the space at the top where the APK icon should be is empty.

The icon bytes were already being found. For F-Droid the manifest icon `@2131623938` resolves to `res/o-.png`, a real PNG (`89 50 4E 47`, 6254 bytes). The widget then threw that image away.

---

## 2. What that means

`Gtk.Image` stores only one kind of content. These two lines ran in that order:

```vala
image.paintable = Gdk.Texture.from_bytes(icon);
image.icon_name = null;
```

The first line attaches the APK texture. The second does **not** mean “remove the fallback icon and keep the texture.” In GTK 4, `gtk_image_set_from_icon_name(image, NULL)` calls `gtk_image_clear()`. That drops the paintable as well.

Checked against the F-Droid PNG:

```text
after paintable set
after icon_name=null null
```

So a successful icon load produced a blank image. The fallback symbolic icon was also gone, because it was cleared in the same call. `pixel_size` only affects theme icons, not a `Gdk.Texture`, so it did not reserve a visible box after the clear.

---

## 3. Fix applied

`src/windows/manifest_popup.vala` now uses `Gtk.Picture` for the decoded icon and never assigns `icon_name` on that widget:

```vala
var picture = new Gtk.Picture.for_paintable(Gdk.Texture.from_bytes(icon));
picture.content_fit = Gtk.ContentFit.CONTAIN;
picture.width_request = 96;
picture.height_request = 96;
```

The picture stays at the top of the popup, 96×96, scaled to fit. The generic Android package symbol is used only when the APK has no readable icon.

---

## 4. What you should run

The rebuilt binary is installed. Quit ApkManager and start it again:

```bash
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open an APK and click **Quick Manifest**. The app icon should sit centered above the Application group.
