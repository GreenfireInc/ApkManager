## 1. What you see

Meson configure succeeds. Vala compilation may even proceed in parallel. The build stops on the first custom target:

```text
[1/19] Generating apktool-jar with a custom command
FAILED: apktool.jar
/usr/bin/sh ../scripts/fetch-apktool.sh /home/corey/Workspace/Applications/apkManager/build
../scripts/fetch-apktool.sh: 3: set: Illegal option -o pipefail
ninja: build stopped: subcommand failed.
```

Nothing is wrong with Apktool itself at this stage — the script never reaches the download step.

---

## 2. What that means

On Debian, Ubuntu, and Linux Mint, `/bin/sh` is **dash**, a minimal POSIX shell. It is not bash.

`scripts/fetch-apktool.sh` is written for bash:

```bash
#!/usr/bin/env bash
set -euo pipefail          # pipefail is a bash extension; dash rejects it
...
if [[ -f "${DEST}" ]]; then # [[ ... ]] is bash syntax, not POSIX sh
```

Meson’s `custom_target` in `meson.build` was calling the script explicitly through **`sh`**:

```meson
command: ['sh', fetch_apktool_script, meson.current_build_dir()],
```

That ignores the script’s `#!/usr/bin/env bash` shebang. Dash runs line 3, sees `set -o pipefail`, and exits immediately with **Illegal option -o pipefail**. Ninja marks the `apktool-jar` target failed and stops the build.

This often does not appear on Fedora, where `/bin/sh` may be bash (or bash in POSIX mode), so the same tree can build on one distro and fail on another.

---

## 3. Fix applied

`meson.build` now invokes the script with **bash**, matching the shebang and the bash-only syntax inside the file:

```meson
command: ['bash', fetch_apktool_script, meson.current_build_dir()],
```

No change was required inside `fetch-apktool.sh` — it was already correct for bash; only the Meson runner was wrong.

---

## 4. What you should run

Reconfigure is optional if only `meson.build` changed, but a clean re-run is simplest on a failed partial build:

```bash
cd ~/Workspace/Applications/apkManager
meson setup build --prefix="$HOME/.local" --reconfigure
meson compile -C build
meson install -C build
update-desktop-database ~/.local/share/applications
```

You should see `fetch-apktool: downloading Apktool 2.9.3...` (or “already exists”) instead of the `pipefail` error, and `build/apktool.jar` should appear before the Vala link step finishes.
