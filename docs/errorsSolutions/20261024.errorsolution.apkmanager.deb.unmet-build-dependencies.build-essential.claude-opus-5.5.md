## 1. What you see

The **Debian (.deb)** job in **Release packages** now gets past the `need dh` check (fixed earlier today) and starts `dpkg-buildpackage`, which stops before compiling anything:

```text
dpkg-checkbuilddeps: error: Unmet build dependencies: build-essential:native
dpkg-buildpackage: warning: build dependencies/conflicts unsatisfied; aborting
Error: Process completed with exit code 3.
```

---

## 2. What it means

### 2.1 `dpkg-checkbuilddeps` runs first

Before building, `dpkg-buildpackage` runs `dpkg-checkbuilddeps`, which verifies that every package listed in `Build-Depends` in `debian/control` is **installed as a dpkg package**. Having the right programs on `PATH` is not enough; the check looks at the package database.

### 2.2 `build-essential` is an implicit build dependency

Debian policy says every source package implicitly build-depends on **`build-essential`** — a metapackage that pulls in `gcc`, `g++`, `make`, `libc6-dev`, and `dpkg-dev`. It is never written in `debian/control`, but `dpkg-checkbuilddeps` always adds it. `:native` means “for the build machine's own architecture” (relevant only for cross-builds).

### 2.3 Why it was missing on GitHub but not locally

GitHub's `ubuntu-24.04` image ships `gcc`, `make`, and friends directly, but **does not install the `build-essential` metapackage itself**. `.github/scripts/install-debian-build-deps.sh` installed `devscripts`, `debhelper`, and every library in `Build-Depends`, but not `build-essential`, so the check failed even though a compiler was present.

On the developer machine `build-essential` was already installed, which is why the local `.deb` build succeeded.

### 2.4 Why not `-d`?

The log suggests `-d` (skip the dependency check). That would hide real problems; the check exists so the package is built only with declared dependencies. Installing the package is the correct fix.

---

## 3. Fix

`.github/scripts/install-debian-build-deps.sh` now installs `build-essential` first:

```bash
sudo apt-get install -y \
  build-essential \
  devscripts \
  debhelper \
  …
```

This script is shared by the **Debian (.deb)** and **AppImage** jobs in `release.yml` and the **Compile (Ubuntu)** job in `ci.yml`, so all three get the same toolchain. For local builds on a fresh Debian/Ubuntu machine, running the same script (or `sudo apt install build-essential`) prevents the error.

## 4. Verification

- The changed script is the only file touched; the edit adds one package name to an existing `apt-get install` list.
- The `.deb` build itself was already verified locally on a host that has `build-essential` (see the previous errorsSolutions doc).
- **To confirm on GitHub:** merge into `main` (or push a new `v*` tag); the Debian (.deb) job should move past `dpkg-checkbuilddeps` into `dh_auto_configure` / Meson.

If a later run reports another unmet dependency, compare the list with `Build-Depends` in `build/debian/control` and add the missing package to `install-debian-build-deps.sh`. `dpkg-checkbuilddeps` run locally (with `debian` → `build/debian` linked) prints the same list.
