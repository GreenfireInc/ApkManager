## 1. What you see

Open an APK, switch to the **Properties** tab, and click the **File** row (the APK filename with a folder icon). ApkManager exits immediately. The shell may print:

```text
GLib-ERROR **: g_variant_new: expected array GVariantBuilder but the built value has type '(null)'
Trace/breakpoint trap (core dumped)
```

Earlier GLib-CRITICAL lines about `g_variant_builder_end`, `g_variant_get_type`, and invalid format strings often appear just before the abort.

---

## 2. What that means

The **File** row calls `FileUtilsHelper.show_in_file_manager()` to highlight the APK in the desktop file manager through the session D-Bus service `org.freedesktop.FileManager1` and its `ShowItems` method.

That method expects two input arguments:

1. `as` — array of file URIs to show and select  
2. `s` — startup notification ID (may be empty)

Combined D-Bus tuple type: **`(ass)`** (array of strings, then string).

The first implementation built the payload with:

```vala
new Variant("(as)", new string[] { uri })
```

That is not a valid way to construct this message in GLib:

- `(as)` as a `g_variant_new()` format does not match the `(ass)` tuple `ShowItems` expects.
- Passing a Vala `string[]` directly where GLib expects a nested array variant triggers `g_variant_new` assertions.
- GLib then aborts the process (`g_variant_new: expected array GVariantBuilder…`), which closes ApkManager entirely.

So the crash is not a bad APK path or a broken file manager. It is an invalid **GVariant** for a correct D-Bus call.

---

## 3. Fix applied

`src/utils/file_utils.vala` now builds the D-Bus arguments with `VariantBuilder` and the `^as` format for the URI array:

```vala
var builder = new VariantBuilder(new VariantType("(ass)"));
builder.add("^as", new string[] { uri });
builder.add("s", "");
connection.call_sync(
    "org.freedesktop.FileManager1",
    "/org/freedesktop/FileManager1",
    "org.freedesktop.FileManager1",
    "ShowItems",
    builder.end(),
    new VariantType("()"),
    DBusCallFlags.NONE,
    -1,
    null
);
```

If `ShowItems` is unavailable, the helper still falls back to opening the parent folder with `AppInfo.launch_default_for_uri()`.

After the fix, clicking **File** opens the file manager and selects the APK (for example through Nemo on Linux Mint) without crashing.

---

## 4. What you should run

Quit any running `apk-manager`, then rebuild and install:

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open an APK, run **Quick Manifest**, go to **Properties**, and click **File**. The file manager should open with the APK highlighted instead of ApkManager crashing.
