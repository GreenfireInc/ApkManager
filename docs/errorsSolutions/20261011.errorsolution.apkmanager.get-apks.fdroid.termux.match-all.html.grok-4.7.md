## 1. What you see

Open **Get APKs**, set **Show** to **F-Droid**, and search for **Termux**. The list is not a set of app names. Rows contain raw markup from the F-Droid search page, for example fragments that start with:

```html
<a class="package-header" href="https://f-droid.org/en/packages/com.termux.styling">
```

Those rows have no app icon. The generic Android package icon stays in place because the captured “icon URL” is not a URL.

Aptoide is unaffected: that source is JSON, not this HTML regex.

---

## 2. What that means

F-Droid search is an HTML page at `https://search.f-droid.org/?q=Termux`. Each hit is a block like:

```html
<a class="package-header" href="https://f-droid.org/en/packages/com.termux">
  <img class="package-icon" src="https://ftp.fau.de/fdroid/repo/com.termux/en-US/icon_….png" />
  <h4 class="package-name">Termux</h4>
  <span class="package-summary">Terminal emulator with packages</span>
</a>
```

The parser’s regular expression is correct. Running it with `Regex.match()` and then `MatchInfo.next()` returns 20 clean Termux hits, including **Termux** itself and icon URLs that are `image/png`.

The bug is the walk. `parse_fdroid_results()` called `Regex.match_all()` and then `MatchInfo.next()` in a loop. GLib documents that combination as unsupported: `g_match_info_next()` on a `match_all()` result hits

```text
g_match_info_next: assertion 'match_info->pos >= 0' failed
```

and the capture groups are undefined. In practice the “name” group is a slice of the search HTML, and the “icon” group is empty or also markup. The row label therefore shows XML/HTML, and icon loading is skipped or rejects the value because it is not a PNG, JPEG, GIF, or WebP.

The same `match_all()` plus `next()` pattern was used for Uptodown and is fixed the same way.

---

## 3. Fix applied

`src/core/apk_store_search.vala` now starts both HTML searches with `Regex.match()` and advances with `MatchInfo.next()`:

```vala
if (!block_regex.match(html, 0, out match)) {
    return results;
}
while (true) {
    // fetch package id, icon URL, name, summary
    if (!match.next()) {
        break;
    }
}
```

Against the live Termux page, that walk yields names such as **Termux:Styling**, **Termux**, and **Termux:GUI**, with icon URLs such as `https://ftp.fau.de/fdroid/repo/com.termux/en-US/icon_….png`. Those URLs return `image/png`, so the existing binary icon loader can draw them.

## 4. What you should run

Quit the running `apk-manager`, then install this build:

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open **Get APKs**, set **Show** to **F-Droid**, and search **Termux**. Rows should list app names (including **Termux**) with package ids and summaries, and icons should load from the F-Droid mirror. Apps that F-Droid itself serves with `ic_repo_app_default.png` still show that placeholder, which is the image F-Droid published for those packages.
