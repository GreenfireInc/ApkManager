## Summary

The source code was already fixed, but the app that ran was not.

| Time (Nov 21) | Event |
|---------------|-------|
| 18:11 | `~/.local/bin/apk-manager` installed. Its Lepton commands still `git clone` lepton-x86 and run `build-all.sh` |
| 18:13 | ApkManager started from that installed binary (process 32593, working directory = the repository) |
| 18:39–18:40 | Fix written to `runtime_install_dialog.vala` and compiled into `build/meson/src/apk-manager`. **`meson install` was not run**, so `~/.local/bin` kept the old binary |
| 19:01 | First Lepton attempt in the still-open old app: cloned `lepton-x86/` into the repository, built a 3.4 GB `lepton-builder` Podman image and synced 17 GB of Android source before failing |
| Later | Second attempt (the output above): `git clone` refused because `lepton-x86/` now existed, and with no fail-fast every following line failed too |

The output itself shows the old code:

- The new commands contain no `git clone`, `install-dependencies.sh` or `build-all.sh`. They download the prebuilt `lepton-x86_64-v3.0.2-x86_64.4.tar.zst`.
- The new terminal wrapper runs the commands under `set -eo pipefail` and stops at the first failure. Here, five more lines ran after `git clone` failed.
- `strings ~/.local/bin/apk-manager` found `build-all.sh` and no `set -eo pipefail`; `build/meson/src/apk-manager` was the reverse.

The `apt` lines at the top (`825 not upgraded`, `apt autoremove`) are normal output from the package step and not errors.

## Solution

### 1. Install the fixed build

```bash
meson install -C build/meson
```

The build directory's prefix is `/home/corey/.local`, so this replaces `~/.local/bin/apk-manager` (plus the desktop file, schemas and the bundled apktool). After it:

| Check | Result |
|-------|--------|
| `strings ~/.local/bin/apk-manager` | Contains `set -eo pipefail` and `lepton-x86_64-v3.0.2-x86_64.4.tar.zst`; no `build-all.sh` |
| `~/.local/bin/apk-manager --version` | `ApkManager 0.2.9` |

### 2. Restart ApkManager

An open window keeps running the binary it was started from. **Close every ApkManager window and start it again** before retrying, or the old commands will run again.

### 3. Remove the leftovers of the aborted builds

| Leftover | Size | Action |
|----------|------|--------|
| `apkManager/lepton-x86/` (untracked clone with partial AOSP sync in `image/`) | 17 GB | Deleted |
| `localhost/lepton-builder:latest` Podman image | 3.43 GB | `podman rmi` |
| Exited `lepton-builder` container (`charming_shirley`) | 17 kB | `podman rm` |
| Untagged `docker.io/library/ubuntu` base pulled by the build | 80 MB | `podman rmi` |

Free space on `/home` went from 9.4 GB to 29 GB. The prebuilt install needs about 3 GB (600 MB download plus 1.5 GB unpacked), which the dialog checks before opening the terminal.

## Avoiding this next time

After changing the source, compile **and** install, then restart the app:

```bash
meson compile -C build/meson && meson install -C build/meson
```

`meson install` compiles first if needed, so it alone is enough. To test without installing, run `./build/meson/src/apk-manager` directly. Note that the app menu entry and `apk-manager` on `PATH` both use the installed copy in `~/.local/bin`.

## Expected output now

With the fixed build, the Lepton terminal (Ubuntu / Linux Mint row) should:

- skip `add-apt-repository`, since multiverse is already enabled;
- install packages;
- download the release with a `curl` progress bar;
- unpack it into `~/.local/share/Steam/compatibilitytools.d/lepton-x86_64/`;
- run `setup-host.sh`, which asks for your password and ends with "Done. Restart Steam, add the .apk as a non-Steam game…".

If any step fails, the terminal stops there and shows "The command failed (N)."
