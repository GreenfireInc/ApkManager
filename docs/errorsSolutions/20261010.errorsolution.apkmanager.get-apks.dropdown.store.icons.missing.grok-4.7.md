## 1. What you see

**Get APKs** opens. The **Show** dropdown lists **All sources**, **F-Droid**, **Aptoide**, and **Uptodown**. The three repository names appear as plain text. Their logos from `public/assets/icons/storesRepositories/` are not drawn in the closed button or in the popup list.

This is not a crash. The filter still changes which search results are shown.

---

## 2. What that means

The dropdown is a `Gtk.DropDown` with a custom row factory. Each store row is an icon plus a label. The factory was calling `Gtk.Image.set_from_file()` with a path from `AppPaths.store_repository_icon()`.

That helper looked in this order:

1. `APK_MANAGER_ASSETS_DIR`, if set
2. `<prefix>/share/apk-manager/icons/storesRepositories/<file>`
3. The current working directory, then **one** directory above the executable, plus `public/assets/icons/storesRepositories/<file>`

Two gaps made step 2 and step 3 miss the files:

- A development binary lives at `build/src/apk-manager`. That path is not `<prefix>/bin/apk-manager`, so the prefix falls through to `/usr/local`. The lookup then returns `/usr/local/share/apk-manager/icons/storesRepositories/appRepo.fdroid.svg`, which does not exist. The icons had also never been installed under `~/.local/share/apk-manager/icons/storesRepositories/`.
- The development fallback did not walk up from `build/src/` to the repository root, so it never reached `public/assets/icons/storesRepositories/`.

When the file test failed, the row used the generic `view-grid-symbolic` icon (or no store logo at all). The SVG files themselves are fine: GDK rasterizes them to textures with visible pixels (F-Droid 48×48, Aptoide 30×30, Uptodown 19×19).

A launch of the new binary with the working directory set to `/tmp` logged the miss before the fix:

```text
source filter icon label=F-Droid basename=appRepo.fdroid.svg
  path=/usr/local/share/apk-manager/icons/storesRepositories/appRepo.fdroid.svg
  exists=false cwd=/tmp
```

The same miss happens for Aptoide and Uptodown. Starting the app from the repository root can hide the bug, because the working directory then contains `public/assets/`. Starting it from `~/.local/bin/apk-manager`, a desktop launcher, or `build/src/apk-manager` does not.

---

## 3. Fix applied

The three SVGs are compiled into the executable with `data/apk-manager.gresource.xml` and loaded with `GLib.resources_lookup_data()` plus `Gdk.Texture.from_bytes()`. The dropdown no longer depends on the working directory or on `meson install` having copied the icons.

`AppPaths.store_repository_icon()` still walks parent directories from the working directory and from the executable, so a filesystem copy can be used if the embedded resource is missing. The button and the popup each get their own `Gtk.SignalListItemFactory`, so the closed row and the list do not share one factory instance.

After the change, launching from `/tmp` logged:

```text
loaded store icon /com/github/ApkManager/icons/storesRepositories/appRepo.fdroid.svg (21102 bytes)
loaded store icon /com/github/ApkManager/icons/storesRepositories/appRepo.aptoide.svg (2728 bytes)
loaded store icon /com/github/ApkManager/icons/storesRepositories/appRepo.uptodown.svg (2203 bytes)
```

The open dropdown then shows the F-Droid, Aptoide, and Uptodown marks next to those names. **All sources** keeps the generic grid icon.

---

## 4. What you should run

Quit the `apk-manager` that is already running. The copy in `~/.local/bin` does not pick up this change until you install again.

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open **Get APKs** and the **Show** menu. F-Droid, Aptoide, and Uptodown should each show their logo.
