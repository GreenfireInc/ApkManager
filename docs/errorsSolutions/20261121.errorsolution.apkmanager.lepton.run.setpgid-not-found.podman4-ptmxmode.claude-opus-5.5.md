## What it means

The start of `lepton.bin`:

```bash
if is_start && [[ -z "${IS_PARENT:-}" ]]; then
    export IS_PARENT=true
    exec setpgid --foreground "$0" "$@"
fi
```

When Lepton starts an app, it re-runs itself through **`setpgid`**. That command puts a program in a new process group, and with `--foreground` also makes that group the terminal's foreground group, so Lepton can later stop or signal everything it started as one unit.

`setpgid` is a fairly new **util-linux** command (2.41). Valve built Lepton for SteamOS, and the x86_64 port is tested on Fedora and Arch; all three ship a new enough util-linux. Linux Mint 22 / Ubuntu 24.04 ship **util-linux 2.39.3**, which doesn't have it:

```text
$ command -v setpgid        → (nothing)
$ dpkg -S bin/setpgid       → no path found
```

So bash failed at line 23 with `exec: setpgid: not found`, and ApkManager showed that message. The APK itself had nothing to do with it; any APK fails the same way.

### A second incompatibility behind it

With `setpgid` provided, Lepton got much further (reading the APK, setting up overlays) and then failed with:

```text
Launching lepton-steamlaunch-test-lepton
Error: ptmxmode: invalid mount option
```

`mounting.sh` mounts the container's `/dev/pts` with `--mount type=devpts,…,mode=644,ptmxmode=666`. The `ptmxmode` option is only understood by **Podman 5**, and this machine has **Podman 4.9.3** (Ubuntu 24.04's version). Tested with a small container:

| `devpts` options | Result on Podman 4.9.3 |
|------------------|------------------------|
| `mode=644,ptmxmode=666` | `Error: ptmxmode: invalid mount option` |
| `mode=644` | Starts; `/dev/pts/ptmx` has mode `000`, so non-root processes can't open pseudo-terminals |
| `mode=644` + host `/dev/ptmx` passed through | runc replaces `/dev/ptmx` with its own link, so no change |

Lepton's normal launch (`podman run` in `start_container`) doesn't request a terminal. Only its early-debug shell uses `-it`. Pseudo-terminals inside Android matter only for interactive `adb shell` sessions, so on Podman 4 dropping `ptmxmode` costs nothing for running apps.

## Solution

### 1. A `setpgid` stand-in, used only where the real one is missing

A small Python script at `lepton-x86_64/bin/setpgid` does what `lepton.bin` needs:

- it moves the process into its own process group;
- with `--foreground`, if there is a controlling terminal, it makes that group the terminal's foreground group;
- it then `exec`s the program.

ApkManager starts Lepton in a new session (`Posix.setsid()` in `detach_child`), so Lepton is already a session and group leader without a terminal. The stand-in handles that case instead of failing. (The real `setpgid(2)` call returns `EPERM` for a session leader.)

`lepton.conf`, which the `lepton` wrapper sources with `DIR` set to the tool directory, gets:

```bash
# setpgid(1) is new in util-linux 2.41; use the bundled stand-in where it's missing.
command -v setpgid >/dev/null || export PATH="${DIR}/bin:${PATH}"
```

On a system with util-linux 2.41 or newer, the real `setpgid` is found and the stand-in is never used.

### 2. Skip `ptmxmode` on Podman 4

Line 563 of `liblepton/mounting.sh` becomes:

```bash
podman_mount_entry_type "devpts" /dev/pts "mode=644${LEPTON_DEVPTS_PTMXMODE-,ptmxmode=666}"
```

`lepton.conf` sets the variable to empty only when Podman is older than 5:

```bash
[[ "$(podman --version 2>/dev/null)" =~ version\ [0-4]\. ]] && export LEPTON_DEVPTS_PTMXMODE=""
```

With Podman 5 the variable stays unset and the original `ptmxmode=666` is used.

### 3. The fixes are part of the install

Re-installing Lepton overwrites `lepton.conf` and `mounting.sh`, so `runtime_install_dialog.vala` has a new block, `LEPTON_COMPAT_STEPS`. It runs right after the release is unpacked, before `setup-host.sh`, on all three distribution rows: it writes `bin/setpgid`, patches `mounting.sh`, and appends both lines to `lepton.conf`.

### 4. Clear message when Steam isn't running

The run after these fixes stopped at the next requirement:

```text
Error: statfs /home/corey/.steam/steam.pipe: no such file or directory
```

Lepton bind-mounts the Steam client's pipe (`mounting.sh` line 189), and Steam hasn't been installed or started on this machine yet. Podman's message doesn't say that, so `run_lepton` in `runtime_runner.vala` now checks for `~/.steam/steam.pipe` first. If it's missing, it shows:

> Lepton needs the Steam client. Start Steam (on an X11 desktop, use steam-lepton), then try again.

## What comes next

Lepton now starts correctly on this machine. These are the remaining requirements before an Android app appears:

| Requirement | How |
|-------------|-----|
| Steam installed, run once, running | `steam-installer` was installed by the Lepton steps. On X11, start it with `steam-lepton` (or the **Steam (Lepton)** menu entry) so Lepton also gets a Wayland display |
| binderfs | `sudo modprobe binder_linux` (and `/etc/modules-load.d/binder.conf`); the updated install steps do this |
| Wayland display | Nested Weston via `steam-lepton`, or the Cinnamon on Wayland session |

Restart ApkManager first so the new build (with the Steam check) is the one running.
