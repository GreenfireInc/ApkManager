## 1. What you see

| Build | Window look |

| Local `meson install` (`~/.local/bin/apk-manager`) | Libadwaita styling: rounded window, flat Adwaita header bar, libadwaita window controls |
| AppImage downloaded from GitHub (`ApkManager-0.2.0-x86_64.AppImage`) | Header bar and window controls look like plain GTK, not libadwaita |

Same source code, same libadwaita version family — only the packaging differs.

---

## 2. What it means

### 2.1 The AppImage runs a startup hook before the app

`build-appimage.sh` uses **linuxdeploy** with **linuxdeploy-plugin-gtk** to bundle GTK. That plugin writes an *AppRun hook*, `AppDir/apprun-hooks/linuxdeploy-plugin-gtk.sh`, which the AppImage sources every time it starts. A local `meson install` never runs this hook — which is why only the AppImage is affected.

The upstream hook contains:

```bash
APPIMAGE_GTK_THEME="${APPIMAGE_GTK_THEME:-"Adwaita:$GTK_THEME_VARIANT"}"  # light or dark
export GTK_THEME="$APPIMAGE_GTK_THEME" # Custom themes are broken
export GDK_BACKEND=x11 # Crash with Wayland backend on Wayland
```

### 2.2 `GTK_THEME` overrides libadwaita's styling

Libadwaita ships its own stylesheet and expects GTK's theme to be left alone. Setting `GTK_THEME` (even to `Adwaita`) forces GTK to load **GTK's built-in “Adwaita” theme** — the plain GTK 4 default, not the libadwaita stylesheet — underneath the app. Libadwaita documents `GTK_THEME` as unsupported for this reason. The visible result is GTK-styled header bars and window buttons instead of libadwaita's.

The hook sets it because, for GTK 3 apps, host custom themes often break inside an AppImage. That reasoning does not apply to libadwaita apps, which never use the host theme anyway.

### 2.3 `GDK_BACKEND=x11` forces XWayland

The second line works around an old GTK 3 Wayland crash. For a GTK 4 / libadwaita app it just pushes the window onto X11 (XWayland on Wayland desktops), which changes how decorations, scaling, and shadows are handled compared with the native Wayland run you get locally.

### 2.4 Not a code problem

The app already uses `Adw.ApplicationWindow` + `Adw.ToolbarView` correctly (see the Oct 7 decorations doc). The `.deb`, `.rpm`, Flatpak, and Snap builds do not use this hook and are unaffected.

## 3. Fix

`packaging/appimage/build-appimage.sh` now builds the AppImage in two linuxdeploy passes with an edit in between:

1. **Deploy:** `linuxdeploy --appdir … --plugin gtk` (no `--output`) — bundles libraries and writes the hook.
2. **Patch the hook:** delete the `export GTK_THEME=` and `export GDK_BACKEND=` lines from `apprun-hooks/linuxdeploy-plugin-gtk.sh`. The script fails loudly if the hook is missing or the lines are still present, so a future plugin change cannot silently bring the problem back.
3. **Pack:** `LDAI_OUTPUT="$OUTPUT" linuxdeploy --appdir … --output appimage` — a second pass **without** `--plugin gtk`, so the edited hook is packed as-is into `dist/ApkManager-<version>-<arch>.AppImage`.

The rest of the hook (bundled GSettings schemas, GTK modules, pixbuf loaders, `XDG_DATA_DIRS`) is kept; only the two overrides are removed.

### Workaround for the existing 0.2.0 AppImage

```bash
./ApkManager-0.2.0-x86_64.AppImage --appimage-extract
sed -i '/^export GTK_THEME=/d; /^export GDK_BACKEND=/d' squashfs-root/apprun-hooks/linuxdeploy-plugin-gtk.sh
./squashfs-root/AppRun
```
