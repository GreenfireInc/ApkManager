## 1. What you see

On the Install APK window the app logo sits on the left and the folder icon on the right, with `>` between them. The hint says “Drag and Drop to install in Applications”.

Moving the pointer over the logo does nothing: the cursor stays an arrow and the logo does not highlight. Pressing and dragging the logo does not pick it up, so it cannot be dropped on the folder. The folder still opens the install directory when clicked. **Inspect APK** still works. Nothing is copied into `~/Applications/android`, and the main window does not gain a new recent entry from this gesture.

---

## 2. What that means

The drag-and-drop code was attached, but two GTK 4 rules kept it from ever running.

1. **`Gtk.Image` does not take the pointer.** `Gtk.Image` sets `can-target` to false, so clicks, hover, and gestures pass through it. `Gtk.DragSource` was added to that image. The gesture never saw the press, so there was no grab cursor, no hover, and no drag.

2. **The drag and the drop did not speak the same type.** The source offered the path as `text/plain` bytes (`Gdk.ContentProvider.for_bytes`). The folder’s `Gtk.DropTarget` asked for `GLib.Bytes`. GTK only highlights a drop target and delivers `drop` when the offered formats include what the target asked for. These two formats do not match, so even a drag that started would be rejected by the folder.

The copy itself (`ApkInstall.install`) and the main-window hand-off (`install_requested` → `open_apk`) were already in place. They never ran because the gesture and the drop negotiation failed first.

---

## 3. Fix applied

The logo now sits in a box that **does** take the pointer (`can-target` true). That box uses a grab cursor and a hover background (`.apk-install-source:hover`). `Gtk.DragSource` is on the box, not on the image.

`prepare` offers the APK path as a **string** `GValue`. The folder’s `Gtk.DropTarget` asks for `typeof(string)`, so GTK treats the folder as a valid copy target. While the drag is over the folder it gains `.drop-active`. On drop, the path is checked against the open APK, then `ApkInstall.install` copies the file into the Preferences install path (default `~/Applications/android`) on a background thread. Success emits `install_requested`, which registers and opens that path in the main window and closes the Install APK window.

The drag icon is the app logo (`Gtk.DragIcon.set_from_paintable`).

---

## 4. What you should run

Quit ApkManager if it is already running, then rebuild and install:

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager 00.references/orion-store-1-5-0.apk
```

Hover the logo: the pointer becomes a grab hand and the logo picks up a light background. Drag it onto the folder: the folder highlights, the APK is copied to `~/Applications/android` (or the path in Preferences), the Install APK window closes, and the package appears in the main window recents list.
