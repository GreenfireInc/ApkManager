## 1. What you see

Opening `00.references/com.brave.browser.from.Aptoide.x86_64.apk` in ApkManager shows the generic `application-x-android-package` symbol instead of the Brave lion logo. There is no error dialog. Inspect APK, manifest parsing, and the rest of the session UI work normally.

---

## 2. What that means

The loader **did** resolve `android:icon` correctly. The failure happened one step later.

| Step | Brave APK | Result |
|------|-----------|--------|
| Manifest `android:icon` | `@2131297594` (`0x7f09075a`) | OK |
| `resources.arsc` lookup | `res/eHC.xml` | OK |
| File type | Compiled **vector drawable** XML (`pathData`, `viewportWidth`, …) | Not a PNG/WebP |
| Old `ApkIcon.score_path()` | Rejects `.xml` paths by design | Returns `null` |
| UI fallback | `UiUtils.load_session_icon_paintable()` | Generic package icon |

Brave (and many modern apps after aapt2 shrinking) stores the launcher icon as an obfuscated vector drawable such as `res/eHC.xml`, not as `mipmap-*/ic_launcher.png`. This x86_64 Aptoide split **does** contain the icon resource; it is simply not a bitmap.

Adaptive icons add another layer: `android:icon` may point at an `<adaptive-icon>` XML wrapper whose `<foreground>` / `<background>` children are `@drawable/...` references that must be followed through `TYPE_REFERENCE` entries in `resources.arsc` before a raster or vector leaf is reached.

## 3. Fix applied

**Drawable chain resolution (`apk_icon.vala`)**

- `ApkIcon.load()` now calls `ResourceTable.load_icon()` instead of stopping at `best_image_path()`.
- Raster PNG/WebP/JPEG (including extensionless WebP) is still preferred when present.
- When no raster exists, the loader resolves `.xml` drawable paths, follows `TYPE_REFERENCE` chains in `resources.arsc`, and dispatches by root element:
  - `adaptive-icon` → `foreground` drawable first, then `background`
  - `layer-list` → first `item` with a `drawable` reference
  - `inset`, `scale`, `clip-path`, `shape` → nested `drawable` reference
  - `vector` → rasterize (below)

**Binary XML parsing (`apk_binary_xml.vala`)**

- Reads compiled Android binary XML from `res/*.xml`: string pool, optional `0x0180` attribute-id map, element tree, typed attributes (`drawable`, `pathData`, `fillColor`, …).

**Vector-to-raster (`apk_vector_drawable.vala`)**

- For simple `<vector>` drawables with `<path android:pathData="…" android:fillColor="…"/>`, parses SVG-style path commands (`M/L/H/V/C/Z` and lowercase relative variants) and renders a 128×128 PNG with Cairo for `Gdk.Texture.from_bytes()`.

**Build**

- Added `cairo` dependency in `meson.build`.

This is intentionally a **first step**: complex vectors (gradients, groups, strokes, full SVG grammar) and compositing adaptive foreground over background are not implemented yet.
