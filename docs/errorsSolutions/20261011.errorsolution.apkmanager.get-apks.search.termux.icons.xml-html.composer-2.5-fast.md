## 1. What you see

Open **Get APKs**, search for **Termux**, and the result list appears broken:

- Every row keeps the generic Android package icon instead of the app logo from F-Droid, Aptoide, or Uptodown.
- Rows from **Uptodown** show only a page URL in the subtitle (no author or description).
- In logs or when inspecting failed icon loads, the bytes returned for an icon URL are **HTML or XML text** (for example `<!DOCTYPE html>` or an SVG/XML error page), not PNG/JPEG/WebP image data.
- Search itself does not crash; names like **Termux**, **Termux: X11**, and **Termux:API** can still appear.

This is not the dropdown repository-logo bug fixed earlier. That issue was missing SVG paths for F-Droid/Aptoide/Uptodown in the **Show** filter. This issue is missing **app icons in search result rows** and weak metadata from Uptodown.

---

## 2. What that means

Get APKs loads store pages as **text** (HTML or JSON) and parses them into `ApkStoreResult` rows. Each row then downloads its `icon_url` asynchronously and draws it with `Gdk.Texture.from_bytes()`.

Two separate problems caused the broken Termux search experience:

### A. Icon downloads went through UTF-8 text mode

`HttpClient.get_bytes()` called `get_string()`, which used `Subprocess.communicate_utf8_async()`. That API requires valid UTF-8. PNG, JPEG, and WebP icon bytes are binary and often contain sequences that are **not** valid UTF-8.

When icon loading hit binary data, GLib rejected the stdout as invalid UTF-8. The async icon load failed, ApkManager logged a warning, and the row kept the fallback `application-x-android-package` icon. Every store icon failed the same way, so **all results looked icon-less**.

APK downloads used the same broken path (`get_bytes()` → UTF-8 string → cast back to bytes), which could corrupt downloaded APK files even when search looked fine.

### B. Uptodown search never extracted icon URLs

The Uptodown HTML parser only matched the app name and page link:

```html
<div class="name"><a href="…" title="Download Termux"><h2>Termux</h2></a>
```

It ignored the nearby `<img class="app_card_img" src="https://img.utdstc.com/icon/…">` inside the same result card. Uptodown rows were therefore created with `icon_url = ""`, so no icon fetch was attempted even after fixing binary HTTP.

When an icon URL did fail or returned an HTML error document (common on blocked or redirected CDN URLs), the invalid body is **XML/HTML text**. That matches the “xml/html” part of the report: the HTTP layer was treating or receiving markup instead of raster image bytes.

### C. Aptoide JSON guard (minor)

If Aptoide ever returned an HTML error page with HTTP 200, `Json.Parser` would fail silently and contribute zero results. A guard now skips bodies that start with `<`.

## 3. Fix applied

### `src/utils/http_client.vala`

- `run_curl()` now uses `Subprocess.communicate_async()` and returns raw `GLib.Bytes` (binary-safe).
- `get_string()` decodes those bytes as UTF-8 for HTML/JSON search pages.
- `get_bytes()` returns the raw bytes for icons and APK files.
- Added `BROWSER_USER_AGENT` for image CDN requests.
- Added `looks_like_image()` to verify PNG/JPEG/GIF/WebP magic bytes before calling `Gdk.Texture.from_bytes()`.

### `src/core/apk_store_search.vala`

- Uptodown parser now extracts `app_card_img` `src`, author, and description from each search card.
- F-Droid `<img class="package-icon">` regex allows attributes in either order.
- Aptoide parser skips HTML responses before JSON parse.
- APK download writes with `FileUtils.set_data()` instead of casting binary data through `string`.

### `src/windows/get_apks_window.vala`

- Result icon loads use `HttpClient.BROWSER_USER_AGENT` and reject non-image payloads.

After the fix, a Termux search should list apps with real icons (for example Termux from Uptodown with a `img.utdstc.com` JPEG icon, Termux from Aptoide with a `pool.img.aptoide.com` PNG, and F-Droid add-ons with mirror PNG URLs).

## 4. What you should run

Quit any running `apk-manager` instance, then rebuild and install:

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

Open **Get APKs**, search **Termux**, and confirm:

1. Rows show app logos (not only the generic package icon).
2. Uptodown rows include a description such as “Emulate the Linux terminal on your smartphone”.
3. **Download** still works for F-Droid and Aptoide; Uptodown still opens the browser download page.
