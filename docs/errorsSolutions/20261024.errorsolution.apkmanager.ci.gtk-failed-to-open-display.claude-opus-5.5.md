## 1. What you see

The **Compile (Ubuntu)** job in GitHub Actions compiles successfully, then fails at the last step:

```text
Run ./build/meson/src/apk-manager --version

(apk-manager:6101): Gtk-WARNING **: 13:54:05.486: Failed to open display
Error: Process completed with exit code 1.
```

The Vala warnings earlier in the log (deprecated `Gtk.StyleContext`, unhandled `GLib.Error`, …) are unrelated; they do not fail the job.

---

## 2. What that means

### 2.1 GitHub runners are headless

`ubuntu-24.04` runners have no X11 or Wayland session: `DISPLAY` and `WAYLAND_DISPLAY` are unset. Any code that calls `gtk_init()` (directly or indirectly) cannot connect to a display server, logs `Failed to open display`, and the process exits with status 1.

### 2.2 Why `--version` touched GTK at all

`--version` looks like a pure CLI flag, but it was handled inside the GUI application object:

| Order | What runs | Needs a display? |
|-------|-----------|------------------|
| 1 | `main()` → `new ApkManager.Application()` → `app.run(args)` | No |
| 2 | GApplication parses options, registers on D-Bus | No |
| 3 | `startup()` → `Adw.Application` / `Gtk.Application` startup → **`gtk_init()`** | **Yes — fails here** |
| 4 | `command_line()` → `if (opt_version) print(...)` | Never reached |

So the version string was only printed **after** GTK initialization, which can never succeed on a headless runner. The smoke test was effectively launching the GUI.

### 2.3 Why CI/CD did not run usefully after merges into `main`

- `ci.yml` ran on pushes to `main`, but the smoke test always failed there (above).
- `release.yml` only ran on `v*` tags or manual dispatch, so a merge into `main` never produced installable packages, and packaging was not gated on CI passing.

---

## 3. Fix

### 3.1 Answer `--version` before GTK starts (`src/main.vala`)

`main()` now checks for `--version` (stopping at a `--` separator) and prints the version **before** creating the `Adw.Application`, before the D-Bus stale-instance check, and before any GTK call:

```vala
// Answered before GApplication startup, which initializes GTK and needs a display.
if (wants_version(args)) {
    stdout.printf("ApkManager %s\n", APPLICATION_VERSION);
    return 0;
}
```

This also means `apk-manager --version` no longer contacts (or replaces) a running ApkManager instance over D-Bus.

Verified locally with every display and session variable removed:

```bash
env -u DISPLAY -u WAYLAND_DISPLAY -u DBUS_SESSION_BUS_ADDRESS \
  ./build/meson/src/apk-manager --version
# ApkManager 0.1.0
# exit=0
```

The CI step now explicitly runs headless (`unset DISPLAY WAYLAND_DISPLAY`) so the test proves the same thing locally and on GitHub.

### 3.2 CI/CD pipeline around `main`

| Event | Workflow(s) | What happens |
|-------|-------------|--------------|
| Push to a `CS.*` working branch | `ci.yml` | Compile + headless smoke test |
| Pull request into `main` | `ci.yml` | Compile + headless smoke test (merge gate) |
| **Merge / push into `main`** | `release.yml` → calls `ci.yml` | CI first; **only if it passes**, build `.deb`, `.rpm`, Flatpak, Snap, AppImage and upload them as workflow artifacts |
| Push tag `v*` | `release.yml` | Same as above, then **Publish GitHub Release** with all packages attached |
| Manual | either (`workflow_dispatch`) | On demand |

Key changes:

- `ci.yml`: triggers on `pull_request` into `main`, `CS.*` pushes, `workflow_call` (reusable), and `workflow_dispatch`. Pushes to `main` were removed here because `release.yml` now runs CI for them (avoids duplicate runs).
- `release.yml`: adds `push: branches: [main]`; a new `ci` job (`uses: ./.github/workflows/ci.yml`); every packaging job has `needs: ci`. Superseded runs on `main` are cancelled (`cancel-in-progress` only for `refs/heads/main`); tag runs are never cancelled. The `github-release` job is still tag-only, so merges into `main` produce artifacts but no public release.

### 3.3 Recommended GitHub settings (manual, repository admin)

These live in GitHub, not in the repository, so they cannot be committed:

1. **Settings → Actions → General:** Actions enabled; *Workflow permissions* allow read and write (needed by `softprops/action-gh-release` on tags).
2. **Settings → Branches → Branch protection for `main`:** *Require status checks to pass before merging* → select **Compile (Ubuntu)**. This makes the CI result a hard merge gate.

## 5. If a future GUI test needs a display

For tests that genuinely create windows, run them under a virtual X server instead of a real display:

```bash
sudo apt-get install -y xvfb
xvfb-run -a ./build/meson/src/apk-manager --some-gui-test
```

Do not use `xvfb-run` to paper over CLI flags; CLI flags should stay GTK-free as `--version` now is.
