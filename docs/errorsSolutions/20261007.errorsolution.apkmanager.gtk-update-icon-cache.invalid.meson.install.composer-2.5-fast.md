## 1. What you see

Compile succeeds. Most of `meson install` succeeds too — binary, desktop file, GSettings schema, metainfo, and `apktool.jar` are copied under `~/.local`. Then the last post-install hook fails:

```text
Running custom install script '/usr/bin/gtk-update-icon-cache -q -t -f /home/corey/.local/share/icons/hicolor'
--- stderr ---
gtk-update-icon-cache: The generated cache was invalid.

FAILED: install script ... exit code 1, stopped
```

Meson reports failure even though ApkManager itself is already installed.

---

## 2. What that means

`data/meson.build` used `gnome.post_install(gtk_update_icon_cache: true)`. Meson turns that into:

```text
gtk-update-icon-cache -q -t -f $PREFIX/share/icons/hicolor
```

That tool rebuilds the **entire** `hicolor` icon theme, not just ApkManager’s icon. With `--prefix=$HOME/.local`, the target directory is `~/.local/share/icons/hicolor`, which often already contains icons from Wine, manual installs, or other apps.

On this host, names with spaces (for example `14C0_FL (extended memory).0.png` and `093C_Rabby Desktop.0.png`) and stray files (`.DS_Store`, misplaced PNGs) made `gtk-update-icon-cache` write a cache file and then reject it as invalid. ApkManager’s own SVG under `scalable/apps/com.github.ApkManager.svg` is fine; the failure comes from unrelated entries already in that tree.

Meson also prefers `gtk4-update-icon-cache` when present; on Mint it was missing, so the GTK 3 `gtk-update-icon-cache` ran instead (`Program gtk4-update-icon-cache found: NO` during setup).

ApkManager does not need a cache rebuild for its launcher icon. A single SVG at `hicolor/scalable/apps/com.github.ApkManager.svg` is resolved by standard icon theme lookup once the desktop file points at `Icon=com.github.ApkManager`.

---

## 3. Fix applied

`data/meson.build` sets `gtk_update_icon_cache: false` in `gnome.post_install()`. Schema compilation and desktop-database refresh still run; only the fragile whole-tree icon-cache step is skipped.

After install, run (as before):

```bash
update-desktop-database ~/.local/share/applications
```

---

## 4. What you should run

```bash
cd ~/Workspace/Applications/apkManager
meson setup build --prefix="$HOME/.local" --reconfigure
meson compile -C build
meson install -C build
update-desktop-database ~/.local/share/applications
export PATH="$HOME/.local/bin:$PATH"
apk-manager
```

`meson install` should finish without the icon-cache error. The app menu entry should show the Android robot icon from `~/.local/share/icons/hicolor/scalable/apps/com.github.ApkManager.svg`.

### Optional: clean up a broken user icon tree

If you want `gtk-update-icon-cache` to succeed on `~/.local/share/icons/hicolor` for other tools, remove or rename problematic entries (filenames with spaces, `.DS_Store`, PNGs in the wrong size folder), then run:

```bash
gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor
```

That is independent of ApkManager and only needed if you maintain that directory manually.
