## 1. What you see

`meson compile` and `meson install` succeed. `~/.local/bin/apk-manager` is the new binary. Running `apk-manager netflix-….apk` opens an Install APK window — and it still shows the generic Android symbol for Netflix and TikTok, exactly as before the fix. The four smaller APKs show their logos as before.

Nothing in the terminal says anything is wrong. The command returns at once, and the window appears.

---

## 2. What that means

ApkManager is a `Gtk.Application` with the id `com.github.ApkManager`. GLib makes such an app **single-instance**: the first process to start claims that name on the session bus and becomes the *primary* instance. Any later `apk-manager file.apk` only connects to the bus, hands the file to the primary over D-Bus, and exits. The window you then see is created by the primary — not by the binary you just ran.

That is what happened here:

| | |
|---|---|
| Primary instance | PID 88086, started 16:20:10, `/home/corey/.local/bin/apk-manager /home/corey/Programs/bitchat.apk` |
| `meson install` | 16:44:06 — replaced the file on disk |
| `/proc/88086/exe` | `/home/corey/.local/bin/apk-manager (deleted)` |
| New code in 88086? | `grep -c apk-open-icon /proc/88086/exe` → 0 |

The process that owned `com.github.ApkManager` was loaded from the *previous* install. Linux let the install overwrite the file (hence `(deleted)`), but the running program kept its old code in memory. Every new `apk-manager <apk>` forwarded the file to it, so the old 8 MiB read cap and old scorer decided Netflix and TikTok's icons — and failed, as documented in the previous note.

So the fix was right and installed. It simply never executed, because an older copy of the app stayed in charge. Quitting ApkManager before relaunching would have shown the logos; this is the third time in one afternoon that a stale primary hid a change, so it is worth fixing in code rather than remembering.

---

## 3. Fix applied

`main.vala` now calls `Application.retire_stale_instance()` before `app.run()`. It:

1. Asks the session bus who owns `com.github.ApkManager` (`GetConnectionUnixProcessID`). If no one does, it returns — this launch becomes the primary as usual.
2. Compares `/proc/<owner>/exe` with `/proc/self/exe`. If they are the **same file**, nothing changes: the launch joins the running instance exactly as before (verified: a second launch of the installed binary exits immediately and its window is created by the existing PID).
3. If the owner's executable is marked `(deleted)` or is a **different path** (an old install, or `build/src/apk-manager` vs `~/.local/bin/apk-manager`), it logs `Replacing ApkManager instance <pid> (<exe>) with <exe>`, activates the remote `app.quit` action over D-Bus, and waits up to 1.5 s. Binaries that predate this change have no such action; those get `SIGTERM` after the wait. It then waits for the bus name to be released and starts normally as the new primary.

`Application.startup()` now registers that `app.quit` action, so from this build on the hand-off is a clean `Gio.Application.quit()` rather than a signal. The sidebar's `win.quit` is unchanged.

Verified with both reference packages: launching the new build against stale PID 88086 produced the "Replacing" message, the stale process ended, and the new process drew the Install APK window with the Netflix red N; the same for TikTok's note mark after replacing an installed primary with the build-tree binary via `app.quit`.

## 4. What you should run

```bash
cd ~/Workspace/Applications/apkManager
meson compile -C build
meson install -C build
export PATH="$HOME/.local/bin:$PATH"
apk-manager 00.references/netflix-9-87-1-build-9-74701.apk
apk-manager 00.references/tiktok-47-4-41.apk
```

You no longer need to quit the running ApkManager first. If an older copy is still running, the terminal prints one `Replacing ApkManager instance …` line, that copy closes, and the Install APK window opened by the new binary shows the Netflix and TikTok logos.

To check which process owns a window at any time:

```bash
busctl --user list | grep com.github.ApkManager    # PID that owns the name
ls -l /proc/<pid>/exe                               # "(deleted)" means it predates the last install
```
