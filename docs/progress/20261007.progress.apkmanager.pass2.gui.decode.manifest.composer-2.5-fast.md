## 1. Executive summary

**Pass 1** (documented in the initial foundation progress report) delivered the Meson/Vala skeleton: open/drop flow, raw APK listing, Apktool runner wiring, session JSON, and desktop metadata. That pass did not verify a successful compile on the developer host.

**Pass 2** (this document) closes the loop from “scaffold” to **working desktop app** on Fedora: `meson compile` and `meson install` succeed; `~/.local/bin/apk-manager` launches; users can open APKs, list raw ZIP entries, run **Quick Manifest** and **Full Decode**, see a **metadata popup** after manifest decode, and **reload recent sessions** from the sidebar. Several production bugs (install JAR, Apktool CLI mismatch, subprocess crash, status-line noise, missing popup icon, inert recent list) were fixed and recorded under `docs/errorsSolutions/` and `docs/continuation/`.

The main pane still shows **raw archive entries only** after decode; browsing the decoded tree in GTK and GtkSourceView viewers remains **Phase 3–4** work.

## 3. Pass 2 engineering deliverables

### 3.1 Build and install

| Change | Purpose |
|--------|---------|
| Vala compile fixes (continuation doc) | First green `meson compile` on Fedora (property syntax, libarchive API, subprocess I/O, Gtk/ListStore patterns, etc.) |
| `scripts/install-apktool.sh` + Meson `add_install_script` | Copy `apktool.jar` without Meson `depfixer.fix_jar()` (JDK `jar` tool not required on headless hosts) |
| `APKTOOL_LIBDIR` in `build_info.vala.in` | Baked install path for JAR lookup (`lib64/apk-manager` on Fedora) |
| `app_paths.vala` JAR resolution | Env override, baked path, `/proc/self/exe` prefix probe, build-dir fallback |

**Verified on host (October 7, 2026):** Vala 0.56.19, Meson 1.11.2, GTK 4.22, Libadwaita 1.9.4, OpenJDK headless; install prefix `$HOME/.local`.

### 3.2 Apktool subprocess (`src/core/apktool_runner.vala`)

| Fix / behavior | Detail |
|----------------|--------|
| Apktool **2.9.3** CLI alignment | Removed unsupported `-j` / `--only-manifest`; Quick Manifest uses `-s -r --force-manifest` |
| NULL-terminated `argv` | Vala `string[]` for `g_subprocess_newv` (fixes SIGSEGV from `Gee.ArrayList.to_array()`) |
| `STDERR_MERGE` + tail of output | Status line shows Apktool text instead of generic “Child process exited with code 1” |
| `DataInputStream.close_base_stream = false` | Avoid use-after-free on unowned stdout pipe |
| Phase telemetry | Log lines still drive progress messages in the main window |

### 3.3 Raw APK and cache (`src/core/apk_archive.vala`, sessions)

| Change | Purpose |
|--------|---------|
| Safe path checks | Reject absolute paths and `..` segments only (fix false “unsafe” rejects) |
| `read_data_skip()` on non-matches | libarchive must skip entries when scanning for one path |
| Partial → final cache rename | `.partial-<pid>` under `~/.cache/apk-manager/decoded/<sha256>-manifest\|full/` |

### 3.4 Metadata and icon (Phase 3 seed)

| Module | Role |
|--------|------|
| `src/core/apk_metadata.vala` | Parse decoded `AndroidManifest.xml` + `apktool.yml` (package, versions, SDK, permissions cap, icon ref) |
| `src/core/apk_icon.vala` | Resolve `@213…` / hex resource ids via `resources.arsc`; pick best-density PNG/WebP/JPEG from APK ZIP |
| `src/windows/manifest_popup.vala` | Modal `Adw.Window` after Quick Manifest: 64×64 `Gtk.Picture`, property groups, permission list (max 24) |

### 3.5 Main window UX (`src/windows/main_window.vala`)

| Feature | Behavior |
|---------|----------|
| Quick Manifest | Decode → popup with metadata; status “Manifest ready.” |
| Full Decode | Same cache pipeline; no popup (decode only) |
| `Adw.ViewStack` | Empty state until an APK is loaded; switches to content on `open_apk` |
| Recent APKs | `row_activated` + `recent_paths[]`; click loads session via `open_apk()`; missing file shows status message |
| Split view | `show_content = true` when loading so content pane is visible on narrow layouts |

## 5. Build verification (current)

```bash
cd Applications/ApkManager
meson setup build --prefix=$HOME/.local   # once
meson compile -C build
meson install -C build
update-desktop-database ~/.local/share/applications   # optional
~/.local/bin/apk-manager
```

**Sample flow validated in development:** open `/path/to/app.apk` → raw entry tree → **Quick Manifest** → metadata popup with icon (when `resources.arsc` + drawable resolve) → **Recent APKs** click reloads the same file.

**Note:** After `meson install`, quit and restart the app to pick up the new binary.
