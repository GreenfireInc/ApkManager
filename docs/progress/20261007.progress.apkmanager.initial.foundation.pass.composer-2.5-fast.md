## Summary

The initial ApkManager foundation was scaffolded in `Applications/apkManager/` following the unified methodology documents in `docs/methodologies/`, using `Others/AppManager` as the GTK/Libadwaita/Meson shell reference and `Others/Apktool` for the decode engine contract (JVM flags, CLI flags, log phases).

This pass implements **Phase 0–1** from the unified plan: Meson project structure, core modules, basic windows, desktop metadata, and Apktool JAR fetch script. The application is not yet fully feature-complete (no info window, source viewers, or packaging), but the architectural skeleton is in place.

## Design Decisions (Aligned With Methodology Docs)

1. **Shell/engine split:** Vala GTK shell + Apktool subprocess, not a JavaFX fork.
2. **Two-stage reading:** Raw libarchive listing works without Java; decode requires JRE 17+.
3. **Fast manifest path:** `Quick Manifest` button runs `apktool d -s --only-manifest`.
4. **Atomic cache writes:** Decode targets `.partial-<pid>` directory (rename on success planned in next pass).
5. **Libadwaita floor:** Meson requires `libadwaita-1 >= 1.4` (broader Debian support than AppManager's 1.6).
6. **Apktool pin:** Version 2.9.3 downloaded from official Bitbucket releases at build time.
