## 2. What landed in the app

This sits on 0.2.7, which already had the Runtime engine picker, the install-guide dialog, and the D-Bus address fix. Today's changes are the circles, the install button, the alphabetical list, and the version bump.

### 2.1 Installed or missing

Each combo row is a circle, the engine logo, and the name. The closed value and the dropdown use the same row.

| State | Circle | Tooltip |
|-------|--------|---------|
| Program found | Green (`success`) | Installed |
| Program not found | Red (`error`) | Not installed |

"Installed" means the program is present. It does not mean Waydroid has been initialized, and it does not mean Lepton's container is running. The checks are `PATH` and files, not `dnf` or `rpm`, so the same test works on the distros that package these differently.

| Engine | Green when |
|--------|------------|
| Waydroid | `waydroid` or `waydroid-launcher` is on `PATH`, or an executable is at `/usr/bin` or `/run/host/usr/bin` |
| Android Translation Layer | `android-translation-layer` is on `PATH`, or a file whose name contains `android_translation_layer` or `android translation layer` sits directly in `~/Applications`, `~/.local/bin`, or `~/Downloads` |
| Lepton | Steam has app `3029110`, or `compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf` is under a Steam library or `/usr/share/steam` or `/usr/local/share/steam` |

On this machine the Android Translation Layer AppImage is linked from `~/.local/bin`, so that row is green. Waydroid is not installed. There is no Steam directory, so Lepton is red. Podman being installed does not count as Lepton.

Closing the install guide rebuilds the combo factory, so a runtime installed from the guide shows its new circle without reopening Preferences.

### 2.2 Install button

The mark under each distro's copy button is a flat button (`system-software-install-symbolic`).

On **Android Translation Layer** a click does three steps:

1. `gnome-terminal --wait -- bash -c <script>` runs that row's first line (`sudo apt install curl libfuse2`, `sudo apt install curl libfuse2t64`, or `sudo dnf install curl fuse-libs`) and waits for Enter. The script writes `$?` to `/tmp/apk-manager-runtime-install.status`.
2. If that status is `0` and `curl` is on `PATH`, download `Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage` into `~/Downloads` and mark it executable.
3. Run `AppManager install` on that file. Lookup order is `~/Applications/AppManager`, then `app-manager` on `PATH`, then a download of AppManager 3.8.0 from the GitHub release. This machine already has AppManager 3.7.3, so the button uses that copy.

On **Waydroid** and **Lepton** the button opens a terminal and runs the commands printed on the row. Those rows do not download an AppImage and do not call AppManager.

`--wait` returns when the window closes, not when `dnf` exits, so the status file is what the app trusts. A missing file means the terminal closed early. A non-zero status skips the download. Toasts name each step. A second click is ignored until the sequence finishes. Flatpak and the strict Snap cannot run the host package manager or see the host terminal; the `~/.local` build can.

### 2.3 Alphabetical list

The Runtime engine combo now reads:

1. Android Translation Layer
2. Lepton
3. Waydroid

The combo index is cast to `RuntimeEngine`, so the enum in `src/core/app_settings.vala` is in that same order. The saved setting is the string `waydroid`, `android-translation-layer`, or `lepton`, so a choice made before the reorder still selects the same engine. The 0.2.8 changelog was written before this reorder and does not mention it.
