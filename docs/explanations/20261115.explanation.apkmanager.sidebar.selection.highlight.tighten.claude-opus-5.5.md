## 1. What looked wrong

When you select an app in the Recent APKs sidebar:

- **List view:** the highlight was a flat, square-cornered block that filled the whole sidebar width. The row had 12 px of side padding and 6 px above and below, so the block looked heavy compared with the icon and name inside it.
- **Grid view:** the highlight was much larger than the tile. Each tile had its own margins (8 px top and bottom, 4 px left and right). GTK added the default `flowboxchild` padding outside those margins. The grid is homogeneous, so each child was also stretched to an equal column width. Together, the selection box sat well away from the icon and text, and it changed width with the window.

---

## 2. Why it looked that way

`Gtk.ListBox` and `Gtk.FlowBox` draw selection on the **row or child container**, not on the content you place inside it. Everything between the container edge and your content is part of the highlighted area:

1. **Margins on the content box**, such as `row_box.margin_*` and `tile.margin_*`, push the content inward. The highlight still covers that space.
2. **Theme padding on the container**, from Adwaita’s default `row` and `flowboxchild` styles, adds more space around it.
3. **Allocation:** a homogeneous `FlowBox` gives each child a full column width. A child keeps that whole width unless its own `halign` tells it to take only its natural size.

A plain `Gtk.ListBox` also uses Adwaita’s full-width “boxed list” selection. Libadwaita has a sidebar style for this case: the `navigation-sidebar` CSS class gives rounded, inset rows with a soft neutral highlight.

## 3. What was changed

All edits are in `src/windows/main_window.vala`.

### 3.1 List view

| Change | Effect |
|--------|--------|
| `session_list.add_css_class("navigation-sidebar")` | Rows are rounded and inset from the sidebar edge, with the same soft highlight GNOME sidebars use (Files, Settings) |
| `build_session_list_row()`: removed the 12 px start and end margins; top and bottom margins 6 px → 4 px; icon-to-text spacing 10 px → 8 px | The `navigation-sidebar` row already supplies horizontal padding, so the extra margin only widened the block. The highlight now fits the icon, name, and size line |

### 3.2 Grid view

| Change | Effect |
|--------|--------|
| `build_session_grid_tile()`: removed the tile margins (8/4 px); spacing inside the tile 6 px → 4 px | No empty space inside the highlight |
| `grid_item.halign = Gtk.Align.CENTER` on each `Gtk.FlowBoxChild` | The child keeps its natural tile width instead of stretching to the column. The highlight stays the same size when the window is resized |
| New `ensure_session_items_css()` (scoped to `flowbox.session-grid`) | 4 px child padding, 8 px corner radius, focus ring drawn inside the edge (`outline-offset: -2px`), hover at `alpha(currentColor, 0.05)`, selected at `alpha(currentColor, 0.1)`. These match the `navigation-sidebar` look so list and grid feel like the same app |
| `color: inherit` on the selected child | Names and the dim size line keep their normal colors instead of switching to the theme’s selected text color |
| `column_spacing` and `row_spacing` 8 px → 6 px | Tiles sit a little closer together now that each highlight is smaller |

### 3.3 Grid column count

`update_session_grid_columns()` works out how many tiles fit per line. It now counts the child padding (`SESSION_GRID_TILE_MARGIN_PX`, 4 px + 4 px = 8 px) and `column_spacing`. That keeps the column count correct after the spacing change. The CSS padding and that constant must stay equal, and a short comment above the CSS says so.

## 4. Result

- **List:** a rounded, inset highlight that fits the icon and two lines of text, in the same neutral tone as other GNOME sidebars.
- **Grid:** a small rounded highlight that sits close to the icon, name, and size, with a light hover state and no extra padding.
- Selection still works the same way: single click, multi-select, right-click **Remove from recents**, and the selection is kept across refreshes.
