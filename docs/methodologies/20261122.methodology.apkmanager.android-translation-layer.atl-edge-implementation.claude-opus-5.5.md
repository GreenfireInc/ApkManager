## 1. What the user sees

The Android Translation Layer page of the runtime install dialog has an **ATL.edge** row: "Edge builds: the latest upstream source, with the newest features and fixes first". Its install button opens a terminal running the build, then installs the AppImage with AppManager, replacing the current ATL.

## 3. Where it differs from the strategy

### 3.1 The ATL desktop-entry patch was replaced with a `sed` edit

The first test build showed that pkgforge-dev's `atl-desktop-entry-binary-path.patch` no longer applies to ATL `master`: upstream renamed `desktop_entry` to `exec_cmd` in `src/main-executable/main.c`. ATL.edge makes that one edit with a pattern-matching `sed`, and only warns if the pattern stops matching. The patch file was removed. The four art_standalone patches still apply as diffs.

### 3.2 Build-environment changes in `get-dependencies.sh`

ATL `master` has outgrown pkgforge-dev's build environment (the pkgforge recipe was last released 2026-09-22). `get-dependencies.sh` makes three more changes:

- **Jars for `tools/jni_upcall_gen`.** The tool needs the `asm`, `asm-tree` and `java-getopt` jars and looks for them with Fedora's `xmvn5-resolve`, which Arch doesn't have. The recipe downloads pinned jars from Maven Central (asm 9.8, asm-tree 9.8, java-getopt 1.0.13, each checked by SHA-256) through a new `fetch_jar` function. It passes them to ATL's Meson build as `-Dasm_jar_path`, `-Dasm_tree_jar_path` and `-Dgetopt_jar_path`.
- **JDK 17 for the ATL step.** The same tool needs Java 12 or newer (`Path.of`, `Files.mismatch`). Java 8 stays in use for art_standalone. ATL builds with JDK 17 (`JAVA_HOME=/usr/lib/jvm/java-17-openjdk`), the version ATL's `doc/Build.md` uses on Fedora; its sources still target 1.8. Both JDKs are removed before packaging (`pacman -Rns jdk8-openjdk jdk17-openjdk`).
- **New packages:** `speech-dispatcher` (a new dependency in ATL's `meson.build`) and `jq` (writes `atl-build.json`).

## 4. How the build was debugged

Each failed run stopped at one missing piece, fixed in this order:

| Failure | Fix |
|---------|-----|
| `xmvn5-resolve` not found | Pinned jars plus the three `-D…_jar_path` options |
| `speech-dispatcher` dependency not found | Added the package |
| `javac` 8 has no `Path.of` / `Files.mismatch` | JDK 17 for the ATL step |
| `jq` not found | Added the package |

The fifth run finished with exit status 0.

## 5. Result

The first successful build is `94d69d8c-edge`: about 18 minutes, a 139 MB AppImage. It starts and loads apps.

Termux and a Flutter calculator crash on both this build and the pkgforge `3e686d14` build, for different reasons. Termux's `TerminalRenderer` calls `Paint.getFontSpacing()`, which ATL doesn't implement, and Flutter fails `Check failed: libandroid`. The findings documents dated 20261122 cover these and the other app failures.
