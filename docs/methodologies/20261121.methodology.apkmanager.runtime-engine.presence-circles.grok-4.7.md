## 1. What changed

Each entry in the Runtime engine combo is now a circle, then the engine's logo, then its name. The same row is used for the value shown when the combo is closed and for every row in the list.

| State | Circle | CSS class | Tooltip |
|-------|--------|-----------|---------|
| Program found | Green | `success` | Installed |
| Program not found | Red | `error` | Not installed |

The circle is a `●` label. Libadwaita's `success` and `error` classes color it, the same classes the Verify window uses for its result line. A tooltip carries the same fact for anyone who cannot use the color.

The circles are read again when the install guide closes, by replacing the combo's factory. Installing a runtime from that guide and closing it updates the mark without reopening Preferences.

---

## 2. How "present" is decided

The check does not call `dpkg`, `rpm`, or `pacman`. Those differ by distro, and a SteamOS update can remove a package entry while the program is gone. A program on `PATH`, or the known file, is enough. This matches the research note.

| Engine | Green when |
|--------|------------|
| Waydroid | `waydroid` or `waydroid-launcher` is on `PATH`, or either program is executable at `/usr/bin` or `/run/host/usr/bin` (the Flatpak host mount) |
| Android Translation Layer | `android-translation-layer` is found the same way, or a file whose name contains `android_translation_layer` or `android translation layer` sits directly in `~/Applications`, `~/.local/bin`, or `~/Downloads` |
| Lepton | `steamapps/appmanifest_3029110.acf` or `compatibilitytools.d/lepton-x86_64/compatibilitytool.vdf` exists under a Steam data directory: native, Snap, Flatpak, `/usr/share/steam/compatibilitytools.d`, `/usr/local/share/steam/compatibilitytools.d`, or a library path named in that Steam install's `libraryfolders.vdf` |

On this Fedora 44 machine that paints Waydroid red and Android Translation Layer green. Lepton is red: no Steam data directory is present. Android Translation Layer is found because `~/.local/bin/android-translation-layer` points at the AppImage in `~/Applications`.

`meson compile` and `meson install` succeeded. Two headless screenshots of Preferences, with a private settings file so the user's saved engine was left alone:

- Runtime engine set to Android Translation Layer: a green circle, then the wine-glass logo, then the name.
