## 1. Executive summary

The About window now shows **“Running on &lt;distribution&gt;”** with the distribution's logo directly under the version pill, and the same facts (plus GTK / libadwaita versions) under **Troubleshooting → Debug Info**.

The method has three parts:

1. **Detect** the host distribution from `os-release`, preferring the host's copy when running inside Flatpak or Snap, and classify it into one of four families — Linux Mint, Ubuntu, Debian, Fedora — using `ID` first and `ID_LIKE` second.
2. **Ship the logos as themed icons** in the app's GResource, so GTK renders the SVGs crisply at any size and the code can ask “does this icon exist?” before using it.
3. **Insert a badge into `Adw.AboutWindow`**, which has no API for custom main-page content, by locating its version pill (style class `app-version`) and placing a widget after it.

## 2. Detection (`HostDistro`)

### 2.1 Why `os-release`

`/etc/os-release` (fallback `/usr/lib/os-release`) is the freedesktop standard every target distro ships. It is plain `KEY=value` text; values may be quoted. The relevant keys:

| Key | Example (Linux Mint 22) | Use |
|-----|-------------------------|-----|
| `ID` | `linuxmint` | Primary family match |
| `ID_LIKE` | `ubuntu debian` | Fallback family match for derivatives |
| `PRETTY_NAME` | `Linux Mint 22` | Text shown in the badge |
| `VERSION_ID` | `22` | Debug info |

`GLib.Environment.get_os_info()` reads the same data but only from `/etc` and `/usr/lib`, which is wrong inside sandboxes (next section), so `HostDistro` parses the file itself.

### 2.2 Sandboxes see the wrong file

| Package | What `/etc/os-release` says | Host copy read instead |
|---------|-----------------------------|------------------------|
| `.deb`, `.rpm`, local `meson install`, AppImage | The host | — |
| Flatpak | The GNOME runtime (“GNOME”, `ID=org.gnome.Platform`-like) | `/run/host/os-release` (Flatpak mounts it) |
| Snap | The base snap (Ubuntu Core 24) | `/var/lib/snapd/hostfs/etc/os-release` |

`HostDistro` tries, in order: `/run/host/os-release`, `/var/lib/snapd/hostfs/etc/os-release`, `/etc/os-release`, `/usr/lib/os-release`, and uses the first readable file. Outside a sandbox the first two do not exist, so the normal path is reached.

### 2.3 Family matching

```text
families = [linuxmint, ubuntu, debian, fedora]

if ID ∈ families            → family = ID
else for token in ID_LIKE   → first token ∈ families wins (matched_by_id_like = true)
else                        → no family (generic Linux badge)
```

Order matters: Linux Mint lists `ID_LIKE="ubuntu debian"`, but its own `ID` matches first, so it gets the Mint logo. Derivatives without their own logo fall through `ID_LIKE` — e.g. Pop!_OS (`ID=pop`, `ID_LIKE="ubuntu debian"`) shows the Ubuntu badge with an extra “Ubuntu-based” caption; Nobara / Ultramarine fall back to Fedora.

## 3. Icons as themed icons

The SVGs are added to the GResource under the app's icon-theme path:

```xml
<gresource prefix="/com/github/ApkManager/icons/scalable/apps">
  <file alias="apk-manager-distro-debian.svg">public/assets/icons/operatingSystems/debian.svg</file>
  <file alias="apk-manager-distro-fedora.svg">public/assets/icons/operatingSystems/fedora.svg</file>
  <file alias="apk-manager-distro-linuxmint.svg">public/assets/icons/operatingSystems/linuxmint.svg</file>
  <file alias="apk-manager-distro-ubuntu.svg">public/assets/icons/operatingSystems/ubuntu.svg</file>
  <file alias="apk-manager-distro-linux.svg">public/assets/icons/operatingSystems/linux.svg</file>
</gresource>
```

`Gtk.Application` automatically adds `<resource-base-path>/icons` to the icon theme, so `Gtk.Image.from_icon_name("apk-manager-distro-fedora")` works with no extra setup (the same mechanism already used for `qr-code-symbolic` and `github-symbolic`). Compared with loading a `Gdk.Texture` from the SVG bytes:

- GTK rasterizes the SVG at the requested pixel size and scale factor, so the logo stays sharp on HiDPI.
- `Gtk.IconTheme.has_icon()` gives a clean fallback check.
- The `apk-manager-distro-` prefix avoids clashing with icons a system theme might ship under names like `ubuntu` or `fedora`.

### Debian

`debian.svg` was added later the same day and registered as `apk-manager-distro-debian.svg`; no code change was needed. It is an Adobe Illustrator export with XML entity declarations in its DOCTYPE; it was checked to render correctly through gdk-pixbuf's librsvg loader (the path GTK uses for SVG icons).

Any family whose icon is missing still falls back to the generic `linux.svg` via `Gtk.IconTheme.has_icon()`.

## 4. Inserting the badge into `Adw.AboutWindow`

`Adw.AboutWindow` (and `Adw.AboutDialog`) expose properties for fixed fields only — name, icon, version, links, credits, debug info. There is no slot for custom main-page widgets, and the class is final, so it cannot be subclassed.

The approach (the same technique as the existing GitHub credit icon):

1. After configuring the window, walk its widget tree for the widget with the **`app-version`** style class — libadwaita's version pill. (Confirmed present in the installed libadwaita: `strings libadwaita-1.so.0 | grep app-version`.)
2. Build the badge: a centered horizontal `Gtk.Box` with a 32 px `Gtk.Image` and a vertical text stack — dim caption “Running on”, `PRETTY_NAME` in `heading` style, and an optional dim “&lt;Family&gt;-based” line when matched via `ID_LIKE`. A tooltip repeats the detection result.
3. `badge.insert_after(version_button.get_parent(), version_button)` places it directly under the version.

The main page is the navigation view's root page, so it is already in the widget tree when the window is created (unlike the Credits subpage, which is only parented when pushed).

**Graceful degradation:** if a future libadwaita renames or restructures the version pill, `find_with_css_class` returns `null` and the badge is simply skipped. The detection still appears in **Troubleshooting → Debug Info**, which uses public API (`debug_info`, `debug_info_filename`):

```text
ApkManager 0.2.4
Distribution: Linux Mint 22
ID: linuxmint
Version: 22
Family: Linux Mint
GTK: 4.14.x
Libadwaita: 1.5.x
```
