## 1. Executive summary

The **Files** tab today is a read-only `Gtk.TreeView` of ZIP members inside the open APK. Rows show **Entry**, **Size**, and **Type**, but there is no double-click handler, context menu, or launch path yet.

Opening a row in the **system text editor** (GNOME Text Editor, Kate, Vim, VS Code — whatever the desktop default is for that MIME type) is straightforward on Debian and Fedora: **extract the bytes to a temporary file on disk**, then ask GLib/GIO to **launch the default application for that file’s URI**. ApkManager already uses the same GIO mechanism when revealing a path in the file manager (`FileUtilsHelper.show_in_file_manager()` falls back to `AppInfo.launch_default_for_uri()`).

The important design choice is **which bytes** to export:

| Source | When | What the user sees in an external editor |
|--------|------|-------------------------------------------|
| **Raw APK entry** | Before or without decode | Often binary (compiled XML, `.dex`, `.arsc`) — poor fit for a text editor |
| **Decoded cache file** | After Quick Manifest or Full Decode | Human-readable XML, smali, YAML — good fit |

A practical v1 therefore combines **type-aware eligibility**, **decode-aware path selection**, and **temp-file export** for raw entries that are already plain text.

## 2. Current behavior (October 13, 2026)

```text
User selects APK in sidebar
        │
        ▼
MainWindow.open_apk()
        │
        ▼
load_archive_entries(apk_path)
        │
        ▼
ApkArchive.list_entries()  ──►  Gtk.ListStore  ──►  archive_tree (Files tab)
```

Relevant code paths:

- Listing: `ApkArchive.list_entries()` via libarchive — no Java required.
- Reading one member: `ApkArchive.read_entry(apk_path, entry_name)` — capped at 64 MiB per entry.
- Type column: `ApkArchive.entry_type_label()` classifies paths as `text`, `xml` (via extension), `dex`, `image`, etc.
- **No** `row-activated`, **no** popover menu, **no** “Open” action on `archive_tree`.

After **Full Decode**, the Files tab **still** shows the raw ZIP listing; it does not yet switch to the decoded tree under `~/.cache/apk-manager/decoded/<key>/`. That continuation gap affects which files are easiest to open in an editor (see §5).

## 3. Goal

From the Files tab, let the user:

1. Select a file row (single selection).
2. Trigger **Open in Text Editor** (double-click, Enter, toolbar button, or context menu).
3. Have the OS default editor open with sensible content.
4. Stay within ApkManager security rules: read-only, no shell strings, bounded extraction, safe paths.

This complements — does not replace — the planned in-app **GtkSourceView** viewers described in the unified methodology (§7.4). External editor opening is especially useful for users who already configured a preferred editor via `xdg-mime` / GNOME “Default Applications”.

## 4. Recommended architecture

### 4.1 High-level flow

```text
archive_tree row activated
        │
        ▼
Resolve ArchiveFileRef { apk_path, entry_path, type_label, session }
        │
        ├─► If decoded mirror exists on disk ──► open that path directly
        │
        └─► Else extract raw entry ──► write temp file ──► launch default app
                    │
                    ▼
            AppInfo.launch_default_for_uri(file://…)
```

### 4.2 New helper (suggested module)

Add something like `src/core/archive_file_launcher.vala` or extend `src/utils/file_utils.vala`:

```vala
public static bool open_entry_in_system_editor(
    string apk_path,
    string entry_path,
    string? decoded_cache_dir
) throws Error
```

Responsibilities:

1. **Reject** directories and unsafe paths (`ApkArchive.is_safe_archive_path()`).
2. **Choose source path:**
   - If `decoded_cache_dir` is set, map ZIP entry → decoded path (see §5).
   - Otherwise call `ApkArchive.read_entry()`.
3. **Write** bytes to a temp file if needed (preserve extension for MIME guessing).
4. **Launch** with GIO (never `/bin/sh -c xdg-open …`).

Example launch (Vala / GIO):

```vala
var file = File.new_for_path(temp_path);
if (!AppInfo.launch_default_for_uri(file.get_uri(), null)) {
    throw new IOError.FAILED("No default application for %s".printf(temp_path));
}
```

Optional refinement: resolve a more specific handler before launch:

```vala
var content_type = ContentType.guess_type(temp_path, null, out bool uncertain);
AppInfo? app = AppInfo.get_default_for_type(content_type, false);
app.launch_uris(new string[] { file.get_uri() }, null);
```

### 4.3 Temp file policy

| Rule | Rationale |
|------|-----------|
| Directory under `$XDG_CACHE_HOME/apk-manager/open/` or `GLib.FileUtils.open_tmp()` | Keeps exports inside the app cache; matches existing cache layout |
| Filename includes sanitized entry basename + correct extension | So `AndroidManifest.xml` opens as XML, not plain text |
| Mode `0600` | Private preview of potentially sensitive APK contents |
| Size cap for editor export (e.g. 2–8 MiB) | Aligns with unified methodology bounded-preview rule (§9) even though `read_entry` allows 64 MiB |
| Optional: register temp files in a small registry and delete on next app start | Avoids unbounded cache growth; editor may still hold the file open |

Do **not** write into the user’s project tree or `/tmp` without a prefix; use the app cache namespace.

### 4.4 UI wiring (`main_window.vala`)

Minimal integration points:

| Trigger | GTK hook |
|---------|----------|
| Double-click / Enter | `archive_tree.row_activated` |
| Context menu | `Gtk.PopoverMenu` with `"Open in Text Editor"` → `win.open-archive-entry` |
| Optional accelerator | Document in Keyboard Shortcuts (`Return` when tree focused) |

Pseudo-handler:

```vala
private void on_archive_entry_activated(Gtk.TreeView tree, Gtk.TreePath path, Gtk.TreeViewColumn? column) {
    Gtk.TreeIter iter;
    if (!archive_store.get_iter(out iter, path)) return;

    string entry_path;
    archive_store.get(iter, 0, out entry_path);

    var type_label = ApkArchive.entry_type_label(entry_path, false);
    if (!ArchiveFileLauncher.is_editor_eligible(type_label, entry_path)) {
        status_label.set_text("This entry is not readable as text. Run Quick Manifest or Full Decode first.");
        return;
    }

    try {
        ArchiveFileLauncher.open_in_system_editor(
            active_session.apk_path,
            entry_path,
            active_session.cache_dir
        );
    } catch (Error e) {
        status_label.set_text("Could not open editor: %s".printf(e.message));
    }
}
```

Enable single-row selection on `archive_tree` (`selection.mode = SINGLE`).

## 5. Raw ZIP vs decoded cache — what actually opens well

### 5.1 Raw APK entries (current Files tab)

| Entry | Raw bytes in ZIP | System text editor experience |
|-------|------------------|-------------------------------|
| `AndroidManifest.xml` | **Binary XML (AXML)** | Gibberish — needs Apktool decode |
| `res/**/*.xml` | Usually **binary XML** | Gibberish |
| `assets/**/*.json`, `.txt`, `.html` | Plain text | **Good** — open directly |
| `classes.dex`, `resources.arsc`, `lib/**/*.so` | Binary | **Bad** — offer hex viewer or “Open with…” chooser later |
| `META-INF/*` | Often text-like (`.MF`, `.SF`) | **Moderate** — may be readable |

**Recommendation:** Gate “Open in Text Editor” on `entry_type_label()`:

- **Allow immediately:** `text`, and optionally `signature` for `.MF`/`.RSA` text portions.
- **Allow after decode only:** paths that decode to readable XML/smali/YAML.
- **Block or redirect:** `dex`, `native`, `binary`, `resource` (compiled), `image`, `font`, `audio`, `video`.

For blocked compiled XML, show a short status message: *“Run Quick Manifest or Full Decode, then open the decoded copy.”*

### 5.2 Decoded cache (after Apktool)

After **Quick Manifest** (`DecodeMode.MANIFEST_ONLY`):

- `decoded/<key>/AndroidManifest.xml` — readable XML
- `decoded/<key>/apktool.yml` — YAML text

After **Full Decode**:

- `smali*/**/*.smali` — text
- `res/**/*.xml` — readable XML (unless `--only-manifest -s` skipped resources)
- Copied `assets/`, `original/`, etc.

Once the Files tab switches to the decoded tree (continuation milestone), opening becomes **`AppInfo.launch_default_for_uri()` on a real file** under `session.cache_dir` — no temp extraction step, better performance, and editors can reload on re-decode if paths are stable.

### 5.3 Mapping ZIP path → decoded path

Until the UI shows a decoded tree, a launcher can still prefer decoded files when present:

| ZIP entry | Decoded path (typical) |
|-----------|-------------------------|
| `AndroidManifest.xml` | `<cache>/AndroidManifest.xml` |
| `apktool.yml` | N/A in ZIP; only in decode output |
| `assets/foo.txt` | `<cache>/assets/foo.txt` (Full Decode copy) |
| `classes.dex` | `<cache>/smali/` (not 1:1 — open smali folder or block) |

Mapping is **not always 1:1**; the launcher should use explicit rules and fall back to raw extraction only when a decoded counterpart is missing.

## 6. MIME types and desktop integration

On Debian and Fedora, the default editor comes from the **shared-mime-database** and desktop file `MimeType=` / `Default Applications`.

| Extension | Typical MIME | Default app examples |
|-----------|--------------|----------------------|
| `.xml` | `application/xml` or `text/xml` | GNOME Text Editor, Kate |
| `.yml`, `.yaml` | `application/x-yaml` | same |
| `.smali` | often `text/plain` | user’s plain-text editor |
| `.json`, `.txt`, `.properties` | `application/json`, `text/plain` | same |
| `.html` | `text/html` | browser or editor |

Implementation notes:

- Preserve the **original extension** on the temp file so `ContentType.guess_type()` works.
- If launch fails (`launch_default_for_uri` returns `false`), show **`Gtk.AppChooserDialog`** as a fallback (“Open with…”).
- Do **not** hard-code `gedit`, `kate`, or `code`; always defer to the session default.

Existing precedent in-tree: `FileUtilsHelper.show_in_file_manager()` already uses **`AppInfo.launch_default_for_uri()`** when D-Bus `FileManager1.ShowItems` is unavailable — the editor path reuses the same GIO API with a file URI instead of a directory.

## 7. Security and safety (aligned with §9 of unified methodology)

1. **Read-only** — export bytes; never execute DEX, `.so`, or scripts from the APK.
2. **Path validation** — reuse `is_safe_archive_path()`; reject `..`, absolute paths, and directory rows.
3. **No shell** — launch via `AppInfo` / `Gio.Subprocess` argument vectors only; never `xdg-open` through `/bin/sh -c`.
4. **Bounded export** — enforce a smaller cap (e.g. 2 MiB) for editor temp files than the 64 MiB `read_entry` icon/manifest limit.
5. **Private cache** — temp dir mode `0700`; filenames derived from entry path, not user-controlled absolute paths.
6. **No network** — opening a local temp file must not trigger ApkManager network code (GIO launch is out-of-process; acceptable).
7. **Trust model** — user explicitly opens content; APKs are untrusted input, but exporting to an editor is the same risk class as extracting with a file-roller “Extract” action.

## 8. Phased implementation plan

| Phase | Scope | Effort |
|-------|--------|--------|
| **A — External editor for plain-text raw entries** | Double-click / context menu; temp extract; launch default app; gate on `text` type | Small |
| **B — Decode-aware opens** | If `session.cache_dir` exists, open decoded `AndroidManifest.xml` / smali / decoded `res` XML instead of raw AXML | Medium |
| **C — Files tab shows decoded tree** | After Full Decode, list `<cache>/` tree; external editor opens real paths (no temp) | Medium (continuation item) |
| **D — In-app GtkSourceView** | Unified methodology §7.4; optional “Open in external editor” button from viewer | Larger (Phase 4) |
| **E — AppChooser + hex fallback** | Binaries: hex preview in-app; “Open with…” for power users | Optional |

Phase **A + B** delivers the user-visible “open in system text editor” behavior without waiting for the full decoded tree UI.

## 9. Edge cases and UX copy

| Situation | Behavior |
|-----------|----------|
| Java missing; no decode yet | Allow plain `assets/` text; block compiled XML with message to run Quick Manifest |
| Entry &gt; size cap | “File too large to preview in an editor (limit N MiB).” |
| No default app for MIME | Open `Gtk.AppChooserDialog` or suggest installing a text editor |
| Editor already has temp file from prior open | Write new temp file (new inode) or overwrite; document that reload may be needed |
| Multi-select in tree | Ignore or open first selected only in v1 |
| User prefers VS Code / Cursor | Works automatically if set as default for `text/plain` / `application/xml` |

Suggested context menu entries (future):

- **Open in Text Editor** (default for eligible types)
- **Reveal Decoded Folder** (when `cache_dir` set) — reuses `show_in_file_manager(cache_dir)`

## 10. Testing checklist

1. Plain text under `assets/` in a test APK opens in the session default editor.
2. Raw `AndroidManifest.xml` is **blocked** or opens decoded copy after Quick Manifest.
3. After Full Decode, `apktool.yml` and a `.smali` file open readably.
4. Launch works on **Debian GNOME** and **Fedora KDE** with different default editors.
5. Oversized entry shows an error, not a hang.
6. Path traversal entries never appear in the tree (existing `list_entries` filter).
7. No `java` subprocess spawned for editor-only opens of raw text assets.

## 11. Summary

Opening Files tab entries in the **system text editor** is possible with three pieces ApkManager almost already has:

1. **Extract or locate bytes** — `ApkArchive.read_entry()` for raw ZIP members, or a real path under `session.cache_dir` after decode.
2. **Materialize as a normal file** — temp file with correct extension under the app cache (raw case).
3. **Hand off to the desktop** — `AppInfo.launch_default_for_uri()` (same family as existing file-manager reveal code).

The main caveat is **content shape**: many “XML” paths inside an APK are **binary AXML** until Apktool decodes them. The feature should be **type- and decode-aware**, not a blind “export every row” action. Pairing external-editor support with the planned **decoded tree** and **GtkSourceView** viewers gives users both quick OS integration and a safe in-app read-only experience.
