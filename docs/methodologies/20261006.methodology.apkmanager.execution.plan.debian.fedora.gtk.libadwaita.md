## 1. What I would produce

| Artifact | Command / trigger | Backend |
|----------|-------------------|---------|
| Installed desktop app | `meson install -C build` | Vala/GTK shell |
| Double-click `.apk` handler | `update-desktop-database` after install | MIME + `.desktop` |
| Decoded APK tree in GUI | Open APK → Decode & Browse | `java -jar apktool.jar d …` (Phase 1) |
| APK metadata panel | Info window before/after decode | `aapt2 dump badging` + `apktool.yml` |
| CLI entry point | `apk-manager open /path/to/app.apk` | Same decode pipeline as GUI |
| Release bundle (optional) | `./scripts/make-appimage.sh` | AppImage with bundled JRE 17 |

Output cache layout:

```
~/.cache/apk-manager/decoded/<sha256>/   # decoded tree per APK
~/.cache/apk-manager/frameworks/       # apktool framework APKs
~/.local/share/apk-manager/sessions.json # recent sessions index
```

I would **not** embed rebuild/sign (`apktool b`) in the first release. Read-only browsing is the goal.

## 2. The conversion model (Apktool → GUI)

Apktool is already a library (`apktool-lib`) behind a CLI (`apktool-cli`). Converting it to a GUI does **not** mean rewriting decode logic in Vala. It means:

```
┌─────────────────────────────────────────────────────────┐
│  ApkManager (GTK 4 / Libadwaita / Vala)                 │
│  ┌─────────────┐  ┌──────────────┐  ┌─────────────────┐ │
│  │ DropWindow  │  │ MainWindow   │  │ ApkInfoWindow   │ │
│  │ (.apk open) │  │ (sessions)   │  │ (metadata)      │ │
│  └──────┬──────┘  └──────┬───────┘  └────────┬────────┘ │
│         │                │                    │          │
│         └────────────────┼────────────────────┘          │
│                          ▼                               │
│              ApktoolRunner / DecodeWorker                │
└──────────────────────────┬──────────────────────────────┘
                           │ subprocess (Phase 1)
                           ▼
              java -jar apktool.jar d -f -o <cache> <apk>
                           │
                           ▼
              AndroidManifest.xml, res/, smali/, assets/, lib/
                           │
                           ▼
              Gtk.TreeView + GtkSourceView (browse & read)
```

**AppManager analogy:** AppManager never reimplements SquashFS extraction in Vala — it shells out to `unsquashfs` / `dwarfsextract`. ApkManager shells out to Apktool the same way.

## 4. Host tools I would install

### 4.1 Debian / Ubuntu

```bash
sudo apt update
sudo apt install -y \
  valac meson ninja-build pkg-config \
  libadwaita-1-dev libgtk-4-dev libgtksourceview-5-dev \
  libglib2.0-dev libjson-glib-dev libgee-0.8-dev \
  libsoup-3.0-dev libgirepository1.0-dev \
  openjdk-17-jre-headless openjdk-17-jdk-headless \
  desktop-file-utils git curl unzip
```

Verify Java:

```bash
java -version   # must report 17 or newer (Apktool 3.x requirement)
```

### 4.2 Fedora / RHEL-family

```bash
sudo dnf install -y \
  vala meson ninja-build \
  libadwaita-devel gtk4-devel gtksourceview5-devel \
  glib2-devel json-glib-devel libgee-devel libsoup3-devel \
  java-17-openjdk-headless java-17-openjdk-devel \
  desktop-file-utils git curl unzip
```

On RHEL, Alma, or Rocky, install EPEL first.

### 4.3 Do not rely on distro `apktool` packages

Debian and Fedora often ship stale Apktool versions. Bundle a pinned JAR + `aapt2` under `$prefix/lib/apk-manager/apktool/` via `scripts/fetch-apktool.sh`, mirroring how AppManager vendors `unsquashfs`.

## 5. Step-by-step execution sequence

### Step 1 — Scaffold Meson project (Day 1)

Copy the dependency block from `Others/AppManager/meson.build`:

- `libadwaita-1` ≥ 1.6, `gtk4`, `gio-2.0`, `json-glib-1.0`, `gee-0.8`
- Add `gtksourceview-5` for manifest/smali text views

Create minimal entry points:

```
src/main.vala
src/application.vala
src/windows/main_window.vala
src/windows/drop_window.vala
```

Accept `.apk` via drag-and-drop and `Gtk.FileDialog`.

**Gate:** `meson compile -C build` succeeds on Debian and Fedora.

### Step 2 — Vendor Apktool (Day 1–2)

Write `scripts/fetch-apktool.sh`:

1. Download pinned `apktool_<version>.jar` from upstream releases (or copy from a local `Others/Apktool` Gradle build: `./gradlew shadowJar`).
2. Extract Linux `aapt2` (and legacy `aapt` if needed) into `subprojects/apktool/linux/`.
3. Install layout: `$prefix/lib/apk-manager/apktool/apktool.jar` + `$prefix/lib/apk-manager/apktool/linux/aapt2`.

Test manually:

```bash
export PATH="$PWD/subprojects/apktool/linux:$PATH"
java -Xmx1024M -Dfile.encoding=utf-8 \
  -Djdk.util.zip.disableZip64ExtraFieldValidation=true \
  -Djdk.nio.zipfs.allowDotZipEntry=true \
  -jar subprojects/apktool/apktool.jar d -f -o /tmp/apk-test /path/to/sample.apk
ls /tmp/apk-test   # expect AndroidManifest.xml, apktool.yml, res/, smali/
```

**Gate:** Decode matches CLI Apktool on both distros.

### Step 3 — ApktoolRunner subprocess wrapper (Day 2–3)

Implement `src/core/apktool_runner.vala`:

- Build command array (mirror `Others/Apktool/scripts/linux/apktool` JVM flags).
- Run via `Gio.Subprocess` on a `GLib.ThreadPool` or `Gio.Task` (never block GTK main loop).
- Stream stdout/stderr to an `Adw.Toast` or log pane.
- Support cancel via `subprocess.send_signal(POSIX.SIGTERM)`.
- Pass `--frame-path "$XDG_CACHE_HOME/apk-manager/frameworks"`.

Map GUI preferences to CLI flags (from `brut.apktool.Main`):

| Preference | Flag |
|------------|------|
| Force overwrite cache | `-f` |
| Skip smali | `-s` / `--no-src` |
| Skip resources | `-r` / `--no-res` |
| Manifest only | `--only-manifest` |
| Parallel jobs | `-j N` |

**Gate:** Decode from GUI produces the same tree as Step 2 manual command.

### Step 4 — Session registry and main window (Day 3–5)

Implement `src/core/decode_session_registry.vala` (JSON index at `~/.local/share/apk-manager/sessions.json`):

```json
{
  "sessions": [
    {
      "id": "sha256hex",
      "apkPath": "/home/user/Downloads/app.apk",
      "cacheDir": "/home/user/.cache/apk-manager/decoded/sha256hex",
      "decodedAt": "2026-10-06T23:00:00Z",
      "label": "com.example.app"
    }
  ]
}
```

Main window: `Adw.ApplicationWindow` + `Adw.NavigationSplitView`:

- **Sidebar:** recent sessions (like AppManager's installed-app list).
- **Content:** `Gtk.TreeView` or `Adw.NavigationView` over decoded directory.

Double-click a file → open in `GtkSourceView` (XML/YAML/smali) or `Gtk.Picture` (PNG/WebP).

**Gate:** Re-open a previous session without re-decoding.

### Step 5 — ApkInfoWindow (Day 5–7)

Before decode, run fast metadata:

```bash
aapt2 dump badging "$APK"
```

Parse into `ApkMetadata` (Vala struct): package name, versionCode, versionName, minSdk, targetSdk, permissions, launchable activity.

After decode, read `$CACHE/apktool.yml` for Apktool-specific fields (`usesFramework`, `sdkInfo`, etc.).

UI: copy the `Adw.PreferencesGroup` layout from `Others/AppManager/src/windows/app_image_info_window.vala`:

- **General** — package, version, label
- **SDK** — min/target SDK
- **Permissions** — scrollable list
- **Files** — APK path, cache path, decoded size

**Gate:** Info window shows correct metadata for a known test APK before and after decode.

### Step 6 — Desktop integration (Day 7)

Create `data/com.github.ApkManager.desktop.in`:

```ini
MimeType=application/vnd.android.package-archive;
```

Create `data/mime/com.github.ApkManager.apk.xml` registering `.apk` → `application/vnd.android.package-archive`.

Wire `GApplication::open` in `application.vala` to accept file paths (same pattern as AppManager opening AppImages).

```bash
meson install -C build
update-desktop-database ~/.local/share/applications
update-mime-database ~/.local/share/mime
```

**Gate:** Double-clicking an `.apk` in Nautilus/Dolphin opens ApkManager.

### Step 7 — CLI helpers (Day 8)

Mirror AppManager CLI surface:

```bash
apk-manager open /path/to/app.apk          # decode + open main window
apk-manager info /path/to/app.apk          # print metadata, no GUI
apk-manager decode /path/to/app.apk        # decode to cache, exit
apk-manager --clear-cache                  # remove ~/.cache/apk-manager/decoded/*
apk-manager --version
```

**Gate:** `apk-manager open` and GUI double-click use the same code path.

### Step 8 — Sidecar upgrade (Week 2+, optional)

When subprocess progress parsing becomes painful, add `sidecar/` Java module:

- Long-lived JVM on `127.0.0.1:0`
- HTTP or Unix socket API: `POST /decode`, `GET /progress/{id}`, `GET /apkinfo/{id}`
- Use `ApkDecoder` + `Config` directly from `apktool-lib`

Vala client in `src/core/decode_sidecar_client.vala`. Start sidecar from `Application.startup`, stop on quit.

**Gate:** Progress bar shows decode phases; no new JVM per APK.

### Step 9 — Packaging (Week 3)

| Format | JRE | Command |
|--------|-----|---------|
| Native install | Depends on `openjdk-17-jre-headless` | `meson install` |
| AppImage | Bundle Temurin JRE 17 minimal | `./scripts/make-appimage.sh` |
| Flatpak | `org.freedesktop.Sdk.Extension.openjdk17` | `flatpak-builder` |

Document bundled Apktool/aapt2 versions in `data/com.github.ApkManager.metainfo.xml` `<bundle type="legal">`.

**Gate:** Fresh Debian 12 and Fedora 40 VMs install and open a test APK without manual setup.

## 7. Common failures and fixes

| Symptom | Cause | Fix |
|---------|-------|-----|
| `can't find apktool.jar` | JAR not installed to libdir | Run `fetch-apktool.sh`; verify Meson install path |
| `Framework not found` | System APK needs `framework-res.apk` | UI: Install framework → `apktool if` into cache frameworks dir |
| Blank manifest viewer | Opened binary manifest from APK zip | Must decode first; only show decoded `AndroidManifest.xml` |
| Java version error | JRE < 17 | Startup dialog: install `openjdk-17-jre-headless` |
| `aapt2: not found` | PATH missing bundled aapt2 | Export PATH in `ApktoolRunner` like `scripts/linux/apktool` lines 79–81 |
| UI freeze during decode | Subprocess on main thread | Move to `Gio.Task` / thread pool; show `Adw.ProgressBar` |
| Huge cache usage | Every open re-decodes | Key cache by SHA-256; offer "Clear decoded cache" in preferences |

## 8. Acceptance checklist

1. [ ] `meson compile` succeeds on Debian 12+ and Fedora 40+.
2. [ ] Bundled Apktool decodes a sample APK identically to upstream CLI.
3. [ ] Double-click `.apk` opens ApkManager (MIME registered).
4. [ ] Main window browses decoded tree; manifest opens in source view.
5. [ ] ApkInfoWindow shows package name, SDK, and permissions.
6. [ ] Framework-not-found error is actionable from the GUI.
7. [ ] `apk-manager open` and GUI share the same decode path.
8. [ ] Cancel decode does not leave zombie Java processes.
9. [ ] Cache and sessions survive app restart.
