## 1. Executive Summary

Converting Apktool into a GUI application like AppManager requires building a **separate native Linux application** that wraps Apktool's Java engine, not modifying Apktool itself.

**Core principle:** Apktool remains a Java library and CLI tool. ApkManager is a new Vala + GTK 4 + Libadwaita desktop application that:
- Opens `.apk` files via file manager, drag-and-drop, or CLI
- Lists raw APK contents instantly (no Java required)
- Executes Apktool as a background subprocess for decoded views
- Caches results and presents them in native GTK viewers

**AppManager provides the desktop shell pattern; Apktool provides the decode engine.**

## 5. Apktool Command Contract

### 5.1 Pinned Engine

```bash
# scripts/fetch-apktool.sh
APKTOOL_VERSION="2.9.3"  # Pin specific version
APKTOOL_URL="https://github.com/iBotPeaches/Apktool/releases/download/v${APKTOOL_VERSION}/apktool_${APKTOOL_VERSION}.jar"
APKTOOL_SHA256="<commit-verified-hash>"

# Download, verify, install to <libdir>/apk-manager/apktool.jar
```

### 5.2 JVM Invocation

```text
java
-Xmx1024M
-Dfile.encoding=utf-8
-Djdk.util.zip.disableZip64ExtraFieldValidation=true
-Djdk.nio.zipfs.allowDotZipEntry=true
-jar
<libdir>/apk-manager/apktool.jar
d
-f
-j <jobs>
-p <cache>/apk-manager/frameworks
-o <cache>/apk-manager/decoded/<key>.partial-<pid>
<apk-path>
```

**Fast pass:** Add `-s --only-manifest`  
**Full decode:** Omit `-s --only-manifest`

### 5.3 Cache Key

```text
key = SHA-256(APK bytes) + Apktool version + normalized decode options
```

### 5.4 Progress Telemetry

Parse Apktool stdout for phase indicators:

| Log Pattern | GUI Phase |
|---|---|
| `Using Apktool ...` | Starting |
| `Baksmaling ...` | Decoding code |
| `Decoding AndroidManifest.xml` | Decoding manifest |
| `Decoding file-resources` | Decoding resources |
| `Copying assets` / `Copying lib` | Copying files |
| `Copying unknown files` | Finishing |

Display as indeterminate progress bar + phase label.

### 5.5 Cancellation

1. Cancel `Cancellable`
2. `force_exit()` the Java subprocess
3. Wait for process termination
4. Delete `.partial-<pid>` directory
5. Mark session as cancelled

## 6. Reading Pipeline

### Stage A: Instant Raw View (No Java)

Using libarchive, display:

- ZIP entry names, sizes, compression methods
- DEX files (`classes.dex`, `classes2.dex`, ...)
- Native ABIs (`lib/arm64-v8a/`, `lib/x86_64/`, ...)
- Assets, resources, META-INF signatures
- Previewable images and text files

**Works without Java installed.**

### Stage B: Fast Manifest Pass

```bash
apktool d -s --only-manifest -o <cache> <apk>
```

Produces readable `AndroidManifest.xml` + `apktool.yml` in ~1 second.

Extracts:
- Package name, version name/code
- Min/target SDK
- Permissions
- Activities, services, receivers, providers
- Launcher activity

### Stage C: Full Decode

```bash
apktool d -f -j <jobs> -p <frameworks> -o <cache> <apk>
```

Produces:
- `AndroidManifest.xml` (readable)
- `apktool.yml` (metadata)
- `res/` (decoded resources)
- `smali*/` (disassembled code)
- `assets/`, `lib/` (copied raw)
- `original/` (signatures)
- `unknown/` (unhandled files)

## 7. User Interface

### 7.1 Main Window

`Adw.ApplicationWindow` with `Adw.NavigationSplitView`:

- **Sidebar:** Recent APK sessions (package name, icon, last opened)
- **Content:** File tree browser + viewer pane

### 7.2 Drop Window

`Adw.Window` accepting drag-and-drop:

- Shows APK icon (if extractable)
- Displays package name, size, DEX count
- Primary action: "Decode & Inspect"

### 7.3 Info Window

`Adw.Window` with `Adw.PreferencesGroup` sections:

- **General:** Package, version, label
- **SDK:** Min, target, compile SDK
- **Permissions:** List of requested permissions
- **Components:** Activities, services, receivers, providers
- **Code:** DEX count, smali directories
- **Native:** CPU ABIs, shared libraries
- **Signing:** Presence of signature files
- **Files:** APK path, cache path, sizes

### 7.4 Viewers

| Content Type | Viewer |
|---|---|
| XML (manifest, resources) | GtkSourceView (XML syntax) |
| YAML (`apktool.yml`) | GtkSourceView (YAML syntax) |
| Smali | GtkSourceView (plain text initially) |
| Images (PNG/JPEG/WebP) | Gtk.Picture |
| Binaries (.so, .dex, .arsc) | Bounded hex viewer (2 MiB cap) |

## 8. Debian & Fedora Setup

### 8.1 Debian / Ubuntu (Debian 13+, Ubuntu 24.04+)

```bash
sudo apt update
sudo apt install -y \
  valac meson ninja-build pkg-config \
  libgtk-4-dev libadwaita-1-dev libgtksourceview-5-dev \
```

```bash
sudo dnf install -y \
  vala meson ninja-build pkgconf-pkg-config \
  gtk4-devel libadwaita-devel gtksourceview5-devel \
  glib2-devel json-glib-devel libgee-devel \
```

## 9. Security Boundaries

1. **Never execute** APK code (DEX, .so, scripts)
2. **Argument vectors only** — no shell string interpolation
3. **Path validation** — reject `..`, absolute paths, unsafe links
4. **No symlink following** in decoded output
5. **Bounded previews** — 2 MiB text/hex, pixel limits for images
6. **Private cache** — `0700` permissions
7. **No network access** during open/decode
8. **Read-only v1** — no rebuild, no signing, no device install

|---|---|---|---|
