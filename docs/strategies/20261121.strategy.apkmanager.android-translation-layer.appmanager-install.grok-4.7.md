## 1. Goal

The Fedora steps in the runtime install dialog download Android Translation Layer into the current directory and run it immediately. This strategy changes that into two steps ApkManager can run later:

1. Download the ATL AppImage into `~/Downloads`.
2. Hand that file to AppManager's `install` command, which moves it to `~/Applications` and writes the desktop entry and icon.

If AppManager is not already on the system, download AppManager 3.8.0 into `~/Downloads` first and install that with its own `install` command, then use the installed copy for ATL.

AppManager refuses to install a file that is already inside `~/Applications`. The download directory has to stay `~/Downloads`.

## 2. The Android Translation Layer file

Lines 249–254 of `runtime_install_dialog.vala` are the Fedora `DistroSteps`. The URL is the same one the Debian and Ubuntu blocks use. Only the `curl` destination changes: `-o` writes a fixed name under `~/Downloads` instead of `-O` writing into whatever directory the user happened to be in.

| Item | Value |
|------|-------|
| Upstream | [pkgforge-dev/android_translation_layer-AppImage](https://github.com/pkgforge-dev/android_translation_layer-AppImage) release `3e686d14@2026-09-22_1790090775` |
| URL | `https://github.com/pkgforge-dev/android_translation_layer-AppImage/releases/download/3e686d14%402026-09-22_1790090775/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage` |
| Saved as | `~/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage` |

```bash
mkdir -p "$HOME/Downloads"
curl -fL --retry 3 -o "$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage" \
  "https://github.com/pkgforge-dev/android_translation_layer-AppImage/releases/download/3e686d14%402026-09-22_1790090775/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
chmod +x "$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
```

`curl -f` fails on an HTTP error instead of saving an error page. The dialog's `sudo dnf install curl fuse-libs` is a host prerequisite, not part of the install. AppManager itself runs without FUSE (its README credits uruntime). On this machine, `AppManager --help` printed `failed to utilize FUSE during startup`, extracted itself, and still printed the usage text. `fuse-libs` still matters later, when the user launches the ATL AppImage.

## 3. Decide which AppManager to use

Look for an installed copy before downloading anything. On this machine the file is `/home/corey/Applications/AppManager` (no `.AppImage` suffix), and `--version` prints `AppManager 3.7.3`.

| Check | Command | Use it when |
|-------|---------|-------------|
| Installed copy | `test -x "$HOME/Applications/AppManager"` | This is the file AppManager creates for itself. This machine matches |
| On `PATH` | `command -v app-manager` | A package or a PATH symlink exists and `~/Applications/AppManager` does not |

```bash
if [ -x "$HOME/Applications/AppManager" ]; then
  APP_MANAGER="$HOME/Applications/AppManager"
elif command -v app-manager >/dev/null; then
  APP_MANAGER="$(command -v app-manager)"
else
  APP_MANAGER=""
fi
```

An existing copy is used as-is. 3.7.3 and 3.8.0 both implement the `install` subcommand, so this machine does not need the 3.8.0 download. Section 4 runs only when `APP_MANAGER` is empty.

## 4. Bootstrap AppManager 3.8.0 when it is missing

| Item | Value |
|------|-------|
| Project | [github.com/kem-a/AppManager](https://github.com/kem-a/AppManager) (GPL-3.0) |
| File | `AppManager-3.8.0-anylinux-x86_64.AppImage` |
| URL | `https://github.com/kem-a/AppManager/releases/download/v3.8.0/AppManager-3.8.0-anylinux-x86_64.AppImage` |
| Saved as | `~/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage` |

```bash
curl -fL --retry 3 -o "$HOME/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage" \
  "https://github.com/kem-a/AppManager/releases/download/v3.8.0/AppManager-3.8.0-anylinux-x86_64.AppImage"
chmod +x "$HOME/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage"
"$HOME/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage" install \
  "$HOME/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage"
```

`install` is the non-interactive command. It prints `Installed <name>` and exits 0. Launching the file with no arguments instead opens the drag-and-drop window, which is the wrong path for ApkManager. After a successful install the program lives at `~/Applications/AppManager`, and that path is what section 5 calls. The copy in `~/Downloads` is what got moved, so later steps must not expect it to still be there.

## 5. Install the ATL AppImage

```bash
"$APP_MANAGER" install \
  "$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
```

Success prints `Installed <name>` (or `Updated <name>` when the same AppImage is already registered) and exits 0. AppManager then owns the file under `~/Applications` and writes `~/.local/share/applications`. A second install of a different build, kept next to the first, adds `--keep-both`:

```bash
"$APP_MANAGER" install --keep-both \
  "$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
```

Check before installing, without changing anything:

```bash
"$APP_MANAGER" --is-installed \
  "$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
```

That prints `installed` and exits 0, or `missing` and exits 1. It compares the file's checksum with AppManager's registry, so the file still has to be the download in `~/Downloads`, not the copy already moved into `~/Applications`.

Passing the path with no subcommand (`"$APP_MANAGER" ~/Downloads/….AppImage`) opens the installer window. It does not install.

## 6. AppManager command-line options

The option list below is what `/home/corey/Applications/AppManager --help-all` printed on 2026-11-21 (version 3.7.3). The same options and the examples are declared in the v3.8.0 source (`src/application.vala` at tag `v3.8.0`). v3.8.0's release notes add the `appimg://` web-install link and a `Ctrl+Shift+U` shortcut. They do not add a new flag.

The program name inside the AppImage is `app-manager`. Invoking `/home/corey/Applications/AppManager` forwards the same arguments.

### 6.1 Options `--help` prints

| Option | Meaning |
|--------|---------|
| `-h`, `--help`, `-?` | Print help and exit |
| `--help-all` | Help plus the GApplication options |
| `--help-gapplication` | GApplication options only |
| `--version` | Print `AppManager <version>` and exit |
| `--background-update` | Run the background update check (the autostart entry uses this) and exit |
| `--update-all` | Update every installed app and exit |
| `--update-check` | List available updates and exit, without installing them |
| `--keep-both` | With `install`: keep the existing app and add another copy beside it |
| `--is-installed=PATH` | Print whether this file's checksum is already installed. Also accepted as `--is-installed PATH` |
| `--gapplication-service` | Enter GApplication service mode. Used from a D-Bus service file, not from this strategy |

### 6.2 Commands

| Command | Meaning |
|---------|---------|
| *(no arguments)* | Open the AppManager window |
| `FILE…` | Open the installer window for each AppImage. This does not install |
| `install PATH` | Install the AppImage at `PATH` and exit. Hidden long form: `--install=PATH` |
| `uninstall PATH` | Uninstall the app identified by that path or by its checksum, and exit. Hidden long form: `--uninstall=PATH` |
| `update PATH` | Update one installed app, identified by path or checksum, and exit |
| `appimg://install?url=…&sha256=…` | Download that URL, check the SHA-256, then open the install flow. v3.8.0. Not used here, because the file is already in `~/Downloads` |

`install`, `uninstall`, and `update` each require a path. Omitting it prints `Error: '<command>' requires a PATH argument` and exits 7.

### 6.3 Examples from the v3.8.0 help text

```text
app-manager                                          Launch the GUI
app-manager app.AppImage                             Open installer for app.AppImage
app-manager install app.AppImage                     Install app.AppImage
app-manager install app.AppImage --keep-both         Install as a new copy next to the existing app
app-manager uninstall app.AppImage                   Uninstall app.AppImage
app-manager update app.AppImage                      Update app.AppImage
app-manager --update-all                             Update all installed apps
app-manager --update-check                           List available updates
app-manager --is-installed app.AppImage              Check installation status
app-manager --background-update                      Run background update check
```

### 6.4 Exit codes

From `handle_local_options` in the v3.8.0 source:

| Exit | When |
|------|------|
| 0 | Installed, updated, removed, up to date, or `--is-installed` printed `installed` |
| 1 | `--is-installed` printed `missing` |
| 2 | `install` failed. An architecture mismatch names the AppImage's architecture |
| 3 | `uninstall` or `update` found no matching installation |
| 4 | `uninstall` failed |
| 5 | `--is-installed` could not read the file |
| 6 | `update` failed |
| 7 | `install`, `uninstall`, or `update` was given without a path |

## 7. Full order

```bash
#!/bin/bash
set -euo pipefail
mkdir -p "$HOME/Downloads"

atl="$HOME/Downloads/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
curl -fL --retry 3 -o "$atl" \
  "https://github.com/pkgforge-dev/android_translation_layer-AppImage/releases/download/3e686d14%402026-09-22_1790090775/Android_Translation_Layer-3e686d14-anylinux-x86_64.AppImage"
chmod +x "$atl"

if [ -x "$HOME/Applications/AppManager" ]; then
  app_manager="$HOME/Applications/AppManager"
elif command -v app-manager >/dev/null; then
  app_manager="$(command -v app-manager)"
else
  bootstrap="$HOME/Downloads/AppManager-3.8.0-anylinux-x86_64.AppImage"
  curl -fL --retry 3 -o "$bootstrap" \
    "https://github.com/kem-a/AppManager/releases/download/v3.8.0/AppManager-3.8.0-anylinux-x86_64.AppImage"
  chmod +x "$bootstrap"
  "$bootstrap" install "$bootstrap"
  app_manager="$HOME/Applications/AppManager"
fi

"$app_manager" install "$atl"
```

On this Fedora 44 machine the `if` takes the first branch, because `/home/corey/Applications/AppManager` is already executable. The bootstrap download does not run.
