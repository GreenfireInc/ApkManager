**Difference from section 5:** the first test build showed pkgforge-dev's `atl-desktop-entry-binary-path.patch` no longer applies to ATL `master`. Upstream renamed `desktop_entry` to `exec_cmd` in `src/main-executable/main.c`. ATL.edge makes that one edit with a pattern-matching `sed` and only warns if it stops matching. The four art_standalone patches still apply as diffs.

ATL `master` has also outgrown pkgforge-dev's build environment (the pkgforge recipe was last released 2026-09-22). `get-dependencies.sh` makes three more changes for ATL.edge:

- **`tools/jni_upcall_gen`** needs the `asm`, `asm-tree` and `java-getopt` jars and looks for them with Fedora's `xmvn5-resolve`, which Arch doesn't have. The recipe downloads pinned jars from Maven Central (asm 9.8, java-getopt 1.0.13, checked by SHA-256) and passes them as `-Dasm_jar_path`, `-Dasm_tree_jar_path` and `-Dgetopt_jar_path`.
- **The same tool needs Java 12 or newer** (`Path.of`, `Files.mismatch`). Java 8 stays in use for art_standalone. ATL itself builds with JDK 17, the version ATL's `doc/Build.md` uses on Fedora, and its sources still target 1.8. Both JDKs are removed before packaging.
- **New packages:** `speech-dispatcher` (a new `meson.build` dependency) and `jq` (writes `atl-build.json`).

First successful build: `94d69d8c-edge`, about 18 minutes, a 139 MB AppImage. It starts and loads apps. Termux and a Flutter calculator crash on both this build and the pkgforge `3e686d14` build, for different reasons: Termux's JNI asks for `Paint.getFontSpacing()`, which ATL doesn't implement, and Flutter fails `Check failed: libandroid`.

**Not done yet:** the systemd timer (6.2) and the in-app daily check and banner (6.4). `check-update.sh` is in place for both.

## 1. Summary

1. **Why build it ourselves:** the AppImage ApkManager installs (pkgforge-dev) hasn't been rebuilt since September 22. Upstream ATL is **114 commits** ahead of it.
2. **How:** reuse pkgforge-dev's recipe unchanged where possible, run inside a **rootless Podman Arch Linux container** on this machine. The recipe builds five pieces from source: wolfSSL with JNI, bionic_translation, art_standalone, libopensles-standalone and ATL. It applies six patches, then bundles everything into a portable AppImage with `quick-sharun`.
3. **Versioning:** the AppImage is named after the ATL commit, as today. A small `atl-build.json` beside it records the commit of all four GitLab repos, so "is there an update?" is a comparison of four hashes.
4. **Checking for updates:** use `git ls-remote` against the four repos. It is anonymous and quick, and downloads no source.
5. **Routine:** a systemd **user timer** runs the check weekly. Optionally, ApkManager does the same check at most once a day and offers **Build update**. The build runs in a terminal window like the other installers, and the result is installed through AppManager exactly as today.
6. **Which URL:** use the **HTTPS** URL for automation. The `git@gitlab.com:` form only works with an SSH key registered on a GitLab account.

## 3. Getting the source

```bash
# Anonymous, works everywhere (recommended for scripts and timers)
git clone https://gitlab.com/android_translation_layer/android_translation_layer.git

# SSH: only for a GitLab account with an SSH key added (needed for pushing, not for building)
git clone git@gitlab.com:android_translation_layer/android_translation_layer.git
```

### pkgforge-dev's patches (keep them)

| Patch | Applies to | Why it matters for an AppImage |
|-------|-----------|--------------------------------|
| `atl-desktop-entry-binary-path.patch` | ATL | ATL writes desktop entries for apps with `argv[0]`. Inside an AppImage that is a temporary mount, so it honours `ATL_APP_LAUNCHER` (set to `$APPIMAGE`) |
| `art-addr2line-path.patch` | art_standalone | Find `addr2line` through `PATH`, not `/usr/bin` |
| `art-dx-heap.patch` | art_standalone | 4 GB heap for `dx` when dexing the core libraries |
| `art-wolfssljni-host-cacerts.patch` | art_standalone | Use the host's CA certificates instead of a bundled copy |
| `art-ipv4-fixes.patch` | art_standalone | Fall back to IPv4 sockets on hosts without IPv6 (otherwise no network) |
| `vixl-meson-support.patch` | vixl | aarch64 build only |

## 4. Build options considered

| Option | Verdict |
|--------|---------|
| **A. Build directly on Linux Mint** | Not recommended. It needs Java 8 for the old Java code, plus a long list of `-dev` packages and `sudo make install` into `/usr`, so the host fills with build-only packages. The recipe is written for Arch package names |
| **B. Rootless Podman container running pkgforge-dev's Arch recipe** | **Recommended.** It is the exact environment the published AppImages come from, nothing is installed on the host, and it is repeatable. `quick-sharun` bundles every library, so building on Arch does not limit which distros can run the result |
| **C. Our own fork of pkgforge-dev on GitHub Actions** | A good add-on. It builds on GitHub's machines and publishes releases. A push-triggered or upstream-polling workflow avoids the 60-day schedule shutdown that stalled pkgforge-dev. It needs a GitHub repo and releases, which ApkManager's install flow would then download |

The rest of this document details **B**. **C** reuses the same scripts (section 9).

## 5. The build (Option B)

### 5.1 Layout in the ApkManager repo

```text
packaging/atl-appimage/
├── get-dependencies.sh      # vendored from pkgforge-dev, plus ATL_REF support (5.3)
├── make-appimage.sh         # vendored, UPINFO made optional (5.3)
├── patches/                 # the six patches, vendored
├── AppDir/android-translation-layer.desktop
├── build.sh                 # host wrapper: runs the container (5.2)
├── check-update.sh          # update check (6.1)
└── LICENSE                  # pkgforge-dev's recipe is GPL-3.0; keep its license with it
```

Vendoring the recipe, rather than downloading it at build time, means an upstream change to the recipe can't silently change what we build. Updating the vendored copy becomes a reviewed change.

### 5.2 `build.sh` (host side)

```bash
#!/bin/sh
# Builds the ATL AppImage in a throwaway Arch container. Output: ./dist/
set -eu
cd "$(dirname "$0")"
mkdir -p dist cache

podman run --rm \
    -v "$PWD":/work:Z -w /work \
    -v "$PWD/cache":/var/cache/pacman/pkg:Z \
    -e ATL_REF="${ATL_REF:-master}" \
    -e GITHUB_REPOSITORY=GreenfireInc/ApkManager \
    ghcr.io/pkgforge-dev/archlinux:latest \
    sh -c '
        curl -fsSL https://raw.githubusercontent.com/pkgforge-dev/anylinux-setup-action/main/setup.sh | sh &&
        sh ./get-dependencies.sh &&
        sh ./make-appimage.sh &&
        cp ~/version dist/VERSION
    '
```

Notes:

- `setup.sh` is the same script the GitHub Action runs. It installs `base-devel`, `git`, `patchelf`, `zsync` and similar packages, and drops `quick-sharun` and `get-debloated-pkgs` into `/usr/local/bin`. Pin it to a commit once the build works.
- `make-appimage.sh` runs with `set -u` and reads `GITHUB_REPOSITORY` to fill `UPINFO` (the zsync update URL). Outside GitHub it must be set, or `UPINFO` made optional (5.3), or the build stops on an unbound variable.
- The pacman cache mount makes rebuilds after the first one much faster.
- The recipe sets `JAVA_TOOL_OPTIONS=-Xmx4096M` and uses `make -j"$(nproc)"`. With 12 CPUs and 94 GB RAM this machine is well within limits. The first build is expected to take a long time, mostly art_standalone; measure it on the first run.

### 5.3 Small changes to the vendored recipe

1. **Build a chosen ATL commit.** In `build_meson_bin`, after `git clone`:

   ```sh
   if [ "$repo" = 'android_translation_layer' ] && [ "${ATL_REF:-master}" != master ]; then
       git fetch --depth 1 origin "$ATL_REF" && git checkout FETCH_HEAD
   fi
   ```

   This allows rebuilding a known-good commit, or rolling back.

2. **Record what was built.** At the end of `get-dependencies.sh`, write the commit of every clone:

   ```sh
   jq -n --arg atl "$(git -C android_translation_layer rev-parse HEAD)" \
         --arg art "$(git -C art_standalone rev-parse HEAD)" \
         --arg bionic "$(git -C bionic_translation rev-parse HEAD)" \
         --arg opensles "$(git -C libopensles-standalone rev-parse HEAD)" \
         --arg wolfssl "v5.9.2-stable" \
         --arg built "$(date -u +%FT%TZ)" \
         '{atl:$atl, art_standalone:$art, bionic_translation:$bionic,
           libopensles_standalone:$opensles, wolfssl:$wolfssl, builtAt:$built}' \
         > /work/dist/atl-build.json
   ```

3. **Make UPINFO optional.** Replace the `UPINFO=` line with
   `export UPINFO="${UPINFO:-}"`, so no zsync URL is embedded unless we publish releases (Option C).

### 5.4 Output

`dist/` gets `Android_Translation_Layer-<atl short hash>-anylinux-x86_64.AppImage`, matching pkgforge-dev's naming (which `RuntimeRunner.atl_program` already matches), plus `atl-build.json` and `VERSION`. Confirm the exact filename on the first build, since `quick-sharun` derives it.

### 5.5 Smoke test before installing

ATL has no `--version` option (`Unknown option --version`), so test it by running something:

```bash
timeout 20 ./dist/Android_Translation_Layer-*-x86_64.AppImage \
    ~/Applications/android/io.dahliaos.calculator.from.F-Droid.universal.apk \
    2>&1 | tee dist/smoke.log
```

Pass if a window appears and the log has no `FATAL`, `UnsatisfiedLinkError` or `NoClassDefFoundError`. These are the same patterns as ApkManager's `atl_debug_error`. Only install builds that pass.

## 6. Routine update checks

### 6.1 What counts as an update

Any of the four GitLab heads differs from `atl-build.json` of the installed build. ATL alone is not enough, because an art_standalone fix changes behaviour without an ATL commit.

`check-update.sh`:

```bash
#!/bin/sh
# Exit 0 and print what changed if an update is available, 1 if up to date, 2 on error.
set -eu
MANIFEST="${1:-$HOME/Applications/atl-build.json}"
BASE=https://gitlab.com/android_translation_layer
changed=""
for pair in atl:android_translation_layer art_standalone:art_standalone \
            bionic_translation:bionic_translation libopensles_standalone:libopensles-standalone; do
    key=${pair%%:*}; repo=${pair#*:}
    remote=$(git ls-remote "$BASE/$repo.git" HEAD | cut -f1) || exit 2
    local_=$(jq -r ".$key // empty" "$MANIFEST" 2>/dev/null || true)
    [ "$remote" = "$local_" ] || changed="$changed $repo:${remote%"${remote#????????}"}"
done
[ -n "$changed" ] && { echo "update:$changed"; exit 0; }
exit 1
```

When no manifest exists (today's pkgforge install), only the ATL hash can be compared: `X-AppImage-Version` against `git ls-remote … HEAD`. ApkManager already reads that value in `RuntimeRunner.runtime_version`.

For a "how far behind" count, the GitLab API answers anonymously:

```bash
curl -s "https://gitlab.com/api/v4/projects/android_translation_layer%2Fandroid_translation_layer/repository/compare?from=3e686d14&to=master" \
  | jq '.commits | length'        # 114 on 2026-11-21
```

### 6.2 Scheduling: systemd user timer

`~/.config/systemd/user/atl-appimage-update.service`:

```ini
[Unit]
Description=Check for and build Android Translation Layer updates

[Service]
Type=oneshot
Nice=19
IOSchedulingClass=idle
WorkingDirectory=%h/Workspace/Applications/apkManager/packaging/atl-appimage
ExecStart=/bin/sh -c './check-update.sh && ./build.sh && ./install.sh'
```

`~/.config/systemd/user/atl-appimage-update.timer`:

```ini
[Unit]
Description=Weekly Android Translation Layer update check

[Timer]
OnCalendar=weekly
RandomizedDelaySec=6h
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now atl-appimage-update.timer
journalctl --user -u atl-appimage-update.service     # results
```

`check-update.sh` exits 1 when up to date, so the build and install steps only run when something changed. Weekly is a reasonable rate: upstream averaged about 13 commits a week between September and November, and every build is a long job.

### 6.3 Install step (`install.sh`)

Reuse the existing flow from the AppManager strategy:

1. Copy the new AppImage to `~/Downloads` (AppManager refuses files already inside `~/Applications`).
2. Keep the current one: `cp ~/Applications/"Android Translation Layer" ~/Applications/.atl-previous.AppImage`.
3. `~/Applications/AppManager install ~/Downloads/Android_Translation_Layer-<hash>-anylinux-x86_64.AppImage`.
4. Copy `atl-build.json` to `~/Applications/atl-build.json`.
5. **Rollback:** reinstall `.atl-previous.AppImage` the same way.

### 6.4 Inside ApkManager (optional, user-facing)

| Piece | Behaviour |
|-------|-----------|
| Preferences switch | "Check for Android Translation Layer updates" (off by default) |
| Check | On startup, at most once a day: `git ls-remote` of the four repos against `~/Applications/atl-build.json` (or `X-AppImage-Version`). Run it asynchronously, like the other `Subprocess` calls |
| Notice | An `Adw.Banner` reading "Android Translation Layer update available (N commits)" with a **Build update** button |
| Build | `open_terminal_script` runs `packaging/atl-appimage/build.sh && install.sh`, so the user sees progress and can cancel. The existing status-file mechanism reports the result |
| After install | `RuntimeRunner.runtime_version` already shows the new hash in Error Export and debug JSON |

An installed ApkManager (deb, rpm or AppImage) does not have the repo checkout. For those, ship `packaging/atl-appimage/` under `share/apk-manager/` via Meson, or use Option C's published releases and only download.

## 7. Risks and guards

| Risk | Guard |
|------|-------|
| **Disk space**: `/home` is 96 % full (72 GB free); art_standalone and the container images are large | `build.sh` refuses to start below 25 GB free (`df --output=avail`). After the build, `podman image prune -f`, and clean `cache/` monthly |
| Upstream `master` breaks the build, or a patch stops applying | The timer only installs on success, and the smoke test gates installation. Use `ATL_REF` to pin to the last good commit; the journal shows the failure |
| Companion repos drift from ATL (ATL needs a newer art_standalone, or the reverse) | Always build all four from the same moment. Never mix a new ATL with an old ART |
| Recipe changes upstream (pkgforge-dev updates patches) | Vendored copy. Check pkgforge-dev's repo occasionally and merge deliberately |
| `setup.sh` / `quick-sharun` fetched from `main` at build time | Pin both URLs to commits once a build succeeds |
| GitLab outage or rate limits | `git ls-remote` failures exit 2. The timer logs and retries next week; ApkManager shows nothing |
| Podman 4.9 on Mint | Building is an ordinary rootless container (no `keep-id`, no devpts options), unlike Lepton's Podman-5 needs. Docker is installed as a fallback (`docker run` with the same arguments) |

## 9. Option C in brief (GitHub Actions)

Fork `pkgforge-dev/android_translation_layer-AppImage` (or put the vendored folder in its own repo), then change the trigger:

```yaml
on:
  schedule:
    - cron: "0 7 * * 1"       # weekly
  workflow_dispatch: {}
```

Add a first job that runs `check-update.sh` against the `atl-build.json` attached to the latest release, and skips the build when nothing changed. Keep the existing `build` and `release` jobs. To stop GitHub disabling the schedule after 60 quiet days, have the release job commit the new `LATEST_VERSION`, as pkgforge-dev's repo intends, which counts as activity. ApkManager then downloads `releases/latest` instead of a hard-coded URL, and the AppImage's embedded zsync `UPINFO` lets AppImage updaters fetch only the changed blocks.
